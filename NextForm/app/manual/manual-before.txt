&title NextForm Manual
*What NextForm is
NextForm ([[official site:`OFFICIAL_URL`]]) is a wiki engine.
A wiki engine provides the functions to edit, show and manage web pages.

NextForm is a fork of [[ToraToraWiki:http://toratora.wiki/]] 1.3.10.
It inherits the GPLv3 license.

*How to write pages
Document pages are written in Markdown notation or in Wiki notation. Both are first-class ways of writing.
To learn the notation quickly, open a cheat sheet (on the screen for editing the whole page, the notation label at the top right also opens it).

|notation|cheat sheet|details|strengths|h
|[[Markdown notation:./Markdown]]|[[Markdown Cheat Sheet:./Markdown/CheatSheet]]|[[Basic elements:./Markdown/Basic]], [[Extra elements:./Markdown/Extra]], [[Links, images and attachments:./Markdown/Link]], [[Front matter:./Markdown/FrontMatter]]|the way of writing used in common across many tools and services ([[CommonMark:https://commonmark.org/]] with extensions such as tables and strikethrough). Text written in another tool can be brought in as it is. The default for new pages|
|[[Wiki notation:./Wiki]]|[[Wiki Cheat Sheet:./Wiki/CheatSheet]]|[[Basic elements:./Wiki/Basic]], [[Line head notation:./Wiki/LineHead]], [[Functions:./Wiki/Function]]|inherited from ToraToraWiki, in the tradition of PukiWiki. Functions that embed page lists and calendars let you build "living pages"|

How the two notations correspond, when to use which, and how to convert a page in Wiki notation to Markdown are in [[Wiki notation and Markdown notation:./Comparison]].

*Pages
A site built with NextForm is made of pages.
Every page belongs to one of the four types below.

|type    |description                                                                  |h
|Markdown|a page written in [[Markdown notation>./Markdown]] (the default for new pages)|
|wiki    |a page written in [[Wiki notation>./Wiki]]                                   |
|text    |a page shown exactly as written, with no decoration                          |
|file    |a page that holds a single file                                              |

The type is chosen when the page is created. It changes afterwards only when a page in Wiki notation is
[[converted to Markdown:./Comparison#Converting a page in Wiki notation to Markdown]], and when a version of a different type
is restored from the [[history:./PageMenu#History]].

A typical way to use them is to write documents as Markdown or wiki pages, and to
upload images and downloadable files as file pages.
A file page can then be embedded in a document page or linked from it.

How a file page is shown depends on what the file holds.
An image file is shown as an image, a video file is shown in a player where possible,
and any other file is shown as a download screen.

**Page names
Every page has a name, called the page name from here on.
A page name may contain any character.

Pages can also stand in a parent and child relationship.
To create a page that is the child of another page (called a child page),
just use a slash in the name:
 parent page name/child name
For example, creating a page named
 Cooking/Japanese
makes it a child page of the page Cooking.

Writing the structure into the page name makes the shape of your documents clear,
and lets you rename or delete a whole set of child pages at once.

The relationship can be nested as deep as you like:
 Cooking/Italian/Pizza
Here the parent of ''Cooking/Italian/Pizza'' (called the parent page) is
''Cooking/Italian'', and the parent of that in turn is ''Cooking''.

**Relative page names
Inside a page you often write a page name to refer to another page.
When you do, ''.'' and ''..'' let you refer to other pages relative to your own.
''.'' means the page itself, and ''..'' means the parent page.
For example, writing ''.'' inside the page
''Cooking/Italian''
refers to ''Cooking/Italian'' itself, and writing ''..'' refers to ''Cooking''.
Here are some more examples.

|written in Cooking/Italian|page it refers to    |h
|.                         |Cooking/Italian      |
|..                        |Cooking              |
|./Pizza                   |Cooking/Italian/Pizza|
|../Japanese               |Cooking/Japanese     |

*Special pages

**The top page
The page named ''Top'' is shown when a visitor first arrives at the site.
The name ''Top'' can be changed in the settings.

**The side page
It depends on the design theme, but the default theme always shows a page named
''Side'' in a smaller area at the left.
Apart from being shown smaller, ''Side'' is an ordinary page you can edit freely.
List links to the pages you use often there and it becomes the navigation of your site.
The name ''Side'' can be changed in the settings.
*/

&title NextFormマニュアル
*NextFormとは
NextForm([[公式サイト:`OFFICIAL_URL`]])とはWikiエンジンのひとつです．
WikiエンジンはWebページの編集, 表示, 管理等の機能を提供します．

NextFormは[[ToraToraWiki:http://toratora.wiki/]] 1.3.10のforkです．
ライセンスはGPLv3を引き継いでいます．

*ページの書き方
文章のページはMarkdown記法かWiki記法で書きます．どちらも正式な書き方です．
書き方をすぐ知りたいときは，早見表を開いてください(ページ全体の編集画面では，右上の記法の札からも開けます)．

|記法|早見表|詳しい説明|持ち味|h
|[[Markdown記法:./Markdown]]|[[Markdown記法早見表:./Markdown/CheatSheet]]|[[基本要素:./Markdown/Basic]]，[[拡張要素:./Markdown/Extra]]，[[リンク・画像・添付:./Markdown/Link]]，[[フロントマター:./Markdown/FrontMatter]]|多くのツールやサービスで共通に使われている書き方([[CommonMark:https://commonmark.org/]]と，表や打ち消し線などの拡張)．他のツールで書いた文章をそのまま持ち込める．新しいページの既定|
|[[Wiki記法:./Wiki]]|[[Wiki記法早見表:./Wiki/CheatSheet]]|[[基本要素:./Wiki/Basic]]，[[行頭記法:./Wiki/LineHead]]，[[ファンクション:./Wiki/Function]]|ToraToraWikiから受け継いだ，PukiWikiの流れをくむ書き方．ページの一覧やカレンダーを埋め込むファンクションで「動くページ」を作れる|

2つの記法の対応と使い分け，Wiki記法のページをMarkdownに変換する方法は[[Wiki記法とMarkdown記法の対応:./Comparison]]にあります．

*やりたいこと別の案内
**ページを書く・使う

|パスワードを忘れた|[[パスワードを忘れたとき:./SiteMenu#パスワードを忘れたとき]]|
ページメニューとサイトメニューの項目は，[[ページの操作:./PageMenu]]と[[サイトの機能:./SiteMenu]]に画面の並びどおりにあります．

**サイトを管理する(管理者)
|やりたいこと|見るところ|h

|ユーザーと権限を決めたい|[[ユーザーの管理:./Administration#ユーザーの管理]]|

管理ツールの項目は，[[サイトの管理:./Administration]]に画面の並びどおりにあります．

*ページ
NextFormを使ったサイトは複数のページによって構成されます．
それぞれのページは以下の4つのいずれかの種別に属します．

|種別    |説明                                                       |h
|Markdown|[[Markdown記法>./Markdown]]で表記されたページ(新規作成の既定)|
|wiki    |[[Wiki記法>./Wiki]]によって表記されたページ                |
|text    |書いたものが何の装飾もなくそのまま表示されるページ         |
|file    |ひとつのファイルが保存されたページ                         |

種別はページを作るときに選びます．あとから種別が変わるのは，Wiki記法のページを[[Markdownに変換:./Comparison#Wiki記法のページをMarkdownに変換する]]したときと，
[[履歴:./PageMenu#履歴]]で種別の違う版に戻したときだけです．

典型的な使い方を例に挙げると，文章は種別Markdownか種別wikiのページとして作成し，
画像ファイルやダウンロードさせたいファイルは種別fileのページとしてファイルをアップロードすることで作成します．
種別fileのページは文章のページに埋め込んだり，リンクを張ることで利用できます．

種別fileのページはファイルの内容によってページの表示のされ方が異なります．
画像ファイルの場合は画像が表示され，動画ファイルの場合は可能であれば動画再生画面が表示されます．
その他のファイルであればそのファイルをダウンロードする画面が表示されます．

**ページ名
ページには名前を付けます．この名前を以後はページ名と呼びます．ページ名は日本語を含め任意の文字が使用できます．

ページは親子関係を持つこともできます．あるページに対してその子供にあたるページ(子ページと呼びます)
を作成するには半角スラッシュを用いて，
 親ページ名/子供の名前
というページ名を付けるだけです．
例えば
 料理/和食
というページを作成すれば，料理というページの子ページとして認識されます．

ページ名で親子関係を明示しておけば文章の構造が明確化されますし，ページを管理する際に
子ページをまとめてリネームや削除等ができて便利です．

以下のように親子関係は何層になっても構いません．
 料理/イタリアン/ピザ
このとき ''料理/イタリアン/ピザ'' の親になるページ(親ページと呼びます)が ''料理/イタリアン'' になり，
さらにこれの親ページが ''料理'' になります．

**相対ページ名
ページの中で他のページを参照するためにページ名を表記することがあります．
このとき ''.'' や ''..'' を使うと自分のページからみた関係で相対的に他のページを参照することができます．
''.''は自分自身のページを表します．''..''は親ページを表します．
例えば
''料理/イタリアン''
のページの中で ''.'' と表記すると そのまま''料理/イタリアン''のページのことを指していることになります．
''..''と表記すると''料理''のページをことを指します．
さらに例を挙げると以下の表のようになります．

|料理/イタリアン 内での表記|指されるページ      |h
|.                         |料理/イタリアン     |
|..                        |料理                |
|./ピザ                    |料理/イタリアン/ピザ|
|../和食                   |料理/和食           |

*特別なページ

**トップページ
''Top''というページはサイトに最初に訪れたときに表示されます．
''Top''という名前は設定により変更できます．

**サイドページ
デザインテーマにもよりますが，デフォルトのデザインテーマでは
左側に''Side''という名前のページが小さめに常に表示されます．
この''Side''というページは小さめに表示される点を除けば通常のページと同じで自由に編集できます．
このページによく使うページへのリンクを箇条書きすればサイトのナビゲーションとして使うことができます．
''Side''という名前は設定により変更できます．
*/

@manual $manualpage$/ja/PageMenu

&title ページの操作

ページを開いているときの''ページメニュー''の項目を，画面に並ぶ順に説明します．
画面は誰でも開けますが，権限が足りないときは実行のボタンが押せません(ログインすると押せることがあります)．
権限については[[ユーザーの管理:../Administration#ユーザーの管理]]を参照してください．

*編集
''本文の一部をダブルクリックすると，そこだけを編集できます．''
ダブルクリックの代わりにAltキー+クリックでも編集が開始できます．
編集中の欄をもう一度ダブルクリックすると，範囲が外側へ一段ずつ広がります(段落→その節→上の節→ページ全体)．
編集欄の右上には，いま書いている記法の札(''Markdown''または''Wiki'')が出ます(ページ全体の編集画面では，押すとその記法の早見表が開きます)．
Markdownの編集欄には，左に太い線も付きます．
どこまでを一度に編集できるかは，記法によって違います([[Markdown記法:../Markdown#編集方法]]，[[Wiki記法:../Wiki#編集方法]])．

''ページメニュー''内の''編集''を押すと，ページ全体のソースを編集できます．
編集画面の''プレビュー''を押すと，保存する前に変換結果を確かめられます．

*タグ
ページにタグ(分類のための語)を付けます．タグはページの下に出て，押すとそのタグの付いたページの一覧になります([[タグ一覧:../SiteMenu#タグ一覧]])．
ページの下のタグの欄の''編集''からも開けます．
-タグは半角スペースで区切って書きます．入れた内容で''丸ごと置き換わります''．空にすると全部消えます．
-子ページがあるときは，''以下の子ページも同じタグにする''を選べます．孫以下と添付ファイルも，同じタグに置き換わります(足すのではありません)．
-種別Markdownのページでは，本文のフロントマターの ""tags:"" が正です．この画面で変えても，次に本文を保存すると ""tags:"" のとおりに戻ります([[フロントマター:../Markdown/FrontMatter#タグ]])．
-タグはサイトの検索の対象にもなります．

*目次
そのページの見出しを入れ子の一覧にして出します．項目を押すと，その見出しへ飛びます．
本文に書く目次(Wiki記法の[[&&index:../Wiki/Function/index]]，Markdown記法の ""[TOC]""([[目次:../Markdown/Extra#目次]]))と同じ形です．
見出しの無いページでは，本文の書き出しが出ます．

*変更点
履歴の一番新しい版と今のページを比べて，変わった所を出します．履歴が無いときは押せません．
-Wiki記法のページは，表示した形で''削除された部分''と''追加された部分''を出します．''ソースを比較''で行ごとの比較に切り替えられます．
-Markdown記法とtextのページは，行ごとに''削除された行''と''追加された行''を出します．
-添付ファイルは，新旧の2つを並べて出します．
-題名・タグ・説明・ロックの違いは，''メタ情報の違い''の表に出ます．

同じ人が続けて編集したときは版ができないので([[履歴:.#履歴]])，何回か分の変更がまとめて出ます．
好きな2つの版を比べるには，履歴の一覧で2つの版を選んで''比較''を押します．

*履歴
ページは編集される前に，その時の内容が版として履歴に残ります．
ただし同じ人が続けて編集したときは，前の版から15分たつまで新しい版を作りません．
なので過去のある時点でのページの内容を表示したり，比較することができます．
一覧で2つの版を選んで''比較''を押すと，その2つの違いを出します．
タグやメタ情報の変更とロックでも，版ができます．

''ページメニュー''の''履歴''の一覧で，前の版の行の''この版に戻す''を押すと(前の版を表示した画面にもあります)，確認の画面になります．
''この版に戻す''を押すと，今のページをその版の本文と種別で上書きします．
-題名とタグも，その版のものに戻ります(Markdownの題名とタグ，Wiki記法の題名は本文から取り直します)．説明やロックなどは今のままです．
-戻す前の内容は，編集の間隔が短くても必ず履歴に残ります．なので，戻したこと自体も同じ方法で元に戻せます．
-種別の違う版にも戻せます．Wiki記法からMarkdownに変換したページも，変換前の版に戻せばWiki記法に戻ります．
-添付ファイル(種別file)は，中身とファイルの種類を戻します．
-ページを編集できる人だけが使えます．ロック中は，編集と同じく管理者とロックした本人だけです．
-確認の画面を開いたあとに誰かがページを編集していたときは，戻しません．

削除したページの履歴も，そのページ名を開いて''履歴''を押せば見られます(''この版に戻す''は出ません．[[削除:.#削除]]を参照してください)．
[[リネーム:.#リネーム]]したときは，履歴は元の名前のほうに残ります．

*ロック
ロックとはページを編集不可能にすることです．ロックをする権利を与えられたユーザーのみがページのロックを行えます．
ロックはアンロックをすることでもとの編集可能な状態にもどすことができます．
ロックをする権利があるユーザーはロックしたままページを編集することができますが，警告メッセージが表示されます．

ロックの画面では，次のことを選べます．
:''(ユーザー名) だけがアンロックできるようにする''|ログインしているときに出ます．オンにすると，ロックしたユーザー本人と管理者だけが，そのページを編集したりアンロックしたりできます．
:以下の子ページもロックする|子ページがあるときに出ます．はじめからオンです．アンロックの画面にも，同じく''以下の子ページもアンロックする''があります．

ロック中のページを編集・削除・リネームできるのは，管理者とロック可能の権限を持つユーザーです．タグやメタ情報の変更と，''この版に戻す''も同じです．

*削除
ページを削除します．ページを編集できる人が使えます(ロック中は[[ロック:.#ロック]]を参照してください)．
-添付ファイルは子ページなので，''以下の子ページも削除する''をオンにしないと残ります．オンにすると，孫以下もまとめて消えます．
-消す直前の内容は履歴に残ります．消したページは''サイトメニュー''の[[削除されたページ:../SiteMenu#削除されたページ]]に載ります．
-消したページを元に戻すボタンはありません．そのページ名を開いて''履歴''を押すと古い版の内容を見られるので，それを写して同じ名前のページを作り直してください．作り直すと，前の履歴もまた見えるようになり，''この版に戻す''も使えます．
-''履歴も削除する''は管理者にだけ出ます．履歴ごと完全に消すので，''取り消せません''．
-本文を空にして保存しても，削除になります．

*リネーム
ページの名前を変えます．元の名前と新しい名前の両方で，ページを編集できる人が使えます．
-子ページがあるときは''以下の子ページもリネームする''が出ます．はじめからオンです．添付ファイルも子ページなので，オフにすると元の名前の下に残ります．
-新しい名前のページ(子ページの分も含めて)が1つでも既にあると，何も変えずに止まります．
-''他のページのリンクや本文は書き換えません．''元の名前へのリンクは，存在しないページへのリンクになります．必要ならリンクを書き直してください．
-''履歴は付いていきません．''古い版は元の名前の履歴に残り，元の名前は[[削除されたページ:../SiteMenu#削除されたページ]]に載ります．元の名前にリネームし直すと，その履歴もまた見えるようになります．

*Markdownに変換
種別wikiのページを，種別Markdownのページに変換します．種別wikiのページにだけ出ます．
確認の画面で変換後の本文と落ちるものを見てから保存します．変換前の版は履歴に残るので，''この版に戻す''で元に戻せます．
詳しくは[[Wiki記法のページをMarkdownに変換する:../Comparison#Wiki記法のページをMarkdownに変換する]]を参照してください．

*子ページ
そのページの子ページ(孫以下も)と添付ファイルを一覧にします．
上の欄からは，そのページの子ページを作れます(''新規ページ名''に「今のページ名/」が入っています)．
-一覧は入れ子にせず，全部を平らに並べます．読む権限の無いページは出ません．
-並べ方や深さを選んで本文に一覧を出すには，Markdown記法の ""[PAGES]""([[子ページのツリー:../Markdown/Extra#子ページのツリー]])か，Wiki記法の[[&&treepages:../Wiki/Function/treepages]]を使います．
-種別fileのページ(添付ファイル)には出ません．

*添付
他のWikiエンジンで添付ファイルに相当する機能はNextFormでは種別fileの子ページを作ることで実現できます．
''料理/和食''のページにexample1.jpgとexample2.pngを添付した場合，
-''料理/和食/example1.jpg''
-''料理/和食/example2.png''
の二つの種別fileのページを作成したことになります．
''ページメニュー''内の''添付''機能により上記のことが簡単に行えるようになっています．
また，NextFormでは複数のファイルを同時に添付することができます．

添付したファイルは，''添付''の画面の''添付ファイル''の一覧からまとめてダウンロードできます．
一覧は，チェックボックス・添付ファイル名・保存日時・サイズ(バイト数)の表です．見出しを押すと，その列で並べ替えられます．
ファイルの前のチェックボックスで選び，''ダウンロード''を押します．見出しの行のチェックボックスを押すと全部選べ，もう一度押すと全部外れます．
1つだけ選んだときはそのファイルを，2つ以上選んだときはZIPファイル1つにまとめてダウンロードします．
どちらも添付したときのファイルのままです(画像も縮小しません)．

添付した画像や動画をページ内に埋め込むには，Markdown記法では ""![説明](ファイル名)""
([[リンク・画像・添付:../Markdown/Link]])を，Wiki記法では
[[&&include:../Wiki/Function/include]]を使用します．

添付したHTMLファイルは，既定では開くとダウンロードになります．
サイトの設定で有効にすると，ブラウザでそのまま動かせます
([[HTMLファイルの直接実行:../HtmlFile]])．

*メタ情報
ページの''タイトル''(題名)と''説明''を決めます．
:タイトル|ページ名とは別に表示する題名です．本文に題名が書いてあるとき(Wiki記法の[[&&title:../Wiki/Function/title]]，Markdown記法の ""title:"" か先頭の ""#"" 見出し)はそちらが使われ，ここで入れた題名は使われません．本文に題名が無いときはここで付けられますが，種別wikiと種別Markdownのページでは，次に本文を保存すると消えます．
:説明|ページの説明です．検索エンジン向けの説明になり，サイトの検索の対象にもなります．本文を保存しても，''この版に戻す''をしても消えません．
*/

**他のNextFormのページをクローンする
ページの種別で''他のNextFormページのクローン''を選んで''作成''を押すと，
クローン元のページのURLを入れる画面になります．
URLを入れて''クローン''を押すと，そのページの本文と添付ファイルを同じ種別(Markdown，wiki，text，file)で写して，新しいページを作ります．
題名とタグは本文に書いてあるので，一緒に写ります．
-写す添付ファイルは，写すページの直下のもの(""./画像.png""で参照するもの)だけです．ほかのページの添付ファイル(""../画像.png""など)は写しません．本文は書き換えないので，それへのリンクはリンク切れになります(このサイトに同じ名前のページがあれば，そちらを指します)．
-履歴・ロック・権限と，ページや添付ファイルの説明は写しません．クローン元でログインが必要だったページも，写したあとはこのサイトの権限で見えるようになります．
-ログインが必要なページは，URLの下の欄にそのサイトのユーザー名とパスワードを入れればクローンできます．要らなければ空欄のままでかまいません．入れたものは保存せず，そのクローンにだけ使います．対応しているのはNextFormのログイン(ダイジェスト認証)だけで，パスワードそのものはクローン元に送りません．この画面がhttpsでないときは，ブラウザからこのサイトまでパスワードが暗号化されずに送られるので，注意書きが出ます．入れたときは，取りに行く前にログインできることを確かめ(違っていれば何も写しません)，ログインしなくても読めるページも，その利用者として読みます．クローン元がhttpsからhttp(暗号化なし)に転送したときは，ログインの情報を送る前に止まり，続けるかを尋ねます．続けるときは「暗号化されていなくても続ける」にチェックを入れ，パスワードをもう一度入れて押します．初めからhttpのURLを入れたときは尋ねません．
-添付ファイルは1つずつ，このサイトのサイズ上限(''添付''の画面に出る値)に収まる必要があります．
-写せないときは，何も作らずに理由を出します．

URLの下のチェックボックスで，何を写すかを選べます．
:添付ファイルを含む|はじめからオンです．外すと，添付ファイルを写しません．
:子ページを含む|ログインしているときだけ出ます．はじめはオフです．オンにすると，そのページの下のページを孫以下まで全部，同じ形で写します(''添付ファイルを含む''がオンなら，それぞれの添付ファイルも写します)．木の中どうしのリンク(""./子""など)は，そのままつながります．
子ページを含めるときは，次のことに気をつけてください．
-クローン元で読めないページは，一覧に出てこないので写りません．写すには，そのサイトのユーザー名とパスワードを入れてください．
-写す先に同じ名前のページが1つでもあれば，何も写しません．
-一度に写せるのは，既定では子ページ100ページ・添付ファイル500個・合計256MBまでです．クローン元から取るのに30秒を超えたときも断ります．大きな木は，下のページから分けてクローンしてください．
-子ページを含むクローンは，サイト全体で同時に1つだけ動きます．
-書いている途中でサーバーが止まると，一部のページだけが残ることがあります．そのときは，残ったページを''削除''の画面で(''以下の子ページも削除する''をオンにして)消してから，やり直してください．

クローン元を取りに行くのは，このwikiのサーバーです．
既定では，インターネットに公開されているサイトからしか取りません．
開発用のサイトや自宅のLANのサイトのような，プライベートなネットワークにあるサイトから取るには，
''サイト設定''の''クローン元として許すホスト''に，そのホスト名かサイトのURLを書いてください(URLはホストの部分だけを見ます)．

&title サイトの管理

|Google API key|[[&&calendar:../Wiki/Function/calendar]]で予定を取るときに使います|
index.phpで定義した項目は，この画面で変えても効きません([[サイトの高度な設定:.#サイトの高度な設定]])．

**WAFに保存を止められるとき(ConoHa WINGなど)
ConoHa WINGなどの共用サーバーには，攻撃に見える文字列を含む送信を遮断する仕組み(WAF)があります．
本文に""'--""や""<script>""のような，プログラムのコード例によく出る文字列を書いて保存すると，
WAFがそれを攻撃とみなし，「閲覧できません (Forbidden access)」の画面(Powered by SiteGuard Lite)になって保存できないことがあります．
NextFormに届く前に止められているので，NextFormの側には何も記録が残りません．

この場合は''サイトメニュー'' > ''管理ツール'' > ''サイト設定''の''フォームの送り方''を
''Base64に包んで送る (WAF対策)''にしてください．
ブラウザが送る内容をBase64に包んで送り，NextFormが元に戻すので，WAFに当たらなくなります．
index.phpに次のように書いても同じです．
 define('POST_ENCODING', 'base64');

包んで送るようにすると，次のようになります．
-このwikiに送る内容をWAFが検査しなくなります．NextFormはデータベースを使わず，表示するときに自分で無害化しているので，WAFに頼っている守りはありませんが，必要なサイトだけで選んでください．
-ページの本文などの文字は約4/3倍の大きさで送られます．添付ファイルは包まずに送るので，添付のサイズ上限は変わりません．
-JavaScriptを無効にしているブラウザでは包まずに送ります(WAFに止められることがあります)．
-検索語は包みません(URLに出るため)．検索語に""'--""などを入れると止められることがあります．
-自作のプラグインが送られた値をargs_get()を通さずに読んでいる場合は，Base64のまま受け取ります．
-設定を切り替える前に開いていた画面から送ると，「送られた内容を読み取れませんでした」と出ます．入力した内容を控えてから，画面を読み込み直してください．

コントロールパネルのWAFの除外設定で対処することもできますが，止められる文字列の種類ごとに除外を足すことになり，同じドメインのほかのアプリからもその検査が外れます．

*外観の設定
テーマごとの見た目を決めます．テーマそのものは[[サイト設定:.#サイト設定]]の''テーマ''で選びます．
|テーマ|特徴|h
|basic|標準のテーマ|
|plain|線と余白で区切り，角丸や影を使わない．行間が広い|
|docs|本文の幅を読みやすい長さで止め，見出しの深さで差を付ける．サイドページを画面に留めて目次のように使う|
|card|本文とサイドページをカードに載せて浮かせる|
どのテーマも項目は同じで，テーマを切り替えても値は引き継がれます．
:レイアウト|画面全体に広げるか，幅を固定するか．
:サイドページの位置|左か右か．
:文字の大きさ|12〜20px(はじめは14px)．見出しの大きさもこれに合わせて変わります．

*ユーザーの管理
NextFormではユーザーごとページごとに権限が設定できます．
ユーザーの設定をするには''サイトメニュー'' > ''管理ツール'' > ''ユーザーの管理'' を選択してください．
権限には以下のものがあります．上から順に権限が強くなり，下の権限は上の権限を含みます．

|権限            |説明                          |h
|利用不可        |すべての機能が使用できません．|
|閲覧のみ        |ページの閲覧のみが可能                                       |
|テキストの挿入のみ|[[&&comment:../Wiki/Function/comment]]や[[&&bbs:../Wiki/Function/bbs]]で用意されたフォームからコメント等の挿入が可能(注意，下記参照)|
|編集可能        |ページの編集が可能|
|ロック可能      |ページをロックすることが可能|
|エクスポート可能|[[エクスポート機能:../Export]]が有効のとき，エクスポートが可能|
|管理者          |サイトの設定を含むあらゆることが可能|

一覧の表では，次のことができます．
-一番上の行は''ログインしていないユーザー''です．ログインしていない人(と，一覧に無いユーザー名でログインした人)の権限になります．
-一番下の行に名前を入れると，ユーザーを足します．ユーザー名に使えるのは英数字と ""-"" ""_"" です．
-パスワードの列の''未設定''や''変更''を押すと，パスワードを決める画面になります．
-''削除''にチェックして適用すると，そのユーザーを消します．
-パスワードのある管理者が1人もいなくなる変更はできません．
-index.phpに書いたユーザー(""$AUTH_PERMISSIONS"" ""$AUTH_DIGESTS"")は，この画面では変えられません．
-''エクスポート可能''は，[[エクスポート機能:../Export]]を有効にしたときだけ選べます．

これらの権限の他に''ページごとに設定''という項目を選択するとページごとに権限が設定できます．
選ぶと，ページ名と権限の決まりを並べる画面に移ります(JavaScriptが要ります)．
-ページ名には &* と ? のワイルドカードが使えます．料理/&* は料理の子や孫のページで，料理そのものは含みません．
-決まりは上から順に見て，最初に当てはまった行の権限を使います．どれにも当てはまらないページでは，何もできません．

テキストの挿入のみの権限は見かけ上は[[&&comment:../Wiki/Function/comment]]や[[&&bbs:../Wiki/Function/bbs]]
を通してのみ編集可能な権限ですが，実際は任意の位置に任意の文字を挿入することができる権限です．
例えば悪意あるユーザーが特殊な方法を使用して，ページの先頭に'&/&*'を，
ページの末尾に'&*&/'を挿入することでページの内容をすべてコメント(非表示)にすることもできます．
テキストの挿入のみの権限は実質的には編集可能と同様の権限で，
用意されたフォーム以外ではページの編集が行い辛くなるという気休めの権限であると考えてください．

-''検索インデックスを読めませんでした''と出たとき
-検索で見つかるはずのページが見つからないとき

*他のwikiからページをインポート

 define('定数名', '定数の値');

 // custom settings here -------
 define('DEFAULT_PAGE_TYPE', 'text');

 ?>

 SetEnv NEXTFORM_DEFAULT_PAGE_TYPE "text"

index.phpで定義した項目は，画面で変えても効きません．

&title 色調(トーン)

*色調とは
色調は画面で使う27色の組です．
テーマ(配置や余白の作り)とは別の軸なので，どのテーマを選んでも同じ色調が使えます．
''サイトメニュー'' > ''管理ツール'' > ''色調の設定'' で決めます．

*色を決める
''色調の設定''では，27色をそのまま並べています．
変えたい色だけを書き換えて，''適用''(上と下にあります)を押してください．

はじめから入っている色調や，保存した色調から始めることもできます．
一番上の''色調の読み込み''で選んで''読み込む''を押すと，入力欄にその色が入ります．
この時点ではまだ変わりません．''適用''を押すと使われます．

*リンクの色
''未訪問リンク (Markdown)''と''訪問済みリンク (Markdown)''は，
行き先が種別Markdownのページであるリンクの色です．
Wiki記法のページへのリンクと色を変えておくと，押す前にどちらの記法のページか分かります．

この2つと''未訪問外部リンク''・''訪問済み外部リンク''は，''空欄''にしておくと
''未訪問リンク''・''訪問済みリンク''と同じ色になります．''未訪問リンク''を変えれば一緒に変わります．
最初は空欄です．
(外部リンクの色を以前に保存したサイトでは，その色のまま残ります．
空欄にして''適用''すれば，リンクの色に揃います．)

*色調を保存する
色を決めたら，''この色調の保存''に識別子と表示名を入れて''保存''を押します．
サーバーに保存され，''色調の読み込み''に出るようになります．
(''保存''を押すと適用も同時に行われます．)

識別子はそのままファイル名になるので，半角の英数字と . _ - だけが使えます(32文字まで)．
日本語の名前は''表示名''に入れてください．

''保存した色調の削除''から選んで''削除''を押すと消せます．削除は取り消せません．
読み込みの一覧では，''後から保存したものほど上''に出ます．

*保存される場所
色調は1つがファイル1つです．2つのディレクトリから読み込まれます．

|ディレクトリ|内容|h
|app/tone/|NextFormに最初から入っている色調．更新のたびに入れ替わるので，ここは編集しない|
|storage/tone/|このサイトで保存した色調．更新しても残る|

同じファイル名なら''storage''側が使われます．
最初から入っている色調と同じ識別子で保存すれば上書きでき，
storage側のファイルを消せば元に戻ります．

サーバーの管理者は，このファイルを直接置いたり，
別のサイトへ複製したりすることができます．

*ファイルの形式
JSONです．

 (code)
 {
     "order": 100,
     "names": {"en": "deep sea", "ja": "深い海"},
     "colors": {
         "THEME_COLOR_BACKGROUND": "#0b1b2b",
         "THEME_COLOR_TEXT": "#e6eef7"
     }
 }

|項目|内容|h
|order|最初から入っている色調を並べる順．小さいほど先(10〜60)．保存した色調はこれに関わらず新しい順に上に出る|
|names|言語ごとの表示名．その言語の名前が無ければ英語，それも無ければファイル名が使われる|
|colors|色．名前は''THEME_COLOR_''で始まり，値は''#rrggbb''形式|

colorsに書かなかった色は使われません．
ただし''THEME_COLOR_MARKDOWN_LINK''・''THEME_COLOR_MARKDOWN_LINK_VISITED''・
''THEME_COLOR_EXTERNAL_LINK''・''THEME_COLOR_EXTERNAL_LINK_VISITED''は，
書かなければリンクの色と同じになります(画面で空欄にして保存すると書かれません)．
画面から保存すると常に(空欄の色を除く)すべての色が書かれるので，
手で作るときは保存したファイルを複製して書き換えるのが確実です．
*/

&title アクセス解析の設定
このページはWebサーバーの管理者でOSの操作に慣れている方を対象としています．

NextFormではWebサーバーのアクセスログを集計することで，
[[アクセスカウンター:../../Wiki/Function/counter]]や[[人気のページ:../../Wiki/Function/popularpages]]
の機能を実現しています．
そのため，これらの機能を使用する場合は，
一定の間隔でアクセスログを集計するスクリプトを実行させる必要があります．

*集計スクリプト

集計するスクリプトは以下のように使用します．
 $ php <install dir>/app/tool/analyze_weblog <path to index.php> <URL> <path to resume file> <log file>
:<install dir>|NextFormをインストールしたディレクトリ
:<path to index.php>|サイトのindex.phpへのパス(すなわちサイトの設定ファイル)
:<URL>|サイトのURL
:{<path to resume file>|再開情報ファイルへのパス．
存在している必要はありませんが，このファイルを作成，書き込みできる権限必要です．
このファイルはどのアクセスログをどこまで集計済みなのかが記録されています．
消してしまったり，別のファイルを指定して集計すると二重カウントになる恐れがあります．}
:{<log file>|Webサーバーのアクセスログへのパス．
現在対応している形式はcommon, combinedとこれらの先頭にバーチャルホストのホスト名をつけた形式です．
再開情報ファイルをもとに前回集計した箇所まで読み飛ばして集計を行いますので同じログファイルに対して何度実行されても
二重カウントにはなりません．
ログファイルは''必ず相対パス，絶対パスどちらか一方をで指定して使用してください．''
このスクリプトはパスが異なると違うログファイルと認識して，二重カウントしてしまいます．
前回の集計と比べてinode番号が変わっていたり，ファイルサイズが小さくなっている場合はログがローテーションされたと認識し，
ファイルの最初から集計を行います．
もし二重カウントされてしまう場合はログのローテーションのタイミングで再開情報ファイルを削除するとうまくいく可能性があります．
}
スクリプトは''NextFormのディレクトリへの書き込み権限とアクセスログの読み込み権限を持ったユーザー''で実行してください．

アクセスログが残っている場合に限りますが，もし二重カウントしてしまった場合は
 $ php <install dir>/app/tool/analyze_weblog <path to index.php> <URL> <path to resume file> --delete-all
を実行するとすべての集計結果と再開情報ファイルが削除されますので，最初から再集計を行うことができます．

*スクリプトを一定の間隔で実行させる

自動で実行させる前に手動でコマンドを実行し，問題がないか確認しておくことをおすすめします．

例えばcronを使用して10分間隔で実行する場合，crontabに以下のような設定をします(ユーザーの権限に注意)．
 # NextFormアクセスログ集計
 $comment_end$10 * * * * php /var/www/nextform/app/tool/analyze_weblog /var/www/html/index.php http://example.jp/wiki/ /var/www/nextform-resume.txt /var/log/httpd/access_log >/dev/null 2>&1

*集計の結果
集計の結果は，''管理ツール'' -> ''アクセス解析''で確認できます．
*/

/**
@manual $manualpage$/en/PageMenu

&title Page operations

This page explains the items of the ''page menu'' shown on a page, in the order they appear on the screen.
Anyone can open their screens, but the button that carries out an operation cannot be pressed without enough rights (logging in may make it available).
For rights, see [[User Manager:../Administration#User Manager]].

*Edit
''Double click a part of the page to edit just that part.''
Alt and click works instead of a double click.
Double clicking the edit box again widens the range one step outwards (paragraph, its section, the enclosing section, then the whole page).
The label at the top right of the edit box (''Markdown'' or ''Wiki'') shows which notation you are writing in (on the screen for editing the whole page, click it to open the cheat sheet for that notation).
The edit box for Markdown also has a thick line on its left.
How much can be edited at once depends on the notation ([[Markdown notation:../Markdown#How to edit]], [[Wiki notation:../Wiki#How to edit]]).

Click ''Edit'' in the ''page menu'' to edit the source of the whole page.
Press ''Preview'' on the editing screen to check the converted result before saving.

*Tags
Puts tags (words for sorting pages) on the page. The tags are shown at the bottom of the page, and clicking one lists the pages with that tag ([[All tags:../SiteMenu#All tags]]).
''Edit'' in the tag area at the bottom of the page also opens this screen.
-Write the tags separated by half-width spaces. What you enter ''replaces the tags as a whole''; leaving it empty removes them all.
-When the page has subpages, you can choose ''Tag follow subpages''. The grandchildren and the attached files below get the same tags too, replacing theirs (the tags are not added).
-On a page of type Markdown, ""tags:"" in the front matter of the text is what counts. Even if you change the tags on this screen, they go back to ""tags:"" the next time the text is saved ([[Front matter:../Markdown/FrontMatter#Tags]]).
-Tags are also searched by the site search.

*Summary
Shows the headings of the page as a nested list. Clicking an item jumps to that heading.
It has the same shape as a table of contents written in the text (&&index in Wiki notation, ""[TOC]"" in Markdown notation ([[Table of contents:../Markdown/Extra#Table of contents]])).
A page without headings shows the beginning of its text instead.

*Modification
Compares the newest version in the history with the current page and shows what changed. It cannot be pressed when there is no history.
-A page in Wiki notation shows the ''Deleted part'' and the ''Added part'' in the displayed form. ''Compare source'' switches to a line by line comparison.
-Pages in Markdown notation and text pages show the ''Deleted line'' and the ''Added line'' line by line.
-For an attached file, the old and the new files are shown side by side.
-Differences in the title, the tags, the description and the lock are shown in the ''Meta info difference'' table.

When the same person edits again and again, no new version is made ([[History:.#History]]), so the changes of several edits are shown together.
To compare any two versions, choose two versions in the list of the history and press ''Compare''.

*History
Before a page is edited, its contents at that moment are kept in the history as a version.
When the same person edits again within 15 minutes of the last version, however, no new version is made.
You can therefore show the contents of a page as it was at some point in
the past, or compare two versions.
Choose two versions in the list and press ''Compare'' to see the differences between them.
Changing the tags or the meta info, and locking, also make a version.

In the list of ''History'' in the ''page menu'', press ''Restore this version'' on the row of an older version (it is also on the page showing that version), and a confirmation screen appears.
Press ''Restore this version'' there, and the current page is overwritten with the text and the type of that version.
-The title and the tags return to those of that version (the title and tags of Markdown and the title of Wiki notation are taken again from the text). The description, the lock and so on stay as they are.
-The content before restoring is always kept in the history, even when the edits come close together. So restoring can itself be undone in the same way.
-A version of a different type can be restored too. A page converted from Wiki notation to Markdown returns to Wiki notation when restored to the version before conversion.
-For an attached file (type file), its contents and file type are restored.
-Only those who can edit the page can use it. While the page is locked, only administrators and the user who locked it can, as with editing.
-If someone edits the page after the confirmation screen was opened, nothing is restored.

The history of a deleted page can also be seen by opening that page name and clicking ''History'' (''Restore this version'' is not shown; see [[Delete:.#Delete]]).
When a page is [[renamed:.#Rename]], its history stays with the old name.

*Lock
Locking a page makes it impossible to edit. Only a user who has been granted the right
to lock can lock a page. Unlocking returns it to the editable state.
A user who has the right to lock can edit a page while it stays locked,
but a warning message is shown.

On the lock screen you can choose the following.
:''Enable only (user name) unlocking''|Shown when you are logged in. With it on, only the user who locked the page and administrators can edit or unlock it.
:''Lock follow subpages''|Shown when the page has subpages. On at first. The unlock screen likewise has ''Unlock follow subpages''.

While a page is locked, administrators and users with the lock right can edit, delete and rename it. The same goes for changing the tags or the meta info, and for ''Restore this version''.

*Delete
Deletes the page. Those who can edit the page can use it (while it is locked, see [[Lock:.#Lock]]).
-Attached files are subpages, so they remain unless ''Delete follow subpages'' is on. With it on, the grandchildren and below are deleted too.
-The contents just before deletion are kept in the history. A deleted page appears in [[Deleted pages:../SiteMenu#Deleted pages]] in the ''site menu''.
-There is no button that brings a deleted page back. Open that page name and click ''History'' to see its old versions, and create a page of the same name again from them. Once it is created again, the earlier history becomes visible again and ''Restore this version'' can be used.
-''Delete history too'' is shown only to administrators. It deletes the page together with its history, so it ''cannot be undone''.
-Saving a page with empty text also deletes it.

*Rename
Changes the name of the page. Those who can edit both the old name and the new name can use it.
-When the page has subpages, ''Rename follow subpages'' is shown. It is on at first. Attached files are subpages too, so with it off they stay under the old name.
-If a page with a new name (including those of the subpages) already exists, it stops without changing anything.
-''Links and text in other pages are not rewritten.'' Links to the old name become links to a page that does not exist. Rewrite them if needed.
-''The history does not move with the page.'' The old versions stay in the history of the old name, and the old name appears in [[Deleted pages:../SiteMenu#Deleted pages]]. Renaming the page back to the old name makes that history visible again.

*Convert to Markdown
Converts a page of type wiki into a page of type Markdown. It is shown only on pages of type wiki.
You save after checking the converted text and what is dropped on the confirmation screen. The version before conversion is kept in the history, so ''Restore this version'' brings it back.
For details see [[Converting a page in Wiki notation to Markdown:../Comparison#Converting a page in Wiki notation to Markdown]].

*Subpage
Lists the subpages of the page (including grandchildren and below) and its attached files.
The form at the top creates a subpage of the page (''New page name'' is filled in with the current page name and a slash).
-The list is flat, not nested. Pages you cannot read are not shown.
-To show a list in the text with a chosen order or depth, use ""[PAGES]"" in Markdown notation ([[Tree of subpages:../Markdown/Extra#Tree of subpages]]) or &&treepages in Wiki notation (&&pages with show=tree; see [[&&pages:../Wiki/Function/pages]]).
-It is not shown on pages of type file (attached files).

*Attach
What other wiki engines offer as attached files is done in NextForm by creating child
pages of type file.
Attaching example1.jpg and example2.png to the page ''Cooking/Japanese'' means you have
created the two pages of type file
-''Cooking/Japanese/example1.jpg''
-''Cooking/Japanese/example2.png''
The ''Attach'' function in the ''page menu'' makes this easy.
NextForm can also attach several files at once.

Attached files can be downloaded together from the ''Attachment files'' list on the ''Attach'' page.
The list is a table of check boxes, attached file names, the times they were saved and their sizes (in bytes). Pressing a heading sorts the table by that column.
Choose them with the check boxes in front of the files and press ''Download''. The check box in the heading row chooses all of them; pressing it again clears them all.
When you choose one file, that file is downloaded; when you choose two or more, they are put together into one ZIP file.
Either way the files are as they were attached (images are not shrunk either).

To embed an attached image or video in a page, Markdown notation uses
""![description](file name)"" ([[Links, images and attachments:../Markdown/Link]])
and Wiki notation uses [[&&include:../Wiki/Function/include]].

By default, an attached HTML file is downloaded when it is opened.
Enabling it in the site settings lets you run it in the browser as it is
([[Running HTML files directly:../HtmlFile]]).

*Meta info
Sets the ''Title'' and the ''Description'' of the page.
:Title|A title shown apart from the page name. When the text sets a title ([[&&title:../Wiki/Function/title]] in Wiki notation, ""title:"" or a single ""#"" heading at the top in Markdown notation), that one is used and the title entered here is not. When the text has no title you can set one here, but on pages of type wiki and Markdown it disappears the next time the text is saved.
:Description|A description of the page. It becomes the description for search engines and is also searched by the site search. It is kept when the text is saved and when ''Restore this version'' is used.

**When a WAF stops saving (ConoHa WING and others)
Shared servers such as ConoHa WING have a mechanism (a WAF) that blocks requests containing strings that look like attacks.
When you save a page whose text contains strings common in program code examples, such as ""'--"" or ""<script>"",
the WAF may take it as an attack and show a "Forbidden access" page (Powered by SiteGuard Lite) instead of saving.
The request is stopped before it reaches NextForm, so nothing is recorded on the NextForm side.

In that case, choose ''site menu'' > ''Admin tools'' > ''Site preferences'' and set
''How forms are sent'' to ''Wrap in Base64 (for a WAF)''.
The browser wraps what it sends in Base64 and NextForm unwraps it, so the WAF no longer reacts.
Writing the following in index.php does the same.
 define('POST_ENCODING', 'base64');

When forms are wrapped:
-The WAF no longer inspects what is sent to this wiki. NextForm uses no database and makes the output safe itself when showing it, so no protection relies on the WAF, but choose it only on sites that need it.
-Text such as the page body is sent at about 4/3 of its size. Attached files are sent unwrapped, so the size limit for attachments does not change.
-A browser with JavaScript turned off sends without wrapping (the WAF may stop it).
-Search words are not wrapped (they appear in the URL). Search words containing ""'--"" and the like may be stopped.
-A plugin of your own that reads the sent values without going through args_get() receives them still in Base64.
-Sending from a page that was opened before the setting was changed shows "The request could not be read". Copy what you entered, then reload the page.

The WAF exclusion settings in the control panel can also deal with this, but you have to add an exclusion for each kind of string that is stopped, and the exclusion also removes that check from the other applications on the same domain.

:{<path to resume file>|the path to the resume file.
It does not have to exist already, but you need the rights to create and write it.
This file records which access log has been totalled up to where.
Removing it, or totalling up while naming a different file, risks counting twice.}
:{<log file>|the path to the access log of the web server.
The formats supported at present are common and combined, and those two with the host
name of a virtual host in front.
Totalling skips ahead to where the last run finished, based on the resume file, so
running it many times against the same log file does not count twice.
''Always name the log file by either a relative path or an absolute path, consistently.''
This script treats a different path as a different log file and counts twice.
When the inode number has changed since the last run, or the file has become smaller,
it takes the log to have been rotated and totals from the start of the file.
If it does count twice, removing the resume file at the moment the log rotates may
put it right.
}
Run the script ''as a user who has the right to write into the NextForm directory and to read the access log''.

Only while the access log is still there, if it has counted twice, running
 $ php <install dir>/app/tool/analyze_weblog <path to index.php> <URL> <path to resume file> --delete-all
removes every total and the resume file, so that you can total again from the start.

*Running the script at a regular interval

Before running it automatically, we recommend running the command by hand and
checking that nothing is wrong.

To run it every 10 minutes with cron, for example, set up crontab like this
(mind the rights of the user).
 # NextForm access log totalling
 $comment_end$10 * * * * php /var/www/nextform/app/tool/analyze_weblog /var/www/html/index.php http://example.jp/wiki/ /var/www/nextform-resume.txt /var/log/httpd/access_log >/dev/null 2>&1

*The results
The results can be seen at ''Admin tools'' -> ''Access analysis''.
*/

/**
@manual $manualpage$/ja/Markdown/Basic
&title Markdown記法の基本要素

Markdownの土台([[CommonMark:https://spec.commonmark.org/]])の範囲の書き方です．
表や脚注などの拡張は[[拡張要素:../Extra]]に，
ページへのリンクと画像は[[リンク・画像・添付:../Link]]にあります．

*段落と改行
空行で区切ると別の段落になります．
段落の中でソースを改行しても，表示は改行されません(語の区切りとして扱われます)．
段落を分けずに表示も改行したいときは，行末に''半角スペースを2つ''置くか，
''バックスラッシュ''を1つ書きます．

*見出し
行頭に ""#"" と半角スペースを書きます．""#"" の数(1〜6個)がそのまま見出しの深さになります．
ふつう ""#"" はページの題名になる(本文から消えて，ページの上の見出しに出る)ので，本文の見出しは ""##"" から書きます．
""##"" がWiki記法の ""*"" と同じ大きさです．
""#"" が題名にならずに本文に残るとき(フロントマターに ""title:"" があるとき，""#"" が2つ以上あるときなど)は，""##"" より一段大きく出ます．

 # 題名(本文の先頭の1つだけなら，ページの題名になります)
 ## 見出し(Wiki記法の * と同じ大きさ)
 ### その下の見出し

行の''下''に ""==="" の行を書くと1段目，""---"" の行を書くと2段目の見出しになる，
別の書き方もあります．文のすぐ下の行にうっかり ""---"" を書くと，
区切り線ではなくその文が見出しになるので注意してください．

Wiki記法の節と違い，Markdown記法の見出しは折りたたみを持たず，範囲も持ちません．
本文の一部をたたみたいときは[[折りたたみ:../Extra#折りたたみ]]で囲んでください．

*強調
|書き方|出るもの|h
|""**重要**""|太字|
|""*強調*""|斜体|
|""***重要かつ強調***""|太字の斜体|

アスタリスクの代わりにアンダースコア(""__重要__"" ""_強調_"")でも同じです．

*文中のコード
""$bq$"" で囲むと文中のコード(等幅の文字)になります．
コードの中に ""$bq$"" 自体を書きたいときは ""$bq$$bq$"" で囲みます．

*箇条書き
行頭に ""- "" を書きます．項目の頭を半角スペース2つ下げると入れ子になります．

 - 項目
 - 項目
   - 入れ子の項目

数字と ""."" で始めると番号つきになります．
最初の数字が開始番号になり，2つ目からの番号は表示のときに振り直されます．

 1. 番号つきの項目
 2. 番号つきの項目

1つの項目に複数の段落やコードブロックを入れたいときは，
空行を挟んで項目の字下げに合わせて続けます．

項目と項目のあいだに空行を挟んでも，箇条書きは''分かれません''．
前後は1つの箇条書きのままです([[CommonMark:https://spec.commonmark.org/]]の決まりです)．
2つに分けたいときは，片方の記号を変えてください．

 - ハイフンの箇条書き
 * アスタリスクの箇条書き

見た目は書いたとおりに空きます．空行を入れた所だけが，Wiki記法で箇条書きが
分かれたときと同じだけ空き，空行の無い項目のあいだは詰まったままです．

*引用
行頭に ""> "" を書きます．""> > "" と重ねると引用の中の引用になります．

 > 吾輩は猫である。
 > 名前はまだ無い。

*コードブロック
""$bq$$bq$$bq$"" だけの行で囲むと，中身が書いたとおり(改行も含めて)表示されます．
開始の行に続けて言語名を書けます(例: ""$bq$$bq$$bq$php"")．
言語名はソースに意味を添えるだけで，
[[対応表:../../Comparison]]にあるとおり色分けはされません．

 $bq$$bq$$bq$
 int func(int a) {
     return a * 2;
 }
 $bq$$bq$$bq$

""~~~"" の行で囲んでも同じです(中身に ""$bq$$bq$$bq$"" を書きたいときに使えます)．
行頭を半角スペース4つで下げる書き方もあります(囲みは要りません)．

*区切り線
""---"" ""***"" ""___"" のいずれかだけの行は区切り線になります．
文の直後の行に書くと[[見出しの下線:.#見出し]]と解釈されるので，前に空行を置いてください．
文書の''先頭''の ""---"" は[[フロントマター:../FrontMatter]]の始まりとして扱われます．

*エスケープ
記号を記法としてではなくそのまま表示したいときは，記号の前にバックスラッシュを書きます．

 \*強調ではなくアスタリスクを表示\*

*文字の参照
ソースに &&copy; のようなHTMLの文字参照を書くと，その文字(この例では©)になります．
*/

/**
@manual $manualpage$/ja/Markdown/Extra
&title Markdown記法の拡張要素

[[CommonMark:https://commonmark.org/]]の土台に加えて，
[[GitHub Flavored Markdown:https://github.github.com/gfm/]]の拡張
(表・打ち消し線・チェックボックス・自動リンク)と脚注が使えます．
GitHubやObsidianで通じる書き方は，おおむねそのまま通じます．
折りたたみだけはNextForm独自の書き方です．

*表
""|"" でセルを区切って，1行に表の1行分を書きます．
1行目がヘッダになり，2行目には ""---"" を並べた区切りの行を書きます．

 | 品名 | 値段 |
 | --- | --- |
 | りんご | 120円 |
 | みかん | 80円 |

区切りの行にコロンを添えると，列ごとに揃える向きを指定できます．

 | 左揃え | 中央揃え | 右揃え |
 | :--- | :---: | ---: |

セルの中では強調や文中のコードなどの記法が使えます．
Wiki記法の表と違い，セルの結合はできません．
保存のときに桁をそろえる整形も行われません(ソースは書いたとおりに残ります)．

*打ち消し
""~~"" で囲むと打ち消し線が引かれます．

 ~~これは違いました~~

*チェックボックス
箇条書きの項目を ""[ ]"" か ""[x]"" で始めるとチェックボックスになります．

 - [ ] まだの項目
 - [x] 済んだ項目

表示されるチェックボックスは見るためだけのもので，画面から付け外しはできません．
変えるにはソースを編集します．

*脚注
本文に ""[^1]"" のような印を書き，別の行に ""[^1]: 中身"" を書きます．
脚注はページの末尾にまとめて表示され，本文との行き来のリンクが付きます．

 むかしむかし[^1]あるところに．
 
 [^1]: 具体的な年代は分かっていない．

印は数字でなくても構いません(""[^note]"" など)．表示は通し番号になります．

*自動リンク
URLをそのまま書くとリンクになります．""www."" で始まる語もリンクになります．
""<"" と "">"" でURLを囲んで書くこともできます．

*折りたたみ
コロン3つに続けて ""details"" と書いた行から，コロン3つだけの行までが
折りたたみになります．""details"" の後ろに書いた文字が，たたまれているときの
見出しになります．

 :::details 詳しい手順
 中身はふつうのMarkdownです．見出しでも表でも書けます．
 :::

既定では閉じた状態で表示されます．最初から開いておくには，
""details"" の直後に ""+"" を付けるか，""open"" と書きます．どちらも同じ意味です．

 :::details+ 最初から開いている
 中身
 :::

 :::details open 最初から開いている
 中身
 :::

見出しを ""open"" という語で始めたいときは，""+"" のほうを使ってください．

 :::details+ open な話
 中身
 :::

入れ子にするときは，外側のコロンを増やします．
閉じるコロンは，開いたときと同じ数以上でなければなりません．
閉じ忘れたときは，ページの終わりで閉じられます．

 ::::details 外側
 :::details 内側
 中身
 :::
 ::::

見出しの文字に記法は効きません(そのままの文字として表示されます)．
""details"" 以外の語(""note"" など)を書いても折りたたみにはなりません．

見出しを書いた折りたたみは，ふつうの見出しと同じく目次に載り，&[&[ページ名#見出し&]&] でそこへ飛べます(Wiki記法の &*(optional) と同じ)．
目次での深さは，見出しの先頭に ""#"" を書いて決められます(""#"" は表示されません)．
書かなければ，直前の見出しの1段下になります．
""#"" を書いたときは，札(押すと開く行)の文字もその深さの見出しと同じ大きさで出ます．書かなければ本文と同じ大きさの太字です．

 :::details ### 3段目の見出しとして目次に載る
 中身
 :::

この書き方はNextForm独自のもので，Markdownの標準ではありません．
他のツールに貼り付けると，コロンの行が文字として見えます(中身は残ります)．
またブラウザの「ページ内検索」は，閉じている中身を見つけられません
(サイトの検索には中身も載ります)．印刷でも閉じたまま印刷されます．

*目次
""[TOC]"" とだけ書いた行(前後は空行)は，そのページの見出しの目次になります(Wiki記法の &&index と同じ)．
''ツール''の''目次''と同じ形で，項目を押すとその見出しに飛びます．

 [TOC]
 
 ## はじめに

-""[toc]"" と小文字で書いてもかまいません．
-コードの中や，文の途中に書いた ""[TOC]"" は文字のままです．
-サイドページや，取り込まれた先でも目次になります．
-""[TOC]"" という文字は，サイトの検索には載りません．
-GitLab・Typora・Python-Markdown(MkDocs)と同じ書き方です．対応していないツールでは ""[TOC]"" という文字が見えるだけです．

*子ページのツリー
""[PAGES]"" とだけ書いた行(前後は空行)は，そのページの子ページを孫以下まで入れ子にした一覧になります(Wiki記法の[[&&treepages:../../Wiki/Function/treepages]]と同じ)．
""PAGES"" の後ろに空白で区切って，次の指定を並べられます．

 [PAGES]
 [PAGES ./写真]
 [PAGES sort=mtime reverse 10]

:ページ名|そのページの子ページの一覧にします．書き方はリンクと同じで，名前だけと ""./"" はこのページの子，""../"" は隣，""/名前"" はトップ階層からです．""/"" だけならサイト全体です．空白は ""%20"" と書きます．
:sort=mtime|更新日時の順に並べます．""sort=btime"" は作成日時，""sort=size"" は大きさの順です．
:reverse|逆の順に並べます．
:children|直下の子ページだけにします(孫は出しません)．
:数字|その件数だけ出します．
:withsystem|マニュアルのページなども出します．
-読めない指定があるときは，""[PAGES …]"" の文字のまま表示されます．
-子ページが無いときは，何も表示されません．
-""[PAGES …]"" という文字は，サイトの検索には載りません．
-この書き方はNextForm独自のものです．他のツールでは ""[PAGES]"" という文字が見えるだけです．

*記法の例
コロン3つに続けて ""example"" と書いた行から，コロン3つだけの行までが，
「ソース」と「表示」を並べた形になります．
記法の説明を書くときに，同じ原文を2度書かなくて済みます．

 :::example
 - 項目
 - 項目
 :::

「ソース」には書いたとおりの文字が，「表示」にはそれを変換した結果が出ます．
中身はふつうのMarkdownです．表でもコードブロックでも書けます．
コードブロックの中にコロン3つを書いても，そこでは閉じません．

入れ子にするときは，外側のコロンを増やします．
閉じるコロンは，開いたときと同じ数以上でなければなりません．
閉じ忘れたときは，ページの終わりで閉じられます．

 ::::example
 :::example
 中身
 :::
 ::::

折りたたみと違い，""example"" の後ろに文字は書けません．
""exampleX"" のように続けて書いた場合は，囲みになりません．

引用や箇条書きの中にも書けます．そのときも，
""> "" や字下げが「ソース」側に混ざることはありません．

この書き方はNextForm独自のもので，Markdownの標準ではありません．
Wiki記法の[[&&wikiexample:../../Wiki/Function/wikiexample]]に当たります．

*図
言語名を ""mermaid"" にしたコードブロックは，[[Mermaid:https://mermaid.js.org/]]の図になります．
流れ図・シーケンス図・クラス図・状態遷移図・ガントチャートなど，Mermaidの図の種類はどれも使えます．
GitHubやObsidianと同じ書き方なので，そちらで書いた図もそのまま表示されます．

 $bq$$bq$$bq$mermaid
 flowchart LR
     A[依頼] --> B[設計] --> C[実装]
     C -- 直し --> B
 $bq$$bq$$bq$

 $bq$$bq$$bq$mermaid
 sequenceDiagram
     participant A as 書く人
     participant B as サイト
     A->>B: 保存する
     B-->>A: 図を描いて表示する
 $bq$$bq$$bq$

流れ図とシーケンス図のラベルには，""$$"" で囲んで数式を書けます([[KaTeX:https://katex.org/]]の書き方)．

 $bq$$bq$$bq$mermaid
 flowchart LR
     A["$$x^2 + y^2 = r^2$$"] --> B["$$\frac{a}{b}$$"]
 $bq$$bq$$bq$

-図はブラウザの中で，NextFormに同梱したMermaidで描きます．外部のサーバーには何も送りません．
-書き方に誤りがあると，コードのまま表示され，その下に誤りの文が出ます．
-1つの図は50,000文字までです．
-図をダブルクリックすると，その図の原文を部分編集できます．編集画面の''プレビュー''でも図が描かれます．
-ラベルに書けるHTMLは，太字・斜体・下線・打ち消し・上付き・下付き・コード・改行(""<b>"" ""<i>"" ""<u>"" ""<s>"" ""<sup>"" ""<sub>"" ""<code>"" ""<br>"" など)だけです．それ以外のタグと属性(色や大きさを決める ""style""，リンク，画像，フォームなど)は消えます．図の色はMermaidの ""style"" や ""classDef"" の行で付けてください．
-図の中から関数を呼ぶ書き方(""click"" の ""call"" など)は効きません．
-JavaScriptが無効のときや，古いブラウザ(Safari 17.4より前など)では，コードのまま表示されます．
-Wiki記法のページでは図になりません．また，サイドページの図は，表示しているページの本文にも図があるときだけ描かれます．

**図でブラウザが固まるとき
とても大きな図や込み入った図があると，ページを開いたときにブラウザが固まることがあります．
そのときは，ページの名前に ""&action=edit"" を続けたURL(""?ページ名&action=edit"")を開いてください．
図を描かずにページ全体の編集画面が開くので，そこで図を直すか消します．
サイトの管理者は，サイト設定の''種別Markdownのページの図''を''コードのまま出す''にすると，
サイト全体で図を描くのを止められます([[MARKDOWN_DIAGRAM:../../Administration/Settings]])．
Mermaidに安全上の問題が見つかり，直したNextFormの版が出るのを待つあいだにも使えます．

*生のHTML
既定では，Markdownの中に書いたHTMLはHTMLとして解釈されず，そのまま文字として表示されます．
編集できる人が誰でもスクリプトを埋め込める状態を避けるためです．
サイトの設定([[MARKDOWN_ALLOW_HTML:../../Administration/Settings]])で解釈させることもできます．
また，""javascript:"" などの危険なURLへのリンクは，設定によらず作られません．
*/

/**
@manual $manualpage$/ja/Markdown/Link
&title Markdown記法のリンク・画像・添付

*ページへのリンク
&[&[ と &]&] で囲むと，このサイトの中のページへのリンクになります．

|書き方|意味|h
|""[[ページ名]]""|そのページへのリンク|
|&[&[ページ名&|表示名&]&]|表示名を変えたリンク|
|""[[../隣のページ]]""|相対指定([[相対ページ名:../..#相対ページ名]]と同じ解決)|
|""[[ページ名#見出し]]""|そのページの見出しへのリンク|

Wiki記法と違い，&[&[ &]&] の中は''対象が先，表示名が後''です．
ObsidianやMediaWikiと同じ並びに合わせてあります．

存在しないページへのリンクは，Wiki記法と同じく色を変えて示されます．
見出しの位置の決め方は種別をまたいで同じなので，
種別wikiのページの見出しにも ""[[ページ名#見出し]]"" で届きます．

同じページの中の見出しへは ""[表示名](#見出し)"" でも届きます．
見出しの文字をそのまま書くほか，GitHubの形(英字を小文字にし，空白を ""-"" にしたもの．
""[概要](#getting-started)"" など)でも見つけます．
空白を含む見出しの文字をそのまま書くときは ""[表示名](<#見出し 1>)"" のように囲みます．
どの見出しにも当たらない ""#"" はそのまま残るので，脚注などへのリンクは変わりません．

表の中でも ""[[ページ名|表示名]]"" はそのまま書けます．
間の ""|"" が表の区切りとして読まれることはありません
(Markdownの決まりどおり ""\|"" と書いてもかまいません)．

*外部リンク
""[表示名](URL)"" で外部サイトへのリンクになります．
URLをそのまま書いても[[リンクになります:../Extra#自動リンク]]．

同じURLに何度もリンクするときは，URLを本文から離して書く参照の形式も使えます．

 本文は[こちら][ref]を見てください．
 
 [ref]: https://example.com/

*画像と添付
""![説明](ファイル名)"" は，そのページに添付したファイルを指します．
添付はページの子ページとして保存されるので，
''添付''でアップロードしたファイル名をそのまま書けば埋め込めます．

行き先は，Webのリンクと同じく書いた文字だけで決まります．
ページをフォルダーと読み替えると，次のようになります．

|書き方|行き先|h
|""ファイル名"" または ""./ファイル名""|そのページの子(添付)|
|""../ページ名""|隣(兄弟)のページ|
|""/ページ名""|トップ階層からの名前|

名前だけを書いたときの行き先は，Wiki記法の &[&[ページ名&]&] (トップ階層から)と違います
([[Wiki記法とMarkdown記法の対応:../../Comparison]])．
Markdown記法の中に書いた &[&[ページ名&]&] は，Wiki記法と同じです．
まだ無いファイルを指した場合は，作りに行けるようリンクになります．

URLを書けば外部の画像もそのまま表示します．

添付した画像・音声・動画はページに埋め込みます．
画像の説明は，画像が出ないときや読み上げで使われる代替テキストになります．
それ以外のファイルは説明を表示名にしたリンクになり，押すとそのファイルを開きます．
説明を空にした ""![](ファイル名)"" では，ファイル名がリンクになります．

|ファイルの種類|""![説明](ファイル名)"" を押したとき|h
|PDF・テキスト|ブラウザの中で表示します(表示できないブラウザではダウンロードになります)|
|Markdown(.md)|wikiの画面の中に，Markdownのページと同じ見た目で表示します．読むだけで，編集はできません|
|その他(Word，Excelなど)|ダウンロードします|

Wiki記法の &&direct と同じく，ファイルそのものを開くリンクです．
画像・音声・動画は埋め込みになるので，文字のリンクで画像そのものを開く書き方はありません．

添付したMarkdown(.md)の中に書いた ""![図](図.png)"" や ""[資料](./資料.pdf)"" は，
その .md を添付したページの添付を指します．
.md と画像を同じページに添付すれば，そのまま表示できます．
UTF-8でない .md は表示できません(ダウンロードはできます)．

添付したHTMLファイルを動かす設定のサイトでは，""![表示名](ファイル名.html)"" は
押すとそのHTMLが動くリンクになります([[HTMLファイルの直接実行:../../HtmlFile]])．

""[表示名](ファイル名)"" と書くと，埋め込まずに添付のファイルのページへのリンクになります．
ファイルのページには，ファイルの情報と''ダウンロード''が出ます．
Markdown(.md)のファイルのページには，wikiの画面の中に表示する''開く''も出ます．
行き先の決め方は ""![説明](ファイル名)"" と同じです．
""[表示名](/ページ名)"" や ""[表示名](../隣のページ#見出し)"" のように，
ページへのリンクにも使えます．
まだ無いページへのリンクから作ると，書いた場所に作ります．
""[表示名](新しいページ)"" ならそのページの子に，""[表示名](/新しいページ)"" ならトップ階層に作ります．
""?"" ""#"" で始まるものと ""?"" を含むものは，URLとしてそのまま扱います．
このwikiの外を指すときは ""https://"" から書きます．

*大きさ・配置・キャプション
説明の後ろに ""|"" を付けて，大きさや配置を指定できます(Obsidianと同じ形)．
指定に使う語は，Wiki記法の[[&&include:../../Wiki/Function/include]]と同じです．
 ![説明|300](図.png)
 ![説明|50% right](図.png "キャプション")
:幅|""300"" のように数字だけを書くと幅になります．高さは比率を保ちます．
:幅x高さ|""640x400"" のように書くと，その大きさに収まるように縮めます．末尾に ""!"" を付けると比率を無視します．""640x"" や ""x400"" のように片方だけでも書けます．
:拡大率%|""50%"" のように，元の大きさに対する割合で指定します．
:max|""max 640x400"" のように大きさの前に付けると，それより大きいときだけ縮めます．
:left・right|左・右に寄せて，本文を回り込ませます．
:open|押すと新しいタブで開きます．
:!link|押してもリンクにしません．
:!adjust|縮小をサーバーではなくブラウザで行います．
語は空白かカンマで区切って並べられます．
''最後の ""|"" より後ろがすべて指定として読めるときだけ''指定になります．読めないときは全体が説明のままです．
外部の画像では，数字で書いた幅と高さだけが効きます(拡大率と ""max"" は効きません)．

画像をほかのページへのリンクにするときは，""!link"" を付けてリンクの中に書きます．
 [![|100x100 !link](小.png)](大.png)
押すと，囲んだリンクの行き先(この例では 大.png のファイルのページ)が開きます．
""!link"" を付けないと，画像そのものへのリンクと重なります．

ファイル名の後ろに引用符で囲んで書いた文字(Markdownのタイトルの欄．上の例の ""キャプション"")は，画像の下にキャプションとして出ます．
キャプションと ""left""・""right"" は，その画像が段落にそれ1つだけのときに効きます．文中の画像では効きません(外部の画像のタイトルは，これまでどおりマウスを載せたときのヒントになります)．

*ページの取り込み
""![説明](ページ名)"" が段落にそれ1つだけのとき，ふつうのページ(Markdown・wiki・text)は，その場所に中身を取り込みます(Wiki記法の&&include と同じ)．
-文の途中に書いたときは，取り込まずにリンクになります．
-読む権限の無いページと，まだ無いページはリンクのままです．
-ページどうしが互いに取り込み合っているときは，2度目からはリンクになります．
-取り込んだ中身は，このページの検索には載りません(取り込まれたページのほうで見つかります)．
-キャプションと ""left""・""right"" も使えます．
*/

/**
@manual $manualpage$/ja/Markdown/FrontMatter
&title フロントマター

文書の先頭を ""---"" の行で囲んだ部分はメタ情報(フロントマター)として扱われ，
本文には表示されません．
ObsidianやNotionから持ってきた文章に付いていても，そのまま貼り付けられます．

 ---
 title: 会議メモ
 tags: [議事録, 打合せ]
 ---

NextFormが読むのは ""title:"" と ""tags:"" です．
他の項目が書いてあっても，そのままソースに残るだけで害はありません．

*題名
""title:"" を書くと，それがそのページの題名になります．
Wiki記法の &&title{} と同じで，ページ名とは別に表示される名前です．

""title:"" が無いときは，''本文の先頭の # 見出し''が題名になります．
ほかの見出しが ## 以下で，''# がその1つだけ''のときに限ります．
よそで書いた文章を貼り付けると，たいていこの形になっています．

 # 会議メモ        ← 題名になる
 ## 議題
 ## 決まったこと

# が2つ以上ある文書では，どれも並列の節の見出しとみなし，題名にはしません
(ページ名がそのまま出ます)．
題名にした # 見出しはページの上の見出しに出るので，''本文からは消えます''
(二重に出さないため．目次にも出ません)．

*タグ
""tags:"" を書くと，それがそのページのタグになります．
''タグ''の画面で付けるものと同じもので，タグ一覧にも出ます．
書き方は次のどれでもかまいません．

 tags: [議事録, 打合せ]
 tags: 議事録, 打合せ
 tags: 議事録 打合せ
 tags:
   - 議事録
   - 打合せ

タグは半角スペースで区切って保存されるので，''タグ自体に空白は入れられません''．
「議事録 2026」と書くと2個のタグになります．

*書いていないものは消えます
題名とタグは，''ソースに書いてあるとおり''になります．
""title:"" (と，その代わりになる先頭の # 見出し) を消して保存すれば題名も消え，
""tags:"" を消して保存すればタグも消えます．
''メタ情報''や''タグ''の画面で付けた値も，次に本文を保存したときに置き換わります．
ソースを見ればページの状態が分かるようにするためです．

Wiki記法の [[&&title{}:../../Wiki/Function/title]] も同じ約束です．
*/

*Overview
Pages of type Markdown are written in [[Markdown:https://commonmark.org/]].
NextForm follows [[CommonMark:https://spec.commonmark.org/]] and also supports
extensions such as tables and strikethrough
([[GitHub Flavored Markdown:https://github.github.com/gfm/]]) and footnotes.
Unless you choose otherwise when creating a page, the type will be Markdown.

Text written in another tool (Obsidian or Notion, for example) can be pasted in
as it is and will look much the same.

(In a hurry? Go [[here:./CheatSheet]])

*Guides to writing
-[[Markdown Cheat Sheet>./CheatSheet]]
-[[Basic elements>./Basic]] (headings, emphasis, lists, quotes, code and so on)
-[[Extra elements>./Extra]] (tables, checkboxes, footnotes, folding and so on)
-[[Links, images and attachments>./Link]] (links to pages and embedding files)
-[[Front matter>./FrontMatter]] (the metadata at the top; title and tags)

When to use which notation, and how the same things are written in Wiki notation, are collected in
[[Wiki notation and Markdown notation:../Comparison]].
Wiki [[functions:../Wiki/Function]] cannot be used in pages of type Markdown.

*How to edit
How to edit just a part of the page by double clicking, and how to edit the whole page, are in [[Page operations:../PageMenu#Edit]].
On a page in Markdown notation, the units you can edit at once are paragraphs, headings, list items, tables, code blocks,
quotes and folds.
Double clicking a heading edits ''the whole section'' (up to the next heading of the
same or a shallower level).

Unlike Wiki notation, you cannot edit a part of a line (emphasis or strikethrough on
its own) or a single row of a table. A table is one unit as a whole.

/**
@manual $manualpage$/en/Markdown/Basic
&title Basic elements of Markdown notation

These are the ways of writing that belong to the base of Markdown
([[CommonMark:https://spec.commonmark.org/]]).
Extensions such as tables and footnotes are in [[Extra elements:../Extra]], and
links to pages and images are in [[Links, images and attachments:../Link]].

*Paragraphs and line breaks
An empty line separates paragraphs.
A line break inside a paragraph does not appear in the output
(it is treated as a separator between words).
To break the line without starting a new paragraph, put ''two spaces'' at the end of
the line, or write a single ''backslash''.

*Headings
Write ""#"" and a space at the start of the line.
The number of ""#"" (from one to six) is the depth of the heading.
Usually ""#"" becomes the page title (it disappears from the text and is shown as the heading at the top of the page), so headings in the text start from ""##"".
""##"" is the same size as ""*"" of Wiki notation.
When a ""#"" stays in the text instead of becoming the title (when the front matter has ""title:"", when there are two or more ""#"", and so on), it is shown one step larger than ""##"".

 # the title (the only one at the top of the text becomes the page title)
 ## a heading (the same size as * of Wiki notation)
 ### a heading below it

There is another way to write them: a line of ""==="" ''below'' the text makes a first
level heading, and a line of ""---"" makes a second level heading.
Take care not to write ""---"" on the line right below a sentence by accident:
it turns that sentence into a heading instead of drawing a horizontal rule.

Unlike sections in Wiki notation, headings in Markdown notation cannot be folded and
do not span a range. To fold part of the text, wrap it in a
[[folding block:../Extra#Folding]].

*Emphasis
|notation|result|h
|""**strong**""|bold|
|""*emphasis*""|italic|
|""***strong and emphasized***""|bold italic|

Underscores work the same as asterisks (""__strong__"", ""_emphasis_"").

*Code in a sentence
Surround text with ""$bq$"" to make code inside a sentence (a fixed width font).
To put a ""$bq$"" itself inside the code, surround it with ""$bq$$bq$"".

*Lists
Write ""- "" at the start of the line.
Indenting an item by two spaces nests it.

 - item
 - item
   - nested item

Starting with a number and ""."" makes a numbered list.
The first number is the number the list starts from, and the rest are renumbered
when the page is shown.

 1. numbered item
 2. numbered item

To put several paragraphs or a code block into one item, leave an empty line and
continue at the indent of the item.

An empty line between items does ''not'' split the list.
What is above and below it stays one list ([[CommonMark:https://spec.commonmark.org/]]
defines it this way). To split it in two, change the marker of one of them.

 - a list with hyphens
 * a list with asterisks

The look follows what you wrote. Only where you put an empty line is there a gap,
as wide as when a list is split in Wiki notation; items with no empty line between
them stay close together.

*Quotes
Write ""> "" at the start of the line.
Repeating it as ""> > "" makes a quote inside a quote.

 > It was the best of times,
 > it was the worst of times.

*Code blocks
Lines of ""$bq$$bq$$bq$"" around the text show it exactly as written, line breaks and all.
A language name can follow the opening line (""$bq$$bq$$bq$php"", for example).
The language name only records what the source is; as the
[[comparison table:../../Comparison]] notes, it is not coloured.

 $bq$$bq$$bq$
 int func(int a) {
     return a * 2;
 }
 $bq$$bq$$bq$

Lines of ""~~~"" work the same way (useful when the text itself contains ""$bq$$bq$$bq$"").
Indenting the lines by four spaces also makes a code block, with no fence.

*Horizontal rules
A line consisting only of ""---"", ""***"" or ""___"" becomes a horizontal rule.
Written right after a sentence it is read as [[the underline of a heading:.#Headings]],
so leave an empty line before it.
A ""---"" at the very ''top'' of the document starts the
[[front matter:../FrontMatter]] instead.

*Escaping
To show a symbol as itself rather than as notation,
write a backslash before the symbol.

 \*asterisks, not emphasis\*

*Character references
An HTML character reference such as &&copy; written in the source becomes that
character (© in this example).
*/

/**
@manual $manualpage$/en/Markdown/Extra
&title Extra elements of Markdown notation

On top of the base of [[CommonMark:https://commonmark.org/]] you can use the extensions
of [[GitHub Flavored Markdown:https://github.github.com/gfm/]]
(tables, strikethrough, checkboxes and automatic links) and footnotes.
Ways of writing that work on GitHub or in Obsidian mostly work here too.
Only the folding notation is specific to NextForm.

*Tables
Separate the cells with ""|"" and write one row of the table per line.
The first row is the header, and the second must be a separator row of ""---"".

 | item | price |
 | --- | --- |
 | apple | 1.20 |
 | orange | 0.80 |

Adding a colon to the separator row sets how each column is aligned.

 | left | center | right |
 | :--- | :---: | ---: |

Notation such as emphasis and code in a sentence can be used inside cells.
Unlike tables in Wiki notation, cells cannot be merged.
The columns are not lined up when the page is saved either
(the source stays exactly as you wrote it).

*Strikethrough
Surrounding text with ""~~"" strikes it out.

 ~~that was wrong~~

*Checkboxes
Starting a list item with ""[ ]"" or ""[x]"" makes a checkbox.

 - [ ] item still to do
 - [x] item that is done

The checkbox that is shown is only there to be read; it cannot be ticked from the
screen. Edit the source to change it.

*Footnotes
Write a mark such as ""[^1]"" in the text and ""[^1]: the note"" on a line of its own.
Footnotes are shown together at the foot of the page, with links back and forth.

 Once upon a time[^1] there was.
 
 [^1]: The exact date is not known.

The mark does not have to be a number (""[^note]"" works too).
What is shown is a running number.

*Automatic links
A URL written as it is becomes a link. So does a word starting with ""www."".
You can also surround a URL with ""<"" and "">"".

*Folding
A line of three colons followed by ""details"", down to a line of three colons on
its own, becomes a folded block. What you write after ""details"" is the heading
shown while it is folded.

 :::details The detailed steps
 The contents are ordinary Markdown. Headings and tables work too.
 :::

It is shown folded by default. To have it open from the start, put ""+"" right
after ""details"", or write ""open"". The two mean the same thing.

 :::details+ open from the start
 contents
 :::

 :::details open open from the start
 contents
 :::

Use the ""+"" form when the heading itself has to start with the word ""open"".

 :::details+ open questions
 contents
 :::

To nest them, add colons to the outer one. The closing colons must be at least as
many as the opening ones. If you forget to close it, it is closed at the end of
the page.

 ::::details outer
 :::details inner
 contents
 :::
 ::::

Notation does not apply inside the heading; it is shown as plain characters.
A word other than ""details"" (""note"", for instance) does not fold anything.

A folded block with a heading appears in the table of contents like an ordinary heading, and &[&[page name#heading&]&] jumps to it (the same as &*(optional) of Wiki notation).
Its depth in the table of contents can be set by writing ""#"" at the start of the heading (the ""#"" is not shown).
Without it, the depth is one below the heading before it.
When ""#"" is written, the label (the line you press to open it) is also shown in the size of a heading of that depth. Without it, the label is bold text of the normal size.

 :::details ### listed in the table of contents as a third-level heading
 contents
 :::

This notation is specific to NextForm and is not part of standard Markdown.
Pasted into another tool, the colon lines show up as text (the contents remain).
The browser's own find-in-page cannot find contents that are folded away
(the site search does index them). Printing keeps them folded as well.

*Table of contents
A line with only ""[TOC]"" (with blank lines around it) becomes the table of contents of the headings of the page (the same as &&index of Wiki notation).
It has the same form as ''Table of contents'' in ''Tools'', and pressing an item jumps to that heading.

 [TOC]
 
 ## Introduction

-It can be written in lower case, ""[toc]"".
-""[TOC]"" inside code or in the middle of a sentence stays as text.
-It becomes a table of contents on the side page and where the page is pulled in, too.
-The text ""[TOC]"" is not indexed by the site search.
-It is written the same way as in GitLab, Typora and Python-Markdown (MkDocs). Tools that do not support it just show the text ""[TOC]"".

*Tree of subpages
A line with only ""[PAGES]"" (with blank lines around it) becomes a nested list of the subpages of the page, including grandchildren (the same as &&treepages of Wiki notation, which is &&pages with show=tree; see [[&&pages:../../Wiki/Function/pages]]).
After ""PAGES"", the following can be listed, separated by spaces.

 [PAGES]
 [PAGES ./photos]
 [PAGES sort=mtime reverse 10]

:page name|Lists the subpages of that page. It is written as in a link: a bare name and ""./"" are children of this page, ""../"" is next to it, and ""/name"" is from the top. ""/"" alone is the whole site. Write a space as ""%20"".
:sort=mtime|Sorts by the modification time. ""sort=btime"" sorts by the creation time and ""sort=size"" by the size.
:reverse|Reverses the order.
:children|Only the direct subpages (no grandchildren).
:a number|Shows only that many.
:withsystem|Also shows pages such as the manual.
-When there is something it cannot read, the text ""[PAGES …]"" is shown as it is.
-When there are no subpages, nothing is shown.
-The text ""[PAGES …]"" is not indexed by the site search.
-This notation is specific to NextForm. Other tools just show the text ""[PAGES]"".

*Notation examples
A line of three colons followed by ""example"", down to a line of three colons
alone, becomes a pair of ''Source'' and ''Display''. It saves writing the same
text twice when you explain a notation.

 :::example
 - item
 - item
 :::

''Source'' shows the characters exactly as written, ''Display'' shows the result of
converting them. The contents are ordinary Markdown; tables and code blocks work.
Three colons inside a code block do not close it.

To nest them, add colons to the outer one. The closing colons must be at least as
many as the opening ones. If you forget to close it, it is closed at the end of
the page.

 ::::example
 :::example
 contents
 :::
 ::::

Unlike folding, nothing can be written after ""example"".
Written as ""exampleX"", it is not treated as a block at all.

It also works inside a quote or a list. The ""> "" and the indent do not leak
into the ''Source'' side.

This notation is specific to NextForm and is not part of standard Markdown.
It corresponds to [[&&wikiexample:../../Wiki/Function/wikiexample]] in Wiki notation.

*Diagrams
A code block whose language name is ""mermaid"" becomes a [[Mermaid:https://mermaid.js.org/]] diagram.
Every kind of Mermaid diagram works, such as flowcharts, sequence diagrams, class diagrams,
state diagrams and Gantt charts. It is the same notation as on GitHub and in Obsidian,
so diagrams written there are shown as they are.

 $bq$$bq$$bq$mermaid
 flowchart LR
     A[Request] --> B[Design] --> C[Build]
     C -- fix --> B
 $bq$$bq$$bq$

 $bq$$bq$$bq$mermaid
 sequenceDiagram
     participant A as Writer
     participant B as Site
     A->>B: save
     B-->>A: show the drawn diagram
 $bq$$bq$$bq$

In the labels of flowcharts and sequence diagrams, math can be written between ""$$""
(in the notation of [[KaTeX:https://katex.org/]]).

 $bq$$bq$$bq$mermaid
 flowchart LR
     A["$$x^2 + y^2 = r^2$$"] --> B["$$\frac{a}{b}$$"]
 $bq$$bq$$bq$

-Diagrams are drawn in the browser by the copy of Mermaid bundled with NextForm. Nothing is sent to an outside server.
-If the notation has an error, the code is shown as it is, with the error below it.
-A diagram can be up to 50,000 characters.
-Double-click a diagram to edit its source as a partial edit. ''Preview'' on the edit screen also draws diagrams.
-The only HTML allowed in labels is bold, italic, underline, strikethrough, superscript, subscript, code and line breaks (""<b>"" ""<i>"" ""<u>"" ""<s>"" ""<sup>"" ""<sub>"" ""<code>"" ""<br>"" and so on). Other tags and attributes (""style"" for colors and sizes, links, images, forms and so on) are removed. Color a diagram with Mermaid's own ""style"" and ""classDef"" lines.
-Calling a function from a diagram (such as ""call"" in ""click"") does not work.
-With JavaScript turned off, or in an old browser (such as Safari before 17.4), the code is shown as it is.
-Pages in Wiki notation do not draw diagrams. A diagram in the side page is drawn only when the text of the page being shown also has a diagram.

**When a diagram freezes the browser
A very large or complicated diagram can freeze the browser when the page opens.
In that case, open the URL with ""&action=edit"" after the page name (""?page name&action=edit"").
The screen for editing the whole page opens without drawing diagrams, so fix or remove the diagram there.
The site administrator can stop drawing diagrams on the whole site by setting
''Diagrams in Markdown pages'' in the site settings to ''Show as code''
([[MARKDOWN_DIAGRAM:../../Administration/Settings]]).
This also helps while waiting for a NextForm release that fixes a security problem found in Mermaid.

*Raw HTML
By default, HTML written inside Markdown is not interpreted as HTML and is shown as
plain characters. This avoids a state in which anyone who can edit can embed a script.
It can be interpreted through the site setting
([[MARKDOWN_ALLOW_HTML:../../Administration/Settings]]).
Links to dangerous URLs such as ""javascript:"" are never created, whatever the setting.
*/

@manual $manualpage$/en/Markdown/Link
&title Links, images and attachments in Markdown notation

*Links to pages
Surrounding a name with &[&[ and &]&] makes a link to a page inside this site.

|notation|meaning|h
|""[[page name]]""|a link to that page|
|&[&[page name&|display name&]&]|a link with a different display name|
|""[[../the next page]]""|a relative name (resolved as [[relative page names:../..#Relative page names]] are)|
|""[[page name#heading]]""|a link to a heading in that page|

Unlike Wiki notation, what comes first inside &[&[ &]&] is ''the target, and the display name comes second''. This matches the order used by Obsidian and MediaWiki.

A link to a page that does not exist is shown in a different colour,
just as in Wiki notation.
Positions of headings are decided the same way whatever the type of the page, so
""[[page name#heading]]"" reaches headings in pages of type wiki as well.

A heading in the same page can also be reached with ""[display name](#heading)"".
Besides the text of the heading as it is, the GitHub form (letters in lower case and
spaces turned into ""-"", as in ""[Overview](#getting-started)"") is found as well.
To write the text of a heading that contains spaces as it is, enclose it as in
""[display name](<#heading 1>)"".
A ""#"" that matches no heading is left as it is, so links to footnotes and the like
do not change.

""[[page name|display name]]"" can be written as it is inside a table as well.
The ""|"" in it is not read as a cell separator
(writing ""\|"", as Markdown requires, also works).

*External links
""[display name](URL)"" makes a link to an external site.
A URL written as it is [[also becomes a link:../Extra#Automatic links]].

When you link to the same URL many times, you can also write the URL away from the
text, in the reference form.

 See [here][ref] for details.
 
 [ref]: https://example.com/

*Images and attachments
""![description](file name)"" points at a file attached to the current page.
Attachments are saved as child pages, so writing the name of a file uploaded through
''Attach'' embeds it.

As with links on the web, where it points is decided only by what is written.
Reading a page as a folder, it works as follows.

|notation|where it points|h
|""file name"" or ""./file name""|a child (attachment) of the current page|
|""../page name""|the next (sibling) page|
|""/page name""|a name from the top|

Where a bare name points differs from &[&[page name&]&] in Wiki notation, which is
a name from the top ([[Wiki notation and Markdown notation:../../Comparison]]).
&[&[page name&]&] written in Markdown notation is the same as in Wiki notation.
Pointing at a file that does not exist yet makes a link, so that it can be created.

Writing a URL shows an external image as it is.

Attached images, audio and video are embedded in the page.
The description of an image becomes its alternative text, used when the image does
not show and by screen readers.
Any other file becomes a link with the description as its text, and pressing it opens
the file. With an empty description, as in ""![](file name)"", the file name is the link.

|Type of file|What pressing ""![description](file name)"" does|h
|PDF, text|Shows it in the browser (browsers that cannot show it download it)|
|Markdown (.md)|Shows it inside the wiki screen, looking like a Markdown page. It can be read, not edited|
|Others (Word, Excel and so on)|Downloads it|

Like &&direct of Wiki notation, it is a link that opens the file itself.
Images, audio and video are embedded, so there is no way to write a text link that opens the image itself.

In an attached Markdown file (.md), ""![figure](figure.png)"" and ""[document](./document.pdf)""
point at the attachments of the page the .md is attached to.
Attach the .md and its images to the same page and they show as they are.
A .md that is not UTF-8 cannot be shown (it can still be downloaded).

On a site set up to run attached HTML files, ""![display name](file name.html)"" becomes
a link that runs the HTML when pressed ([[Running HTML files directly:../../HtmlFile]]).

Writing ""[display name](file name)"" makes a link to the page of the attached file
instead of embedding it. The page of a file shows its details and ''Download''.
The page of a Markdown file (.md) also shows ''Open'', which shows it inside the wiki screen.
Where it points is decided in the same way as for ""![description](file name)"".
It also links to pages, as in ""[display name](/page name)"" or
""[display name](../the next page#heading)"".
A page created from a link to a page that does not exist yet is created where the link
points: ""[display name](new page)"" creates it as a child of the current page, and
""[display name](/new page)"" creates it at the top.
Anything that starts with ""?"" or ""#"", or that contains ""?"", is treated
as a URL as it is.
To point outside this wiki, write the URL from ""https://"".

*Size, placement and caption
Write ""|"" after the description to give the size or the placement (the same form as Obsidian).
The words are the same as [[&&include:../../Wiki/Function/include]] of Wiki notation.
 ![description|300](figure.png)
 ![description|50% right](figure.png "caption")
:width|A number alone, such as ""300"", is the width. The height keeps the ratio.
:widthxheight|""640x400"" shrinks it to fit that size. A trailing ""!"" ignores the ratio. Only one side, such as ""640x"" or ""x400"", can be given too.
:percent%|""50%"" gives the size as a ratio of the original.
:max|Put before a size, as in ""max 640x400"", to shrink only when it is larger.
:left, right|Places it to the left or right, with the text flowing around it.
:open|Opens it in a new tab when pressed.
:!link|Does not make it a link.
:!adjust|Shrinks it in the browser instead of on the server.
Words are separated by spaces or commas.
''Only when everything after the last ""|"" can be read as words of this list'' does it become a specification. Otherwise the whole stays the description.
For an external image, only a width and height written as numbers take effect (not the percentage or ""max"").

To make an image a link to another page, add ""!link"" and write it inside the link.
 [![|100x100 !link](small.png)](large.png)
Pressing it opens where the surrounding link points (the page of the file large.png in this example).
Without ""!link"", it overlaps with the link to the image itself.

Text written in quotes after the file name (the title part of Markdown; ""caption"" in the example above) is shown under the image as its caption.
The caption and ""left"" / ""right"" take effect only when the image is the only thing in its paragraph. They do not for an image in the middle of a sentence (the title of an external image is shown as a hint when the mouse is over it, as before).

*Pulling in a page
When ""![description](page name)"" is the only thing in its paragraph, an ordinary page (Markdown, wiki or text) is pulled in at that place (the same as &&include of Wiki notation).
-When it is written in the middle of a sentence, it is a link instead.
-A page that cannot be read and a page that does not exist yet stay links.
-When pages pull each other in, the second time becomes a link.
-The contents pulled in are not searched as part of this page (they are found in the page pulled in).
-A caption and ""left"" / ""right"" can be used too.
*/

@manual $manualpage$/en/Markdown/FrontMatter
&title Front matter

A part at the very top of the document surrounded by lines of ""---"" is treated as
metadata (the front matter) and is not shown in the text.
Text brought over from Obsidian or Notion can be pasted in with it still attached.

 ---
 title: Meeting notes
 tags: [minutes, meeting]
 ---

What NextForm reads is ""title:"" and ""tags:"".
Other entries do no harm; they simply stay in the source.

*Title
Writing ""title:"" makes it the title of the page.
It works like &&title{} in Wiki notation: a name shown separately from the page name.

Without ""title:"", ''the # heading at the top of the text'' becomes the title,
as long as ''it is the only #'' and the other headings are ## or deeper.
Text written in another tool usually has this shape.

 # Meeting notes   <- becomes the title
 ## Agenda
 ## Decisions

In a text with two or more # headings they are all taken as sections side by side,
and none of them becomes the title (the page name is shown as it is).
The # heading used as the title is shown in the heading at the top of the page, so
''it is removed from the text'' (so that it does not appear twice; it is not in the
table of contents either).

*Tags
Writing ""tags:"" makes them the tags of the page.
They are the same tags you set from the ''Tag'' screen, and they appear in the tag list.
Any of the following ways of writing them will do.

 tags: [minutes, meeting]
 tags: minutes, meeting
 tags: minutes meeting
 tags:
   - minutes
   - meeting

Tags are saved separated by spaces, so ''a tag cannot contain a space''.
Writing "minutes 2026" gives two tags.

*What is not written is removed
The title and the tags become ''exactly what the source says''.
Remove ""title:"" (and the # heading at the top that stands in for it) and save,
and the title is removed too;
remove ""tags:"" and save, and the tags are removed.
Values set from the ''Meta information'' or ''Tag'' screens are replaced the next time
the text is saved.
This is so that the state of a page can be seen from its source.

The same promise applies to
[[&&title{}:../../Wiki/Function/title]] in Wiki notation.
*/

&[&[ &]&] の中の並びは''逆''です．
Wiki記法は表示名が先，Markdown記法は対象が先になります．

*意味は同じだが働きが違うもの

|目次|&&index|""[TOC]"" とだけ書いた行|Markdown記法では，ほかのページの目次(&&index(&[&[ページ名&]&]))は書けません|

|他のページの取り込み|&&include(&[&[ページ名&]&])|段落にそれ1つだけの !&[説明&](ページ名)|Markdown記法では，文の途中に書いたときはリンクになります．大きさや配置の指定は説明の後ろに書きます([[リンク・画像・添付:../Markdown/Link#大きさ・配置・キャプション]])|
|ファイルそのものを開くリンク|&&direct(&[&[./資料.pdf&]&]){説明}|!&[説明&](./資料.pdf)|PDF・テキスト・Wordなどは同じ働きです．Markdown(.md)は，表示した画面が開きます．画像・音声・動画は埋め込みになるので，文字のリンクにするときは &[説明&](./写真.png) と書きます(押すとファイルのページが開きます)|
|部分編集の単位|文中の一部・表の行まで細かく取れます|段落・見出し(節)・箇条書きの項目・表・コードブロック・引用|どちらもダブルクリックで編集できます．Markdown記法では文中の一部分や表の1行だけは取り出せません|

|関連リスト(定義リスト)|&:項目&|説明|なし|Markdown記法では箇条書きか表で代用します|

|表のセル結合|&< &> &^ &_|なし|Markdown記法にセル結合はありません|
|表の桁揃え|保存時に自動でそろえる|そろえない|Markdown記法の原文は書いたとおりに残します(Wiki記法から変換した表は，そろえて書き出します)|
|コードのハイライト|行頭スペースのあとに (code)|""$bq$$bq$$bq$php""|Wiki記法は色分けまで行われます．Markdown記法は言語名が記録されるだけで，色分けはされません|
|チェックボックス|なし|""- [ ] 項目""|Markdown記法だけの機能です|
|脚注|なし|""本文[^1]"" と ""[^1]: 中身""|同上|

見出しへのリンク &[&[ページ名#見出し&]&] は，種別をまたいで同じ場所に届きます．

*Markdown記法では書けないもの
種別Markdownのページでは，Wiki記法のファンクションは使えません．
次のようなことをしたいページは，種別wikiで作ってください．

|やりたいこと|Wiki記法|h
|ページの一覧(表・中身ごと・テンプレート)|&&pages &&subpage|
|カレンダー|&&calendar &&datepages|
|数値計算・表計算|行頭の &= と セルの &=|
|検索結果の埋め込み|&&search|
|新着・更新の一覧|&&feed &&mtime|
|文字の色や大きさ|&&color &&size|
|配置の指定|&&align|
|抜粋の区切り|&&more|
|CSV形式の表|行頭の &,|

これらが1つでも要るページは，Wiki記法のまま置いてください．

*Wiki記法のページをMarkdownに変換する
種別wikiのページは，''ページメニュー''の''Markdownに変換''で，種別Markdownのページに変換できます．
確認の画面に，変換後の本文と，次のものが出ます．''変換する''を押すと保存します．
-落ちるもの(関連リスト・表のセル結合・文字の色など)
-原文のままコードの枠で残すもの(カレンダー・計算・書き込みのフォームなど，Markdown記法に無い働きをするファンクション)
-飛び先が変わる見出し(ほかのページからの &[&[ページ名#見出し&]&] が届かなくなるもの)

変換の決まりは次のとおりです．
-見出しは1段下げます．&&title は本文の先頭の ""#"" に，&* は ""##"" に，&*&* は ""###"" にします(6段まで)．
-タグはフロントマターの ""tags:"" に書き出します．
-&*(optional) の節は "":::details"" の折りたたみにします(見出しの深さは保ちます)．
-&&include は ""![](..)"" に，&&index は ""[TOC]"" に，&&treepages などのページの一覧は ""[PAGES]"" にします．
-&&direct(&[&[./資料.pdf&]&]){説明} は ""![説明](./資料.pdf)"" にします．押すとファイルそのものが開くのは同じです(Markdown(.md)は表示した画面が開きます)．
画像・音声・動画とページへの &&direct は，見た目を変えないよう ""[説明](./写真.png)"" にします．押すとファイルのページが開くようになるので，落ちるものに出ます．
-縮小画像を押すと元の画像が開く &&direct(&[&[./写真.png&]&]){&&include(&[&[./写真.png&]&],100x100);} は ""![|100x100](./写真.png)"" にします．
縮小画像が別の画像のときは ""[![|!link](./小.png)](./写真.png)"" にします．押すと写真.png のファイルのページが開きます．
""&link(https://example.com/){&include([[./バナー.png]]);}"" のように外部のサイトへのリンクにした縮小画像も，""[![|!link](./バナー.png)](https://example.com/)"" にします．
-&&color や &&size などの装飾は，中の文字だけを残します．
-表は1行目を見出しの行にします(Markdown記法の表には見出しの行が要るため)．見出しの行(行末の h)の無かった表は，1行目の見え方が変わるので落ちるものに出ます．表の桁はそろえて書き出します．
-&[&[表示名:ページ名&]&] は &[&[ページ名&|表示名&]&] に並べ替えます．行き先の決まりは同じなので，行き先は書き換えません．

変換前の版は履歴に残り，本文の末尾に「このページは、wikiページから変換して作りました。(変換前の版)」とその版へのリンクが付きます．
元に戻すには，その版を開いて''この版に戻す''を押します．
-変換するのはそのページだけです．子ページは変換しません．
-ページの名前を変えると，変換前の版は元の名前の履歴に残ります(履歴は新しい名前に付いていきません)．末尾のリンクで変換前の版は開けますが，''この版に戻す''は出ません．戻すときは，先に元の名前に[[リネーム:../PageMenu#リネーム]]してください．
-ほかのページがこのページのWiki記法に頼っているときは，その見え方が変わります．
たとえば，親のページの &&tracker などの一覧は子ページの原文から項目を読み，&&blogpages などの抜粋は &&more を区切りにしています．
-ページ名の自動リンク(サイトの設定で有効にしたもの)は，Markdown記法では掛かりません．
*/

@manual $manualpage$/en/Comparison
&title Wiki notation and Markdown notation

Pages of type wiki and pages of type Markdown are both first-class ways of writing.
You can use Wiki notation for "living pages" that use functions, and Markdown notation
for documents meant to be read.
This page puts the two side by side, showing how the same thing is written in each.

Each notation is described in [[Markdown notation:../Markdown]] and
[[About Wiki notation:../Wiki]].

*Things that carry over directly
|what you want|Wiki notation|Markdown notation|h
|paragraph|insert an empty line|insert an empty line|
|strong|&'&'strong&'&'|""**strong**""|
|emphasis|&'&'&'emphasis&'&'&'|""*emphasis*""|
|strikeout|&%&%strikeout&%&%|""~~strikeout~~""|
|list (unordered)|&- item|""- item""|
|list (ordered)|&+ item|""1. item""|
|quote|&>quoted text|""> quoted text""|
|preformatted text|a space at the start of the line|surround with ""$bq$$bq$$bq$""|
|horizontal rule|&=&=&=&=|""---""|
|link to a page|&[&[display name:page name&]&]|&[&[page name&|display name&]&]|
|external link|&[&[display name:URL&]&]|""[display name](URL)""|
|page title|&&title{title}|""title:"" in the front matter; otherwise the only ""#"" heading at the top of the text|
|table (basic)|&|cell1&|cell2&||&|cell1&|cell2&||
|notation example (source and display side by side)|&&wikiexample{target}|wrap it in "":::example"" and "":::""|

The order inside &[&[ &]&] is ''the other way round''.
Wiki notation puts the display name first, Markdown notation puts the target first.

*Things that mean the same but work differently
|what you want|Wiki notation|Markdown notation|difference|h
|heading|&* heading|""## heading"" (""#"" is used for the title)|A section in Wiki notation ''spans a range'', up to the next section. A heading in Markdown notation spans no range|
|folding|&*(optional)|wrap it in "":::details heading""|Wiki notation folds a ''section'' (it is put on the heading, so the range runs to the end of the section). Markdown notation folds ''the range you wrapped''. In both, the heading appears in the table of contents|
|table of contents|&&index|a line with only ""[TOC]""|Markdown notation cannot write the table of contents of another page (&&index(&[&[page name&]&]))|
|tree of subpages|&&treepages|a line with only ""[PAGES]""|Markdown notation can give the page, the order, the number and only the direct subpages (children). Lists as tables or with contents cannot be written|
|marking the end of a section|&*(end)|none|as above|
|pulling in another page|&&include(&[&[page name&]&])|!&[description&](page name) alone in its paragraph|In Markdown notation, it is a link when written in the middle of a sentence. The size and placement are written after the description ([[Links, images and attachments:../Markdown/Link#Size, placement and caption]])|
|a link that opens the file itself|&&direct(&[&[./document.pdf&]&]){description}|!&[description&](./document.pdf)|PDF, text, Word and so on work the same. A Markdown file (.md) opens the screen that shows it. Images, audio and video are embedded, so for a text link write &[description&](./photo.png) (pressing it opens the page of the file)|
|unit of partial editing|down to a part of a line or a table row|paragraph, heading (section), list item, table, code block, quote|Both are edited by double clicking. Markdown notation cannot take a part of a line or a single table row|
|empty line inside a list|the list ''ends'' there|it does not end; it stays one list|In Wiki notation an empty line is how you split a list in two. In Markdown notation you change the marker of one of them (""- "" and ""* ""). In both notations only the place with the empty line gets a gap, of the same width|
|description list|&:item&|description|none|In Markdown notation use a list or a table instead|
|table formatting|h f c l r n and so on at the end of the row|column alignment in the separator row|All you can set in Markdown notation is the column alignment|
|header row of a table|h at the end of the row (may be left out)|the first row is always the header row (the second row must be a separator row)|Markdown notation cannot write a table without a header row|
|merging table cells|&< &> &^ &_|none|Markdown notation cannot merge cells|
|lining up table columns|done automatically when saved|not done|The source in Markdown notation stays exactly as written (tables converted from Wiki notation are written out lined up)|
|highlighting code|(code) after the leading space|""$bq$$bq$$bq$php""|Wiki notation colours the code. Markdown notation only records the language name; it is not coloured|
|checkbox|none|""- [ ] item""|Only Markdown notation has this|
|footnote|none|""text[^1]"" and ""[^1]: the note""|as above|
|where a link with a bare name points|&[&[page name&]&] is a name from the top|""[display name](page name)"" is a child (attachment) of the current page|Markdown notation reads a page as a folder, as links on the web do. From the top, write ""[display name](/page name)"". &[&[page name&]&] written in Markdown notation is the same as in Wiki notation|

A link to a heading, &[&[page name#heading&]&], reaches the same place
whatever the type of the page.

*Things Markdown notation cannot write
Functions of Wiki notation cannot be used in pages of type Markdown.
Create a page of type wiki when you want to do any of the following.

|what you want|Wiki notation|h
|lists of pages (as tables, with contents, with templates)|&&pages &&subpage|
|calendars|&&calendar &&datepages|
|calculation and spreadsheets|&= at the start of a line and &= in a cell|
|embedding search results|&&search|
|lists of new and updated pages|&&feed &&mtime|
|colour and size of text|&&color &&size|
|alignment|&&align|
|marking where the excerpt ends|&&more|
|tables in CSV form|&, at the start of a line|

Keep a page in Wiki notation if it needs even one of these.

*Converting a page in Wiki notation to Markdown
A page of type wiki can be converted to a page of type Markdown with ''Convert to Markdown'' in the ''page menu''.
The confirmation screen shows the text after conversion and the following. Press ''Convert'' to save it.
-Things that are dropped (definition lists, cell merges in tables, colours of text and so on)
-Functions kept as their source in code blocks (calendars, calculations, input forms and other functions whose work Markdown notation does not have)
-Headings whose links change (&[&[page name#heading&]&] from other pages stops reaching them)

The rules are as follows.
-Headings go one level down: &&title becomes the ""#"" at the top of the text, &* becomes ""##"" and &*&* becomes ""###"" (up to level 6).
-Tags are written in ""tags:"" of the front matter.
-A section with &*(optional) becomes a "":::details"" fold (keeping the depth of the heading).
-&&include becomes ""![](..)"", &&index becomes ""[TOC]"", and page lists such as &&treepages become ""[PAGES]"".
-&&direct(&[&[./document.pdf&]&]){description} becomes ""![description](./document.pdf)"". Pressing it still opens the file itself (a Markdown file (.md) opens the screen that shows it).
&&direct to images, audio, video and pages becomes ""[description](./photo.png)"", so that the look does not change. Pressing it now opens the page of the file, so it is listed among the things that are dropped.
-&&direct(&[&[./photo.png&]&]){&&include(&[&[./photo.png&]&],100x100);}, a thumbnail that opens the image when pressed, becomes ""![|100x100](./photo.png)"".
When the thumbnail is a different image, it becomes ""[![|!link](./small.png)](./photo.png)"". Pressing it opens the page of the file photo.png.
A thumbnail made a link to another site, as in ""&link(https://example.com/){&include([[./banner.png]]);}"", becomes ""[![|!link](./banner.png)](https://example.com/)"" too.
-Decorations such as &&color and &&size keep only the text inside.
-The first row of a table becomes its header row (a table in Markdown notation needs one). For a table that had no header row (h at the end of the row), the first row looks different, so it is listed among the things that are dropped. The columns of tables are written out lined up.
-&[&[display name:page name&]&] is reordered to &[&[page name&|display name&]&]. Where it points is decided in the same way, so the destination is not rewritten.

The version before conversion is kept in the history, and a sentence with a link to that version is added at the end of the text.
To undo, open that version and press ''Restore this version''.
-Only that page is converted. Its subpages are not.
-If the page is renamed, the version before conversion stays in the history of the old name (the history does not move to the new name). The link at the end still opens the version before conversion, but ''Restore this version'' is not shown there. To undo the conversion, first [[rename:../PageMenu#Rename]] the page back to the old name.
-If other pages rely on the Wiki notation of this page, how they look changes.
For example, lists such as &&tracker on the parent page read items from the source of the subpages, and excerpts such as &&blogpages use &&more as the mark.
-Automatic links to page names (when enabled in the site settings) are not applied in Markdown notation.
*/

}

文字を空行で分けると異なる段落として扱われます．

&wikiexample{

}

URLをそのままかけばリンクとして表示されます．

&wikiexample{NextFormのサイトは`OFFICIAL_URL`にあります．}

*重要
文字を&'&'と&'&'で囲むことで強い重要性が示された文字になります．
文章全体のうち重要な部分を示すときに使用します．

&wikiexample{... この記事は''料理についての''文章です． ...}

文字を&'&'&'と&'&'&'で囲むことで強調された文字になります．

&wikiexample{私は'''和食'''が好きです．}

文字を&%&%と&%&%で囲むことで打ち消された文字になります．

&wikiexample{%%こんにちは%%こんばんは}

&[&[と&]&]で囲まれた文字は他のページへのリンクになります．

&>&>で区切ると新しいウィンドウ(タブ)で開くリンクになります．

$comment_end$

-[[Functions>./Function]]

On a page in Wiki notation, double clicking replaces just that part with its source. Even a part of a line or a single row of a table can be edited.
For a list, double clicking switches to a display in which items can be removed or
struck out. Double clicking an item again lets you edit its source.
While editing the source, press ''Ctrl+Space'' or a similar key to open a window that completes the notation ([[Wiki Cheat Sheet:./CheatSheet]]).

/**
@manual $manualpage$/en/Wiki/Basic
&title Basic elements
*Ordinary text
Write ordinary characters in the source and the wiki engine shows them as they are.
A line break in the source means no more than a single space, though.

&wikiexample{
Some text
and a second line in the source..
}

*Paragraph
Text separated by an empty line is treated as a separate paragraph.

&wikiexample{
Some text

and an empty line in the source...
}

*URL
A URL written as it is appears as a link.

&wikiexample{The NextForm site is at `OFFICIAL_URL`.}

*Strong
Surrounding text with &'&' and &'&' marks it as strongly important.
Use it for the important parts of a piece of writing.

&wikiexample{... this article is ''about cooking''. ...}

*Emphasis
Surrounding text with &'&'&' and &'&'&' emphasizes it.
Use it for the part of a sentence you want to stand out.

&wikiexample{I like '''Japanese food'''.}

*Strikeout
Surrounding text with &%&% and &%&% strikes it out.

&wikiexample{%%Good morning%%Good evening}

*Link
Text surrounded by &[&[ and &]&] becomes a link to another page.
Writing &[&[Cooking/Japanese&]&] makes a link to the page ''Cooking/Japanese''.
Writing &[&[the food I like:Cooking/Japanese&]&] also links to ''Cooking/Japanese'',
but the link is shown as ''the food I like''.
The separator can be &| or &> or &>&> as well as &:.
Separating with &>&> makes a link that opens in a new window (tab).
The page name can be a [[relative page name:../..#Relative page names]]
using ''.'' or ''..''.
Adding ''#heading name'' after the page name links to a section within that page.
A URL can be written instead of a page name.
Use [[&&link:../Function/link]] when you want to build a link with finer control.

&wikiexample{
[[Cooking/Japanese]]
[[the food I like:Cooking/Japanese]]
[[../Italian]]
[[$manualpage$/en/PageMenu#History]]
[[NextForm official page:`OFFICIAL_URL`]]
}

*Comment
Characters from where &/&/ is written to the end of the line are ignored.
A part surrounded by &/&* and &*&/ (several lines allowed) is ignored in the same way.
Use this to put notes in the source.

&wikiexample{
Good moring //fix the spelling later
$comment_begin$
Text we do not want shown yet
but want to keep
$comment_end$
}

*Line break
Writing &~ at the end of a line breaks the line.
In ordinary writing, though, you should not break lines just to tidy the look or to
make it easier to read.
If the break carries meaning, we recommend inserting an empty line and separating it
as a paragraph instead.
And when you want to show text with its line breaks exactly as they are, we recommend
[[preformatted text:../LineHead#Preformatted text]].
To break a line somewhere other than the end of a line, you can write &&br; instead.

*Symbols
To show a symbol used by Wiki notation as it is, put && in front of it.
For example, write &&/&&/ to show &/&/ as it is, and &&&& to show && as it is.

HTML character entity references and numeric character references can be used,
such as &&copy; &&nbsp; and &&#9834;.

The following emoticons can also be used.
|notation|shown|hlc
|&&heart;|&heart;|
|&&smile;|&smile;|
|&&bigsmile;|&bigsmile;|
|&&huh;|&huh;|
|&&oh;|&oh;|
|&&wink;|&wink;|
|&&sad;|&sad;|
|&&worried;|&worried;|

*Showing text as it is
To show symbols as they are across a long stretch of text, surround the range with
&"&" (two double quotes) and &"&".
The range surrounded that way is not read as Wiki notation and is shown as it is.
To do the same across several lines, use [[&&plain:../Function/plain]].

&wikiexample{
""when you use many symbols of Wiki notation such as & or [[, surrounding them with two double quotes shows them as they are""
}
*/

@manual $manualpage$/ja/Wiki/LineHead

&title 行頭記法

*行頭記法の基本
ソースの行頭に決められた記号を書くことで特別な意味になります．基本的な書き方は以下のようになります．
 記号 対象となる文
例えば行頭の''&-(マイナス)''記号は箇条書きを意味し，箇条書きを作るには以下のようにします．
 - パスタ
対象となる文が複数行になる場合は
 記号{
 対象となる文1
 対象となる文2
 }
のように&{と&}で囲んで記述します．&{と&}の中でもWiki記法が使えます．例えば以下のように記述します．
 -{パスタは
 おいしい}
例外として&{が先にあっても行頭記法と解釈されます．例えば上の例は以下のようにも書けます．
 {-パスタは
 おいしい}

行頭記法の記号のすぐ後に&(と&)で囲まれた部分があると特別な指定と解釈されます．
記号のすぐ後に&(を記述した場合は記号の後にスペースを入れてから&(を記述してください．

*節
行頭に&*を書くと節の始まりになります．&*のあとに文をかくとそれが節の見出しになります．
節は次の節かページの終わりに到達するまで続いていると解釈されます．
&*&*のように&*を複数続けて書くことで節の中の節を作ることもできます．&*の数に制限はありません．

もし節の終わりを明示したい場合は終わらせたい節の深さに対応した分だけ行頭から&*を書き，その直後に''(end)''と書きます．
また&*の直後に''(optional)''と書くと折りたたまれた状態で表示されます．

&wikiexample{
*パスタの作り方について
**材料
材料は...
***生地の材料
生地の材料は..
***ソースの材料
ソースの材料は..
*(optional)ちょっとひと工夫
ごにょごにょするとおいしくなります．
}

*箇条書き
行頭に&-または&+を書くと箇条書きになります．&-は順序に依存しない箇条書き，&+は順序に意味のある箇条書きになります．
空行をいれずにこれらを続けることでひとまとまりの箇条書きとして扱われます．
&-と&+は混在させることもできます．
どちらも記号を連続して書くことで入れ子になった箇条書き(箇条書きの中の箇条書き)を表現できます．
入れ子の深さに制限はありません．

&-または&+の直後に''(optional)''と書くと折りたたまれた状態で表示されます．

&wikiexample{
-食材
--肉
---牛肉
---豚肉
--野菜
---キャベツ
---にんじん

+下ごしらえ
++以下の材料をきざむ
---キャベツ
---にんじん
+ソースを作る
++{フライパンに火を付け
油をひく そして複数行にわたり...}
++きざんだ材料をいれる
}

*関連リスト
ある項目とその項目の説明のような，対応関係を列挙したもの(関連リスト)を記述できます．
関連リストを記述するには行頭に&:を書きます．
その後に項目と説明を書きます．項目と説明は&|で区切ります．
空行をいれずにこれらを続けることでひとまとまりの関連リストとして扱われます．

&wikiexample{
:包丁|包丁とは調理をするための刃物である．
:{おたま|
おたまとは．．．
複数行にわたる場合は:のあとに{と}を書きます．
}
}

*整形済みテキスト
行頭に半角スペースを書くと，半角スペース以降に書いたものが改行も含めそのまま表示されます．
テキストをそのまま表示させたいときに便利です．
編集画面で整形済みテキストにしたい範囲を選択し''引用''のボタンを2回押すと簡単に整形済みテキストが作成できます．
プログラム言語等を書く場合は最初の行で半角スペースに続いて(code)と書くとハイライト機能が有効になります．
詳細な使い方は[[&&pre:../Function/pre]]のページを参考にしてください．

&wikiexample{
 あいうえお
 かきくけこ

 (code)
 int func(int a) {
     return a * 2;
 }
}

*引用

行頭に&>を書くと他の情報源から引用されたテキストとして表示されます．
空行をいれずにこれらを続けることでひとまとまりの引用として扱われます．
編集画面で引用にしたい範囲を選択し''引用''のボタンを押すと引用を素早く作成できます．

&wikiexample{
>吾輩は猫である。
>名前はまだ無い。
}

*区切り線
行頭から4つ以上の&=を書くと区切り線になります．

&wikiexample{
====
}

*数値計算
行頭に&=をひとつだけ書き，続けて式を書くとその式の計算結果に置き換わります．
式の最後に&=を書くと結果を置き換えずに数式と結果の両方を表示します．
数式内の&[と&]で囲まれた部分は無視されます．
&=の直後に&(を書く場合はスペースを入れてください．

[[数値計算の詳細>../Calc]]ページも参照してください．

&wikiexample{
= (1 + 2) * 3 ^ 2 / 4
= sin(pi/4) + cos(pi/4) + log(2 & 1024) =
= 1,000[ml] * 20[本] / 1000[L換算] = [L]
}

*表
行頭に&|を書くと表になります．ソースでの1行がテーブルの1行になります．
行中でさらに&|で区切ることでテーブルの列を記述できます．
最後の列の後にも&|を記述してください．

''行の最後&|のあと''に以下の文字を列挙するとセルの書式を指定できます．
複数回書くことで左のセルから順番に対応して指定できます(hとfは除く)．
指定がない場合はその直前のセルまたは行の書式に従います．

|文字|効果                                            |h
|h   |その行をヘッダーにする                          |
|f   |その行をフッターにする                          |
|c   |そのセルを中央揃えにする                        |
|l   |そのセルを左揃えにする                          |
|r   |そのセルを右揃えにする                          |
|n   |中央,左,右揃えを解除する                        |
|#   |セルの背景の強調                                |
|&=  |セルの背景の強調の解除                          |
|%   |セルの文字の強調                                |
|/   |セルの文字の強調の解除                          |
|&,  |セルの数式をカンマ区切りにする                  |
|.   |カンマ区切りを解除                              |
|w   |w100 や w14em のように書くことでセルの幅を指定  |
|e   |e100 や e14em のように書くことでセルの高さを指定|
幅や高さは''w''や''e''のみを書くことで指定を解除できます．

またセルの記述の中に &^ &_ &< &> だけを記述することで
それぞれ上下左右のセルと結合ができます．

セルの先頭に&~を書くとそのセルは見出しのセルとして扱われます．
セルの先頭に&=を書くと式を書くことができ，表計算をすることができます．
詳細は[[数値計算の詳細>../Calc]]を参照してください．

ソース上で&|の位置がずれていたとしてもページの保存時に，
桁がそろえられ，ソース上でも表が見やすくなります．

閲覧時にヘッダー(hで書式指定された行)をクリックすることで自由に並び替えることができます．

&wikiexample{
|材料        |分量     |価格(円)  |h,
|キャベツ    |1/4カット|=100      |lcr
|にんじん    |半分     |=50       |
|高級トマト缶|<        |=1200     |
|塩          |少々     |不明      |%/
|こしょう    |少々     |=10       |/
|愛情        |たくさん |=100000000|#
|合計        |<        |=sum(up)  |f=
}

ヘッダーまたはフッターに ''@項目名/選択肢1/選択肢2/...@'' という形式の列を作ると，
その列のセルをダブルクリックして編集する時に選択肢が表示されるようになります．

*CSV形式の表
行頭に&,を書きその後にCSV形式のデータを記述することで，
CSV形式のデータを表として表示できます．

&wikiexample{
,りんご,100円
,"みかん,オレンジ",200円
}
*/

&title Line head notation

*The basics of line head notation
Writing a set symbol at the start of a line in the source gives that line a special
meaning. The basic form is
 symbol the text it applies to
For example ''&-(minus)'' at the start of a line means a list, so a list is made
like this:
 - pasta
When the text it applies to runs over several lines, surround it with &{ and &}:
 symbol{
 first line of the text
 second line of the text
 }
Wiki notation can be used inside &{ and &} as well. For example:
 -{pasta is
 delicious}
As an exception, a &{ that comes first is still read as line head notation.
The example above can therefore also be written:
 {-pasta is
 delicious}

A part surrounded by &( and &) right after the symbol of a line head notation is read
as a special setting.
When you write &( right after the symbol, put a space before the &(.

*Sections
Writing &* at the start of a line begins a section.
Text after the &* becomes the heading of that section.
A section is read as continuing until the next section or the end of the page.
Writing several &* in a row, as in &*&*, makes a section inside a section.
There is no limit to the number of &*.

To mark the end of a section, write as many &* from the start of the line as the depth
of the section you want to end, and write ''(end)'' right after them.
Writing ''(optional)'' right after the &* shows the section folded.

&wikiexample{
*How to make pasta
**Ingredients
The ingredients are...
***Ingredients for the dough
The dough needs..
***Ingredients for the sauce
The sauce needs..
*(optional)One small extra touch
A little fiddling makes it taste better.
}

*Lists
Writing &- or &+ at the start of a line makes a list.
&- makes a list whose order carries no meaning, &+ a list whose order does.
Continuing them without an empty line makes them one list.
&- and &+ can be mixed.
Writing the symbol several times in a row expresses a nested list
(a list inside a list). There is no limit to the depth.

Writing ''(optional)'' right after the &- or &+ shows the list folded.

&wikiexample{
-Ingredients
--Meat
---Beef
---Pork
--Vegetables
---Cabbage
---Carrot

+Preparation
++Chop the following
---Cabbage
---Carrot
+Make the sauce
++{Heat the frying pan
and add oil, over several lines...}
++Add the chopped ingredients
}

*Description lists
You can write a list of pairs, such as an item and its description
(a description list).
To write one, put &: at the start of the line.
Then write the item and the description, separated by &|.
Continuing them without an empty line makes them one description list.

&wikiexample{
:knife|A knife is a blade used for cooking.
:{ladle|
A ladle is...
When it runs over several lines, write { and } after the :.
}
}

*Preformatted text
Writing a space at the start of a line shows everything after that space exactly as
written, line breaks included.
It is handy when you want text shown as it is.
On the editing screen, select the range you want as preformatted text and press the
''Quote'' button twice to make preformatted text quickly.
When writing a programming language, write (code) after the space on the first line
to turn on highlighting.
See the [[&&pre:../Function/pre]] page for how to use it in detail.

&wikiexample{
 abcde
 fghij

 (code)
 int func(int a) {
     return a * 2;
 }
}

*Quotes

Writing &> at the start of a line shows the text as quoted from another source.
Continuing them without an empty line makes them one quote.
On the editing screen, select the range you want quoted and press the ''Quote'' button
to make a quote quickly.

&wikiexample{
>It was the best of times,
>it was the worst of times.
}

*Horizontal rules
Writing four or more &= from the start of a line makes a horizontal rule.

&wikiexample{
====
}

*Calculation
Writing a single &= at the start of a line, followed by an expression, replaces it with
the result of that expression.
Writing &= at the end of the expression shows both the expression and the result
instead of replacing it.
A part surrounded by &[ and &] inside an expression is ignored.
When you write &( right after the &=, put a space before it.

See the [[details of calculation>../Calc]] page as well.

&wikiexample{
= (1 + 2) * 3 ^ 2 / 4
= sin(pi/4) + cos(pi/4) + log(2 & 1024) =
= 1,000[ml] * 20[bottles] / 1000[to L] = [L]
}

*Tables
Writing &| at the start of a line makes a table.
One line in the source is one row of the table.
Separating further with &| within the line writes the columns of the table.
Write a &| after the last column as well.

Listing the following characters ''after the &| at the end of the row'' sets the format
of the cells. Writing them several times sets the cells in order from the left
(except for h and f).
With nothing set, a cell follows the format of the cell before it or of the row.

|character|effect                                                    |h
|h        |make the row a header                                     |
|f        |make the row a footer                                     |
|c        |centre the cell                                           |
|l        |align the cell left                                       |
|r        |align the cell right                                      |
|n        |clear centre, left and right alignment                     |
|#        |highlight the background of the cell                      |
|&=       |clear the background highlight                            |
|%        |highlight the text of the cell                            |
|/        |clear the text highlight                                  |
|&,       |show the expression in the cell with thousands separators  |
|.        |clear the thousands separators                            |
|w        |set the width of the cell, written as w100 or w14em        |
|e        |set the height of the cell, written as e100 or e14em       |
Width and height can be cleared by writing ''w'' or ''e'' on their own.

Writing only &^ &_ &< or &> inside a cell merges it with the cell above, below,
to the left or to the right.

Writing &~ at the start of a cell makes that cell a heading cell.
Writing &= at the start of a cell lets you write an expression, giving you a
spreadsheet. See [[details of calculation>../Calc]].

Even when the &| are out of line in the source, the columns are lined up when the page
is saved, so the table is easy to read in the source too.

Clicking a header (a row formatted with h) while reading sorts the table freely.

&wikiexample{
|ingredient   |amount   |price     |h,
|cabbage      |quarter  |=100      |lcr
|carrot       |half     |=50       |
|good tomatoes|<        |=1200     |
|salt         |a pinch  |unknown   |%/
|pepper       |a pinch  |=10       |/
|love         |plenty   |=100000000|#
|total        |<        |=sum(up)  |f=
}

Making a column in the header or footer of the form
''@item name/choice1/choice2/...@'' shows the choices when a cell in that column is
double clicked to be edited.

*Tables in CSV form
Writing &, at the start of a line and CSV data after it shows the CSV data as a table.

&wikiexample{
,apple,1.00
,"orange, mandarin",2.00
}
*/

&title ファンクション
*ファンクションの基本
より複雑な機能を使うためにファンクション記法と呼ぶ記法が用意されています．
ファンクション記法は以下のいずれかの形式で書きます．

 &ファンクション名(パラメータ) 対象..

 &ファンクション名(パラメータ) 対象..; 対象ではない後続の文

 対象2
 対象3..

パラメータは機能に対する付加的な指示を書きます．
対象はその機能を適用する文などを書きます．

例えば[[&&color:./color]]は文字の色を変更するファンクションです．使用するには以下のように書きます．

&wikiexample{これから&color(red){赤い文字}を書きます．}

colorがファンクション名，redがパラメータ, "赤い文字"が対象です．
以下のように&;記号か改行で対象の終了を指示することもできます．

 これから&color(red)赤い文字;を書きます．

 これから&color(red)赤い文字
 を書きます．

ファンクションを他のファンクションや他のWiki記法の中で使用することもできます．
[[&&size:./size]]は文字の大きさを変えるファンクションです．

&wikiexample{
- &color(green)緑色の箇条書き
&size(150%) { &color(blue) { 青くて大きい文字 }}
}

**パラメータ
パラメータは&(と&)も含め省略することができます．
パラメータが複数ある場合は&,(カンマ)記号で区切って書きます．
機能によってパラメータの書き方は異なりますが，
原則として以下のようなパターンになっています．
:特定の英単語|付加的な機能の有効化
:!特定の英単語|付加的な機能の無効化
:特定の英単語=値|値の指定
:&[&[ページ名&]&]|対象とするページの指定
:数値|数量の指定

**(optional)複数の中括弧を用いた対象の指定
対象は ''&{&{&{'' と ''&}&}&}'' のように連続した''&{記号''と''&}記号''で囲むこともできます(連続する回数は任意)．
このようにすると，対象の中に ''&{記号'' や ''&}記号'' が入っていても期待通りに動作します．

&wikiexample{{{{{
&color(green) {{{{緑色で中括弧 } を書きました．}}}}
}}}}}

&title Functions
*The basics of functions
A notation called function notation is provided for using more involved features.
Function notation is written in one of the following forms.

 &function name(parameters) the target..

 &function name(parameters) the target..; text after it that is not the target

 &function name(parameters) { target 1
 target 2
 target 3..
 }

The function name is the fixed name given to each feature.
The parameters are additional instructions to that feature.
The target is the text and so on that the feature applies to.

For example [[&&color:./color]] is the function that changes the colour of text.
It is used like this:

&wikiexample{Now I write &color(red){text in red}.}

Here color is the function name, red is the parameter and "text in red" is the target.
The end of the target can also be marked with a &; symbol or with a line break,
as follows.

 Now I write &color(red)text in red;.

 Now I write &color(red)text in red
 here.

A function can also be used inside another function or inside other Wiki notation.
[[&&size:./size]] is the function that changes the size of text.

&wikiexample{
- &color(green)a list item in green
&size(150%) { &color(blue) { big blue text }}
}

**Parameters
The &( and &) can be left out along with the parameters.

**(optional)Marking the target with repeated braces

/**
@manual $manualpage$/ja/Export
&title エクスポート機能

NextFormにはNextFormで作成したページをhtmlファイル,画像ファイル,cssファイル等に書き出し，
静的コンテンツのサイトを構築できる機能があります．
これをエクスポート機能と呼びます．

エクスポート機能を用いるとサイトの内容やデザイン，サイトを管理する画面をNextFormのページ(種別wikiでも種別Markdownでも)で管理することができます．
大げさに表現するならばNextFormはCMS(Content Management System)自体を構築，管理できるCMSMSであるといえます．
すなわち，サイトの管理者がサイトの編集者に必要最低限のCMSや，親切な説明を加えたCMSを簡単に提供することができます．

*有効化

エクスポート機能はデフォルトでは無効になっています．
使用する場合はindex.phpに
 define('EXPORT_ENABLE', 'true');
を追記します．(index.phpについては[[サイトの高度な設定:../Administration#サイトの高度な設定]]参照)

またエクスポート機能を使用できるのは管理者かエクスポートの権限を与えられたユーザーのみです．

*基本的な設定
エクスポート機能を使用するにはどのページをどのファイルに書き出すかを設定する必要があります．
この設定をするには好きなページに[[Wiki記法の表:../Wiki/LineHead#表]]を用いて設定表を書きます．
設定表は1列目にページへのリンク, 2列目に書き出すファイル名を書きます．
例えばWiki記法で
 |ページ名          |ファイル名   |h
 |[[トップページ]]  |index.html   |
 |[[スタイルシート]]|css/style.css|
のように書きます．ヘッダ行(上記の例では1行目)は無視されますので省略しても，お好みのヘッダにしても構いません．

設定表は[[Markdown記法の表:../Markdown/Extra#表]]で書いても構いません．
そのときは1列目のページへのリンクを ""[[ページ名]]"" で書きます．

設定表を書いたら，表でリンクにしたページを作成しておいてください．
htmlファイルにしたいページは種別wikiか種別Markdownのページで，その他のページは種別textか種別fileのページで作成するのがおすすめです．
種別wikiと種別Markdownのページは，画面に表示するときと同じようにHTMLに変換して書き出されます．

次にこの設定にしたがって実際にファイルの書き出しを行うためのボタンを作成します．
このボタンを作成するには
 &export;
と書きます．これは先ほどの設定表の上でも下でも構いませんし，別のページ書いても構いません．
ただし，別のページに書いた場合は
 &export([[設定表のあるページ]]);
と書いてください．
&&export;のより高度な使用方法は[[こちら:../Wiki/Function/export]]を参照してください．
これでボタンが作成され，押せば実際にファイルの書き出し(エクスポート)が行われます．

ファイルは設定表の2列目に設定したファイル名で，
[[設定項目:../Administration/Settings]]の''EXPORT_DIR_PATH''
で設定されているディレクトリの下に保存されます．
このディレクトリに対してWebサーバーの設定を行い，公開することでhtmlファイル等で構成された静的なサイトが構築できます．
もしNextFormを設置したWebサーバーとは別のWebサーバーにあるコンテンツを管理したい場合は[[エクスポート後の処理:.#エクスポート後の処理]]を参照してください．

*テンプレート
上記の例ではindex.htmlとcss/style.cssというファイルを書き出しましたが，
index.htmlはcss/style.cssをスタイルとして使用するようにはなっていないためcss/style.cssが無意味になってしまいます．
この問題は，エクスポート用のテンプレートを設定することで解決できます．
テンプレートを使用するには設定表の3列目を作成し，テンプレートになるページへのリンクを書きます．例えば
 |ページ名          |ファイル名   |テンプレート              |h
 |[[トップページ]]  |index.html   |[[通常ページテンプレート]]|
 |[[スタイルシート]]|css/style.css|                          |
のように書きます．設定表にテンプレートを書いたらテンプレートを作成します．
テンプレートになるページは種別textか種別fileにしてください．
例えば以下のような内容にします．
 (code)
 <!DOCTYPE html>
 <html>
   <head>
     <meta charset="UTF-8">
     <title>$title$</title>
     <link rel="stylesheet" type="text/css" href="./css/style.css"/>
   </head>
   <body>
     $contents$
   </body>
 </html>
このようなテンプレートを設定しエクスポートをすると，index.htmlにはテンプレートの内容が書き出されますが，
テンプレート内の$title$の部分がページ名になり，
$contents$の部分が設定表の1列目で指定したページの内容になります．

設定表の3列目，すなわちテンプレートの欄に何も書かなければ1列目の内容がそのまま書き出されます．

エクスポート機能でのテンプレートとWiki記法の[[&&pages:../Wiki/Function/pages]]や[[&&writepage:../Wiki/Function/writepage]]でのテンプレートは異なるものです．注意してください．

**テンプレートの書き方
上記の$title$や$contents$のようにテンプレート内で特定のキーワードを書けば別の内容に置き換わります．
キーワードには以下のようなものがあります．

:$title$|ページ名または[[&&title:../Wiki/Function/title]]で設定されたタイトル(種別Markdownのページでは[[フロントマター:../Markdown/FrontMatter]]の ""title:"")
:$contents$|ページの内容
:{$&[&[ページ名&]&]$|ページ名で指定したページの内容に置き換えます．
ページ名はテンプレートのページから見た[[相対的な名前:..#相対ページ名]]でも構いません．
}
:{$mtime$|ページの更新日時
 $mtime?format=%Y/%m/%d$
のように書くことで任意のフォーマットにできます．
フォーマットは[[strftimeのフォーマット:http://php.net/manual/ja/function.strftime.php]]に従います．
}
:$btime$|ページの作成日時 (フォーマットの指定は$mtime$と同様)
:$exporttime$|エクスポートした日時 (フォーマットの指定は$mtime$と同様)
:{$tags$|ページのタグ一覧を表示します．
 $tags?list=[[ページ名]]$
上のように書くことでタグのリンク先を指定できます．
ページ名には[[&&pages:../Wiki/Function/pages]]等でページの一覧表示を行っているページを指定します．
こうすることでこのタグをクリックした先はページ一覧のうちこのタグを持っているものに限定されます．
さらに
 $tags?list=[[ページ名]]&prefix=この記事は&sep=と&suffix=のタグを持っています$
のようにタグがあった場合に前に表示する内容，後に表示する内容，タグの区切り文字を指定できます．
} 

*複数のページに対する設定
複数のページをエクスポートする際にすべてのページとファイル名の対応を設定表に書く必要はありません．
設定表の1列目に書かれたページから別のページにリンクがある場合，リンクされているページもエクスポートされます．
同様にリンクされているページからさらにリンクされているページもエクスポートされます．
すなわち設定表に書かれたページからリンクでたどることのできるページはすべてエクスポートされます．

このようにリンクによって派生的にエクスポートされるページには，
書き出すファイル名やテンプレートが設定されていません．
この場合はファイル名やテンプレートは自動で決定されますが，設定表で明示することもできます．例えば以下のように設定します．
 |ページ名          |ファイル名       |テンプレート              |h
 |[[トップページ]]  |index.html       |[[通常ページテンプレート]]|
 |[[スタイルシート]]|css/style.css    |                          |
 |ブログ/&*         |                 |[[ブログ用テンプレート]]  |
 |type=wiki         |                 |[[通常ページテンプレート]]|
 |&*.jpg            |images/$basename$|                          |

設定表の1列目にページへのリンクではなくページ名のパターンをワイルドカードを用いて指定できます．
このパターンと一致するページはこの行を設定として使用します．
''Wiki記法で&*や&/&*や&*&/は見出しやコメントの意味になってしまうので&*の前に&&記号をつけてエスケープする必要があるので注意してください．''
上記の設定表の例では''ブログ''というページの子ページはすべて''ブログ用テンプレート''というテンプレートして使用し，ファイル名は空欄なので自動で決定するように設定されています．

同じく設定表の1列目に
 type=ファイル種別
の形式でページ種別を指定することもできます．上記の設定表の例では種別wikiのページはすべて''通常ページテンプレート''をテンプレートして使用するように設定されています．

設定表の1列目の条件は上から順に検査され，最初に一致した行を設定として使用します．

設定表の2列目には書き出すファイル名を書きますが，特定のキーワードを書けばページに応じたファイル名を設定できます．
キーワードには以下のようなものがあります．

:$id$|自動で決定された他のページと重複しない英数字の羅列になります．
:$basename$|ページ名のうち最後の/(スラッシュ)より後ろの部分になります．
:$extension$|ページ名をファイル名とみなしたときの拡張子の部分になります．ドットも含みます．
:$filename$|$basename$のうち拡張子に相当する部分を除いたものになります．
:{$args$|ひとつのページに複数のバリエーションがある時
([[&&pages:../Wiki/Function/pages]]のcontentsパラメータを使用した際に一覧が複数ページにまたがる時や，
一覧を特定のタグで限定できるとき)
にそのバリエーションを一意に識別する英数字列に置き換わります．}

*エクスポート後の処理
エクスポートを行った後にUNIXコマンドを実行することができます．
実行するコマンドは[[設定項目:../Administration/Settings]]の''EXPORT_POST_COMMAND''で設定できます．
このコマンドはコマンド引数にエクスポート先のディレクトリを渡され，
標準入力から実際にエクスポートされたファイル名をNUL文字('\0')区切りで入力されます．

このコマンドにrsyncやftpコマンドでファイルを送信するスクリプトを設定すれば，
リモートホストにあるWebサーバーのコンテンツを管理することができます．

''コマンドに入力される文字列はNextFormのサイトで自由に編集できる文字列であることに注意してください．''

コマンドは0以外のステータスで終了することでエラー扱いになります．

例えばエクスポートの結果をログとして残すシェルスクリプトは以下のようになります．
 (code)
 #!/bin/bash
 dir="$1"
 log() {
     local time
     time=$(date '+%F %T')
     echo "$time: $1" >> log.txt
 }
 log "start export $dir"
 while read -d $'\0' file; do
     log "export $file"
 done
 log "end export $dir"
 exit 0

*エクスポート先の切替え
ひとつの設定表に対してエクスポート行うボタンを複数作成しても構いません．
[[&&export:../Wiki/Function/export]]のdirectoryパラメータを用いると，
同じコンテンツを異なるディレクトリにエクスポートできます．
例えば以下のように書きます．
 &export(directory=test, label=テスト環境へエクスポート);
 &export(directory=real, label=本番環境へエクスポート);
これはテスト環境と本番環境のディレクトリ(testとreal)を用意し，それぞれに対してボタンを作成しています．
テスト環境でエクスポート結果を確認した後で本番環境に反映させるといったような使い方ができます．
*/

@manual $manualpage$/ja/HtmlFile
&title HTMLファイルの直接実行

HTMLで作ったゲームやちょっとした道具をページに添付しておき，
ブラウザでそのまま動かすことができます．

*有効にする
この機能は''既定では無効''です．無効のあいだは，添付したHTMLファイルを開くと
ダウンロードになります．

有効にするには，管理権限を持つユーザーでログインして，
''サイトメニュー'' > ''管理ツール'' > ''サイト設定'' を開き，
''添付したHTMLファイル''を''隔離して動かす''にして保存します．
(設定の名前は[[FILE_ALLOW_HTML:../Administration/Settings]]です．)

有効にすると，編集できる人なら誰でも，このサイトのURLの下に好きな画面
(たとえばログイン画面に似せたもの)を出せるようになります．
自分だけ，または信頼できる人だけが編集するサイトで有効にしてください．

*動かし方
HTMLファイルを[[添付:../PageMenu#添付]]してから，ファイルのページに出る''開く''を押します．
ページからは，次のように書くと押すだけで動くリンクになります．

|記法|書き方|h
|Markdown記法|""![落ちものパズル](./ochimono.html)""|
|Wiki記法|&&direct(&[&[./ochimono.html&]&]){落ちものパズル}|

Markdown記法では，""![ ]"" の中に書いた文字がリンクの表示になります．
何も書かなければ''開く''になります．
""[落ちものパズル](./ochimono.html)"" と書いた場合は，動かすのではなく
ファイルのページへのリンクになります．

Wiki記法の[[&&direct:../Wiki/Function/direct]]は，ファイルへ直接リンクを張る記法です．
""{ }"" の中がリンクの表示になります．

どちらも，ファイル名は[[相対ページ名:..#相対ページ名]]で書けます．
''./'' はそのページの添付，''../'' は親のページの添付を指します
(''game/wiki-page'' から ''../ochimono.html'' と書けば ''game/ochimono.html'')．

*動くときの制限
HTMLはwikiから隔離して動きます．開いた人の権限でwikiのページや設定を
書き換えることはできません．そのかわり，次のこともできません．
-保存したデータ(localStorage)を残すこと．ゲームの最高点などは，開き直すと消えます
-フォームの送信
-警告や確認の表示(alert，confirm，prompt)
-新しいウィンドウを開くこと

外部のサーバーから部品(フォントや画像など)を読み込むことはできます．

HTMLの中で文字コードを宣言していれば(""<meta charset=Shift_JIS>"" など)，
その文字コードで開きます．宣言が無ければUTF-8として開きます．

/**
@manual $manualpage$/en/Export
&title Export function

NextForm can write out the pages you made with it as HTML files, image files, CSS files
and so on, letting you build a site of static content.
This is called the export function.

With the export function you can manage the contents and the design of a site, and the
screens that administer it, in NextForm pages (of type wiki or Markdown).
Put grandly, NextForm is a CMSMS that can build and manage a CMS (Content Management
System) itself. That is, the administrator of a site can easily hand the editors of the
site a minimal CMS, or a CMS with helpful explanations added.

*Enabling it

The export function is disabled by default.
To use it, add
 define('EXPORT_ENABLE', 'true');
to index.php. (For index.php see
[[advanced site settings:../Administration#Advanced site settings]].)

Only an administrator, or a user granted the export right, can use the export function.

*Basic setup
To use the export function you have to set which page is written out to which file.
To do so, write a setup table on any page you like, using a
[[table in Wiki notation:../Wiki/LineHead#Tables]].
The setup table has a link to the page in the first column and the name of the file to
write in the second column.
In Wiki notation, write something like
 |page name       |file name    |h
 |[[Top page]]    |index.html   |
 |[[Style sheet]] |css/style.css|
The header row (the first row above) is ignored, so you may leave it out or make it
whatever you like.

The setup table may also be written as a [[table in Markdown notation:../Markdown/Extra#Tables]].
Write the links to the pages in its first column as ""[[page name]]"".

Once the setup table is written, create the pages you made into links in the table.
We recommend making the pages you want as HTML files pages of type wiki or type
Markdown, and the other pages of type text or type file.
Pages of type wiki and type Markdown are converted to HTML, just as they are when shown
on the screen.

Next, make a button that actually writes the files out following this setup.
To make this button, write
 &export;
This may go above or below the setup table, or on another page entirely.
When it is on another page, though, write
 &export([[the page with the setup table]]);
For more advanced ways of using &&export;, see
[[here:../Wiki/Function/export]].
That makes the button, and pressing it actually writes the files out (exports them).

The files are saved under the name set in the second column of the setup table, in the
directory set by ''EXPORT_DIR_PATH'' in the [[settings:../Administration/Settings]].
Configuring the web server for that directory and publishing it builds a static site
made of HTML files and so on.
To manage content on a web server other than the one NextForm is installed on, see
[[what happens after an export:.#What happens after an export]].

*Templates
The example above wrote out the files index.html and css/style.css, but index.html was
not made to use css/style.css as its style, so css/style.css is meaningless.
Setting a template for the export solves this.
To use a template, make a third column in the setup table and write a link to the page
that is the template. For example
 |page name       |file name    |template                |h
 |[[Top page]]    |index.html   |[[Normal page template]]|
 |[[Style sheet]] |css/style.css|                        |
Once the template is written in the setup table, create the template.
Make the page that is the template type text or type file.
Give it contents such as the following.
 (code)
 <!DOCTYPE html>
 <html>
   <head>
     <meta charset="UTF-8">
     <title>$title$</title>
     <link rel="stylesheet" type="text/css" href="./css/style.css"/>
   </head>
   <body>
     $contents$
   </body>
 </html>
Set a template like this and export, and the contents of the template are written to
index.html, with the $title$ part of the template becoming the page name and the
$contents$ part becoming the contents of the page named in the first column of the
setup table.

Write nothing in the third column, the template column, and the contents of the first
column are written out as they are.

The templates of the export function and the templates of
[[&&pages:../Wiki/Function/pages]] and
[[&&writepage:../Wiki/Function/writepage]] in Wiki notation are different things.
Take care.

**How to write a template
Write a particular keyword in the template, such as the $title$ and $contents$ above,
and it is replaced by something else.
The keywords are as follows.

:$title$|the page name, or the title set by [[&&title:../Wiki/Function/title]] (for a page of type Markdown, ""title:"" in the [[front matter:../Markdown/FrontMatter]])
:$contents$|the contents of the page
:{$&[&[page name&]&]$|replaced by the contents of the page named.
The page name may be a [[relative name:..#Relative page names]] seen from the template
page.
}
:{$mtime$|the time the page was modified
 $mtime?format=%Y/%m/%d$
Written like this it can take any format.
The format follows the
[[strftime format:http://php.net/manual/en/function.strftime.php]].
}
:$btime$|the time the page was created (the format is set as for $mtime$)
:$exporttime$|the time of the export (the format is set as for $mtime$)
:{$tags$|shows the list of tags of the page.
 $tags?list=[[page name]]$
Written as above it sets where the tags link to.
Name a page that lists pages with [[&&pages:../Wiki/Function/pages]] or the like.
Clicking a tag then leads to the page list narrowed to those carrying that tag.
Furthermore
 $tags?list=[[page name]]&prefix=This article has the tags &sep= and &suffix=.$
sets what is shown before the tags, what is shown after them, and the separator
between them, when there are any tags.
}

*Settings for several pages
When exporting several pages you do not have to write every page and file name into the
setup table.
When a page named in the first column of the setup table links to another page, the
linked page is exported too.
Likewise pages linked from those linked pages are exported.
That is, every page that can be reached by following links from the pages in the setup
table is exported.

Pages exported as a knock-on effect of a link like this have no file name or template
set for them.
The file name and template are then decided automatically, but they can also be stated
in the setup table. For example:
 |page name       |file name        |template                |h
 |[[Top page]]    |index.html       |[[Normal page template]]|
 |[[Style sheet]] |css/style.css    |                        |
 |Blog/&*         |                 |[[Blog template]]       |
 |type=wiki       |                 |[[Normal page template]]|
 |&*.jpg          |images/$basename$|                        |

The first column of the setup table can name a pattern of page names using wildcards,
instead of a link to a page.
Pages matching the pattern use that row as their setup.
''Note that &* and &/&* and &*&/ mean a heading or a comment in Wiki notation, so the &* has to be escaped by putting an && in front of it.''
In the example above, every child page of the page ''Blog'' uses the template
''Blog template'', and the file name is blank so it is decided automatically.

The first column of the setup table can also name a page type, in the form
 type=page type
In the example above every page of type wiki uses ''Normal page template''.

The conditions in the first column are checked from the top down, and the first row
that matches is used as the setup.

The second column of the setup table holds the name of the file to write, and writing
particular keywords there sets a file name that follows the page.
The keywords are as follows.

:$id$|a run of letters and digits, decided automatically, that no other page shares.
:$basename$|the part of the page name after the last / (slash).
:$extension$|the extension of the page name taken as a file name. The dot is included.
:$filename$|$basename$ with the part that is the extension removed.
:{$args$|replaced by a run of letters and digits that uniquely identifies a variation,
when one page has several of them
(when a list runs over several pages because the contents parameter of
[[&&pages:../Wiki/Function/pages]] is used, or when a list can be narrowed to a
particular tag).}

*What happens after an export
A UNIX command can be run after an export.
The command to run is set by ''EXPORT_POST_COMMAND'' in the
[[settings:../Administration/Settings]].
The command is passed the directory exported to as a command argument, and the names of
the files actually exported are fed to its standard input, separated by NUL
characters ('\0').

Set this command to a script that sends the files with rsync or ftp and you can manage
the content of a web server on a remote host.

''Note that the strings fed to the command are strings that can be edited freely on the NextForm site.''

The command is treated as having failed when it exits with a status other than 0.

For example, a shell script that keeps a log of the export looks like this.
 (code)
 #!/bin/bash
 dir="$1"
 log() {
     local time
     time=$(date '+%F %T')
     echo "$time: $1" >> log.txt
 }
 log "start export $dir"
 while read -d $'\0' file; do
     log "export $file"
 done
 log "end export $dir"
 exit 0

*Switching where you export to
You may make several buttons that export against one setup table.
The directory parameter of [[&&export:../Wiki/Function/export]] lets you export the
same content to different directories.
For example, write:
 &export(directory=test, label=Export to the test environment);
 &export(directory=real, label=Export to the live environment);
This prepares directories for a test environment and a live environment (test and real)
and makes a button for each.
You can use it to check the result of an export in the test environment before
reflecting it in the live one.
*/

/**
@manual $manualpage$/en/HtmlFile
&title Running HTML files directly

You can attach a game or a small tool made in HTML to a page and run it in the
browser as it is.

*Enabling it
This function is ''disabled by default''. While it is disabled, opening an attached
HTML file downloads it.

To enable it, log in as a user with administrator rights, choose
''site menu'' > ''Admin tools'' > ''Site preferences'', set ''Attached HTML files'' to
''Run in a sandbox'' and save.
(The name of the setting is [[FILE_ALLOW_HTML:../Administration/Settings]].)

Once it is enabled, anyone who can edit can show any page they like under the URL of
this site (for example, one made to look like a login screen).
Enable it only on a site that you alone, or people you trust, edit.

*Running a file
[[Attach:../PageMenu#Attach]] the HTML file, then press ''Open'' on the page of the file.
From a page, writing the following makes a link that runs the file when pressed.

|notation|how to write it|h
|Markdown notation|""![Falling blocks](./ochimono.html)""|
|Wiki notation|&&direct(&[&[./ochimono.html&]&]){Falling blocks}|

In Markdown notation, the words written inside ""![ ]"" become the text of the link.
If nothing is written there, it is ''Open''.
Writing ""[Falling blocks](./ochimono.html)"" instead makes a link to the page of the
file, not one that runs it.

In Wiki notation, [[&&direct:../Wiki/Function/direct]] makes a link straight to the
file. What is inside ""{ }"" becomes the text of the link.

In both, the file name can be a [[relative page name:..#Relative page names]].
''./'' points at an attachment of the page itself, and ''../'' at an attachment of the
parent page (from ''game/wiki-page'', ''../ochimono.html'' is ''game/ochimono.html'').

*Limits while it runs
The HTML runs isolated from the wiki. It cannot rewrite the pages or the settings of
the wiki with the permissions of the person who opened it. In exchange, it cannot do
the following.
-Keep data it saves (localStorage). The best score of a game and the like disappear
when it is opened again
-Submit forms
-Show alerts or confirmations (alert, confirm, prompt)
-Open new windows

It can load parts (fonts, images and so on) from outside servers.

If the HTML declares its character encoding (""<meta charset=Shift_JIS>"" and so on),
it is opened with that encoding. Without a declaration it is opened as UTF-8.
*/
