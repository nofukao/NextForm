/**
@manual $manualpage$/en

&title NextForm Manual
*What NextForm is
NextForm ([[official site:`OFFICIAL_URL`]]) is a wiki engine.
A wiki engine provides the functions to edit, show and manage web pages.

NextForm is a fork of [[ToraToraWiki:http://toratora.wiki/]] 1.3.10.
It inherits the GPLv3 license.

(In a hurry? Go to the [[Markdown Cheat Sheet:$manualpage$/en/Markdown/CheatSheet]] or the
[[Wiki Cheat Sheet:$manualpage$/en/Wiki/CheatSheet]])

*Pages
A site built with NextForm is made of pages.
Every page belongs to one of the four types below.

|type    |description                                                                  |h
|Markdown|a page written in [[Markdown notation>./Markdown]] (the default for new pages)|
|wiki    |a page written in [[Wiki notation>./Wiki]]                                   |
|text    |a page shown exactly as written, with no decoration                          |
|file    |a page that holds a single file                                              |

The type is chosen when the page is created and cannot be changed afterwards.

A typical way to use them is to write documents as Markdown or wiki pages, and to
upload images and downloadable files as file pages.
A file page can then be embedded in a document page or linked from it.

How a file page is shown depends on what the file holds.
An image file is shown as an image, a video file is shown in a player where possible,
and any other file is shown as a download screen.

**Page names
Every page has a name, called the page name from here on.
A page name may contain any character.

Pages can also stand in a parent and child relationship.
To create a page that is the child of another page (called a child page),
just use a slash in the name:
 parent page name/child name
For example, creating a page named
 Cooking/Japanese
makes it a child page of the page Cooking.

Writing the structure into the page name makes the shape of your documents clear,
and lets you rename or delete a whole set of child pages at once.

The relationship can be nested as deep as you like:
 Cooking/Italian/Pizza
Here the parent of ''Cooking/Italian/Pizza'' (called the parent page) is
''Cooking/Italian'', and the parent of that in turn is ''Cooking''.

**Relative page names
Inside a page you often write a page name to refer to another page.
When you do, ''.'' and ''..'' let you refer to other pages relative to your own.
''.'' means the page itself, and ''..'' means the parent page.
For example, writing ''.'' inside the page
''Cooking/Italian''
refers to ''Cooking/Italian'' itself, and writing ''..'' refers to ''Cooking''.
Here are some more examples.

|written in Cooking/Italian|page it refers to    |h
|.                         |Cooking/Italian      |
|..                        |Cooking              |
|./Pizza                   |Cooking/Italian/Pizza|
|../Japanese               |Cooking/Japanese     |

*Special pages

**The top page
The page named ''Top'' is shown when a visitor first arrives at the site.
The name ''Top'' can be changed in the settings.

**The side page
It depends on the design theme, but the default theme always shows a page named
''Side'' in a smaller area at the left.
Apart from being shown smaller, ''Side'' is an ordinary page you can edit freely.
List links to the pages you use often there and it becomes the navigation of your site.
The name ''Side'' can be changed in the settings.

*How to create a new page
There are several ways to create a new page. They are listed below.
:{Use ''New page'' in the ''site menu'' and type a page name|
A page created this way can only be reached from ''All pages'' in the ''site menu''.
That is inconvenient on its own, so you will end up
creating a link to the new page somewhere.}
:{Make the link first, on the Top page or the side page|
Add a line of the form
 [[name of the page you want to create]]
to the Top page or the side page
(this is written the same way in both Markdown and wiki pages).
That part becomes a link to a page that does not exist yet.
Clicking a link to a page that does not exist takes you to the screen that creates it.
This way is easy, so we recommend it.
In practice the text of a link is often a ''display name'' different from the page name.
How to write one differs between the notations, so see
[[Links, images and attachments:./Markdown/Link#Links to pages]] for Markdown notation
and [[Link:./Wiki/Basic#Link]] for Wiki notation.}

*Attached files
What other wiki engines offer as attached files is done in NextForm by creating child
pages of type file.
Attaching example1.jpg and example2.png to the page ''Cooking/Japanese'' means you have
created the two pages of type file
-''Cooking/Japanese/example1.jpg''
-''Cooking/Japanese/example2.png''
The ''Attach'' function in the ''page menu'' makes this easy.
NextForm can also attach several files at once.

To embed an attached image or video in a page, Markdown notation uses
""![description](file name)"" ([[Links, images and attachments:./Markdown/Link]])
and Wiki notation uses [[&&include:./Wiki/Function/include]].

By default, an attached HTML file is downloaded when it is opened.
Enabling [[FILE_ALLOW_HTML:./Administration/Settings]] in the site settings lets you run
it in the browser as it is, from ''Open'' on the page of the file.
The HTML then runs isolated from the wiki, so it cannot operate on the pages or the
settings of the wiki. Data it saves (localStorage) is not kept, and it cannot submit
forms or show alert dialogs.

*Backup
A backup is taken before a page is edited (it is skipped when the edits come close
together). You can therefore show the contents of a page as it was at some point in
the past, or compare two versions.

*Lock
Locking a page makes it impossible to edit. Only a user who has been granted the right
to lock can lock a page. Unlocking returns it to the editable state.
A user who has the right to lock can edit a page while it stays locked,
but a warning message is shown.

*How to write pages
Document pages are written in Markdown notation or in Wiki notation.
Both are first-class ways of writing.

Markdown notation is the way of writing used in common across many tools and services.
NextForm understands [[CommonMark:https://commonmark.org/]] and extensions such as
tables and strikethrough. Its strength is that text written in another tool can be
brought in as it is.

Wiki notation is the way of writing NextForm inherited from ToraToraWiki, the engine it
is based on. It follows the tradition of wiki engine notations represented by PukiWiki,
in which symbols at the start of a line express the structure of the document
(not the same as it: ToraToraWiki added extensions of its own).
[[Functions:./Wiki/Function]], which embed things such as page lists and calendars,
are available only in Wiki notation, and being able to build "living pages"
is its strength.

For details see the pages below.
-[[Markdown notation>./Markdown]]
-[[About Wiki notation>./Wiki]]
-[[Wiki notation and Markdown notation>./Comparison]]

*Site administration
For administering the site, see the page below.
-[[Site administration:./Administration]]

*Export function
For the export function, see below.
-[[Export function:./Export]]
*/

/**
@manual $manualpage$/ja

&title NextFormマニュアル
*NextFormとは
NextForm([[公式サイト:`OFFICIAL_URL`]])とはWikiエンジンのひとつです．
WikiエンジンはWebページの編集, 表示, 管理等の機能を提供します．

NextFormは[[ToraToraWiki:http://toratora.wiki/]] 1.3.10のforkです．
ライセンスはGPLv3を引き継いでいます．

(早く書き方を知りたい方は[[Markdown記法早見表:$manualpage$/ja/Markdown/CheatSheet]]か
[[Wiki記法早見表:$manualpage$/ja/Wiki/CheatSheet]]へ)

*ページ
NextFormを使ったサイトは複数のページによって構成されます．
それぞれのページは以下の4つのいずれかの種別に属します．

|種別    |説明                                                       |h
|Markdown|[[Markdown記法>./Markdown]]で表記されたページ(新規作成の既定)|
|wiki    |[[Wiki記法>./Wiki]]によって表記されたページ                |
|text    |書いたものが何の装飾もなくそのまま表示されるページ         |
|file    |ひとつのファイルが保存されたページ                         |

種別はページを作るときに選び，あとから変更することはできません．

典型的な使い方を例に挙げると，文章は種別Markdownか種別wikiのページとして作成し，
画像ファイルやダウンロードさせたいファイルは種別fileのページとしてファイルをアップロードすることで作成します．
種別fileのページは文章のページに埋め込んだり，リンクを張ることで利用できます．

種別fileのページはファイルの内容によってページの表示のされ方が異なります．
画像ファイルの場合は画像が表示され，動画ファイルの場合は可能であれば動画再生画面が表示されます．
その他のファイルであればそのファイルをダウンロードする画面が表示されます．

**ページ名
ページには名前を付けます．この名前を以後はページ名と呼びます．ページ名は日本語を含め任意の文字が使用できます．

ページは親子関係を持つこともできます．あるページに対してその子供にあたるページ(子ページと呼びます)
を作成するには半角スラッシュを用いて，
 親ページ名/子供の名前
というページ名を付けるだけです．
例えば
 料理/和食
というページを作成すれば，料理というページの子ページとして認識されます．

ページ名で親子関係を明示しておけば文章の構造が明確化されますし，ページを管理する際に
子ページをまとめてリネームや削除等ができて便利です．

以下のように親子関係は何層になっても構いません．
 料理/イタリアン/ピザ
このとき ''料理/イタリアン/ピザ'' の親になるページ(親ページと呼びます)が ''料理/イタリアン'' になり，
さらにこれの親ページが ''料理'' になります．

**相対ページ名
ページの中で他のページを参照するためにページ名を表記することがあります．
このとき ''.'' や ''..'' を使うと自分のページからみた関係で相対的に他のページを参照することができます．
''.''は自分自身のページを表します．''..''は親ページを表します．
例えば
''料理/イタリアン''
のページの中で ''.'' と表記すると そのまま''料理/イタリアン''のページのことを指していることになります．
''..''と表記すると''料理''のページをことを指します．
さらに例を挙げると以下の表のようになります．

|料理/イタリアン 内での表記|指されるページ      |h
|.                         |料理/イタリアン     |
|..                        |料理                |
|./ピザ                    |料理/イタリアン/ピザ|
|../和食                   |料理/和食           |

*特別なページ

**トップページ
''Top''というページはサイトに最初に訪れたときに表示されます．
''Top''という名前は設定により変更できます．

**サイドページ
デザインテーマにもよりますが，デフォルトのデザインテーマでは
左側に''Side''という名前のページが小さめに常に表示されます．
この''Side''というページは小さめに表示される点を除けば通常のページと同じで自由に編集できます．
このページによく使うページへのリンクを箇条書きすればサイトのナビゲーションとして使うことができます．
''Side''という名前は設定により変更できます．

*新しいページの作成方法
新しいページを作るにはいくつか方法があります．以下にその方法を挙げます．
:{''サイトメニュー''内の''新規ページ作成''機能を使いページ名を入力する|
この方法で作成されたページは''サイトメニュー''内の''全ページ一覧''からしかアクセスできません．
このままでは不便なので，
どこかのページに新しく作ったページへのリンクを作成することになります．}
:{Topページやサイドページで先にリンクをつくってしまう|
Topページやサイドページ内に
 [[新しく作成したいページ名]]
という形で行を追記します(この書き方は種別Markdownでも種別wikiでも同じです)．
するとその部分は存在しないページへのリンクになります．
存在しないページへのリンクをクリックするとそのページの新規作成画面にいくことができます．
この方法が簡単なのでおすすめです．
なお実際には，リンクの文字をページ名とは別の''表示名''にすることが多くあります．
表示名の付け方は記法によって違うので，Markdown記法は
[[リンク・画像・添付:./Markdown/Link#ページへのリンク]]を，
Wiki記法は[[リンク:./Wiki/Basic#リンク]]を参照してください．}

*添付ファイル
他のWikiエンジンで添付ファイルに相当する機能はNextFormでは種別fileの子ページを作ることで実現できます．
''料理/和食''のページにexample1.jpgとexample2.pngを添付した場合，
-''料理/和食/example1.jpg''
-''料理/和食/example2.png''
の二つの種別fileのページを作成したことになります．
''ページメニュー''内の''添付''機能により上記のことが簡単に行えるようになっています．
また，NextFormでは複数のファイルを同時に添付することができます．

添付した画像や動画をページ内に埋め込むには，Markdown記法では ""![説明](ファイル名)""
([[リンク・画像・添付:./Markdown/Link]])を，Wiki記法では
[[&&include:./Wiki/Function/include]]を使用します．

添付したHTMLファイルは，既定では開くとダウンロードになります．
サイトの設定の[[FILE_ALLOW_HTML:./Administration/Settings]]を有効にすると，
ファイルのページに出る''開く''から，ブラウザでそのまま動かせます．
このときHTMLはwikiから隔離して動くので，wikiのページや設定を操作することはできません．
保存したデータ(localStorage)は残らず，フォームの送信や警告の表示(alert)もできません．

*バックアップ
ページは編集される前にバックアップがとられます(編集の間隔が短い場合はバックアップをスキップします)．
なので過去のある時点でのページの内容を表示したり，比較することができます．

*ロック
ロックとはページを編集不可能にすることです．ロックをする権利を与えられたユーザーのみがページのロックを行えます．
ロックはアンロックをすることでもとの編集可能な状態にもどすことができます．
ロックをする権利があるユーザーはロックしたままページを編集することができますが，警告メッセージが表示されます．

*ページの書き方
文章のページはMarkdown記法かWiki記法で書きます．どちらも正式な書き方です．

Markdown記法は多くのツールやサービスで共通に使われている書き方です．
NextFormは[[CommonMark:https://commonmark.org/]]と，表や打ち消し線などの拡張を
解釈します．他のツールで書いた文章をそのまま持ち込めるのが持ち味です．

Wiki記法はNextFormのもとになったToraToraWikiから受け継いだ書き方です．
行頭の記号で文書の構造を表す，PukiWikiに代表されるWikiエンジンの記法の流れを
くんでいます(そのままではなく，ToraToraWiki独自の拡張が入っています)．
ページの一覧やカレンダーを埋め込む[[ファンクション:./Wiki/Function]]が使えるのは
Wiki記法だけで，「動くページ」を作れるのが持ち味です．

詳しくは以下のページにあります．
-[[Markdown記法>./Markdown]]
-[[Wiki記法について>./Wiki]]
-[[Wiki記法とMarkdown記法の対応>./Comparison]]

*サイトの管理
サイトの管理については以下のページを参照して下さい．
-[[サイトの管理:./Administration]]

*エクスポート機能
エクスポート機能については以下を参照して下さい．
-[[エクスポート機能:./Export]]

*/

@manual $manualpage$/ja/Administration

&title サイトの管理

*サイトの設定
サイトの基本的な設定を行うには，
管理権限を持つユーザーでログインして，
''サイトメニュー'' > ''管理ツール'' > ''サイト設定'' を選択して下さい．

**(optional)サイトの高度な設定
サイトの高度な設定はindex.phpの中に定数の定義を追記してくことで行うことができます．
定数の定義は以下の形式で行います．
 define('定数名', '定数の値');
例えばデフォルトのページ種別を設定する定数''DEFAULT_PAGE_TYPE''を''text''にするにはindex.phpを以下のような内容に書き換えます．
 (code)
 <?php
 // custom settings here -------
 define('DEFAULT_PAGE_TYPE', 'text'); 
 
 // ----------------------------
 require_once('app/boot.inc');
 ?>

またApache HTTP Serverを使用していれば定数名の先頭に''NEXTFORM_''をつけて
 SetEnv NEXTFORM_DEFAULT_PAGE_TYPE "text"
といった記述をhttpd.confや.htaccessに記述することで同様に設定できます．

設定できる定数は以下のページを参照して下さい．

-[[設定項目:./Settings]]

*ユーザー
NextFormではユーザーごとページごとに権限が設定できます．
ユーザーの設定をするには''サイトメニュー'' > ''管理ツール'' > ''ユーザーの管理'' を選択して下さい．
権限には以下のものがあります．上から順に権限が強くなり，下の権限は上の権限を含みます．

|権限            |説明                          |h
|利用不可        |すべての機能が使用できません．|
|閲覧のみ        |ページの閲覧のみが可能                                       |
|テキスト挿入のみ|[[&&comment:../Wiki/Function/comment]]や[[&&bbs:../Wiki/Function/bbs]]で用意されたフォームからコメント等の挿入が可能(注意，下記参照)|
|編集可能        |ページの編集が可能|
|ロック可能      |ページをロックすることが可能|
|エクスポート可能|[[エクスポート機能:../Export]]が有効のとき，エクスポートが可能|
|管理者          |サイトの設定を含むあらゆることが可能|

これらの権限の他に''ページごとに設定''という項目を選択するとページごとに権限が設定できます．

テキスト挿入のみの権限は見かけ上は[[&&comment:../Wiki/Function/comment]]や[[&&bbs:../Wiki/Function/bbs]]
を通してのみ編集可能な権限ですが，実際は任意の位置に任意の文字を挿入することができる権限です．
例えば悪意あるユーザーが特殊な方法を使用して，ページの先頭に'&/&*'を，
ページの末尾に'&*&/'を挿入することでページの内容をすべてコメント(非表示)にすることもできます．
テキスト挿入のみの権限は実質的には編集可能と同様の権限で，
用意されたフォーム以外ではページの編集が行い辛くなるという気休めの権限であると考えて下さい．

*色調(画面の色)
画面の色をまとめて選んだり，自分で作って保存したりできます．
''サイトメニュー'' > ''管理ツール'' > ''色調の設定'' で行います．
-[[色調(トーン):./Tone]]を参照して下さい．

*アクセス解析の設定
アクセス解析については
-[[アクセス解析の設定:./Analyzer]]を参照して下さい．
*/

/**
@manual $manualpage$/ja/Administration/Tone

&title 色調(トーン)

*色調とは
色調は画面で使う25色の組です．
テーマ(配置や余白の作り)とは別の軸なので，どのテーマを選んでも同じ色調が使えます．
''サイトメニュー'' > ''管理ツール'' > ''色調の設定'' で決めます．

*色を決める
''色調の設定''では，25色をそのまま並べています．
変えたい色だけを書き換えて，一番下の''適用''を押して下さい．

はじめから入っている色調や，保存した色調から始めることもできます．
一番上の''色調の読み込み''で選んで''読み込む''を押すと，入力欄にその色が入ります．
この時点ではまだ変わりません．''適用''を押すと使われます．

*色調を保存する
色を決めたら，''この色調の保存''に識別子と表示名を入れて''保存''を押します．
サーバに保存され，''色調の読み込み''に出るようになります．
(''保存''を押すと適用も同時に行われます．)

識別子はそのままファイル名になるので，半角の英数字と . _ - だけが使えます(32文字まで)．
日本語の名前は''表示名''に入れて下さい．

''保存した色調の削除''から選んで''削除''を押すと消せます．削除は取り消せません．
読み込みの一覧では，''後から保存したものほど上''に出ます．

*保存される場所
色調は1つがファイル1つです．2つのディレクトリから読み込まれます．

|ディレクトリ|内容|h
|app/tone/|NextFormに最初から入っている色調．更新のたびに入れ替わるので，ここは編集しない|
|storage/tone/|このサイトで保存した色調．更新しても残る|

同じファイル名なら''storage''側が使われます．
最初から入っている色調と同じ識別子で保存すれば上書きでき，
storage側のファイルを消せば元に戻ります．

サーバの管理者は，このファイルを直接置いたり，
別のサイトへ複製したりすることができます．

*ファイルの形式
JSONです．

 (code)
 {
     "order": 100,
     "names": {"en": "deep sea", "ja": "深い海"},
     "colors": {
         "THEME_COLOR_BACKGROUND": "#0b1b2b",
         "THEME_COLOR_TEXT": "#e6eef7"
     }
 }

|項目|内容|h
|order|最初から入っている色調を並べる順．小さいほど先(10〜60)．保存した色調はこれに関わらず新しい順に上に出る|
|names|言語ごとの表示名．その言語の名前が無ければ英語，それも無ければファイル名が使われる|
|colors|色．名前は''THEME_COLOR_''で始まり，値は''#rrggbb''形式|

colorsに書かなかった色は使われません．
画面から保存すると常に25色すべてが書かれるので，
手で作るときは保存したファイルを複製して書き換えるのが確実です．
*/

/**
@manual $manualpage$/ja/Administration/Analyzer

&title アクセス解析の設定
このページはWebサーバーの管理者でOSの操作に慣れている方を対象としています．

NextFormではWebサーバーのアクセスログを集計することで，
[[アクセスカウンター:../../Wiki/Function/counter]]や[[人気のページ:../../Wiki/Function/popularpages]]
の機能を実現しています．
そのため，これらの機能を使用する場合は，
一定の間隔でアクセスログを集計するスクリプトを実行させる必要があります．

*集計スクリプト

集計するスクリプトは以下のように使用します．
 $ php <install dir>/app/tool/analyze_weblog <path to index.php> <URL> <path to resume file> <log file>
:<install dir>|NextFormをインストールしたディレクトリ
:<path to index.php>|サイトのindex.phpへのパス(すなわちサイトの設定ファイル)
:<URL>|サイトのURL
:{<path to resume file>|再開情報ファイルへのパス．
存在している必要はありませんが，このファイルを作成，書き込みできる権限必要です．
このファイルはどのアクセスログをどこまで集計済みなのかが記録されています．
消してしまったり，別のファイルを指定して集計すると二重カウントになる恐れがあります．}
:{<log file>|Webサーバーのアクセスログへのパス．
現在対応している形式はcommon, combinedとこれらの先頭にバーチャルホストのホスト名をつけた形式です．
再開情報ファイルをもとに前回集計した箇所まで読み飛ばして集計を行いますので同じログファイルに対して何度実行されても
二重カウントにはなりません．
ログファイルは''必ず相対パス，絶対パスどちらか一方をで指定して使用して下さい．''
このスクリプトはパスが異なると違うログファイルと認識して，二重カウントしてしまいます．
前回の集計と比べてinode番号が変わっていたり，ファイルサイズが小さくなっている場合はログがローテーションされたと認識し，
ファイルの最初から集計を行います．
もし二重カウントされてしまう場合はログのローテーションのタイミングで再開情報ファイルを削除するとうまくいく可能性があります．
}
スクリプトは''NextFormのディレクトリへの書き込み権限とアクセスログの読み込み権限を持ったユーザー''で実行して下さい．

アクセスログが残っている場合に限りますが，もし二重カウントしてしまった場合は
 $ php <install dir>/app/tool/analyze_weblog <path to index.php> <URL> <path to resume file> --delete-all
を実行するとすべての集計結果と再開情報ファイルが削除されますので，最初から再集計を行うことができます．

*スクリプトを一定の間隔で実行させる

自動で実行させる前に手動でコマンドを実行し，問題がないか確認しておくことをおすすめします．

例えばcronを使用して10分間隔で実行する場合，crontabに以下のような設定をします(ユーザーの権限に注意)．
 # NextFormアクセスログ集計
 $comment_end$10 * * * * php /var/www/nextform/app/tool/analyze_weblog /var/www/html/index.php http://example.jp/wiki/ /var/www/nextform-resume.txt /var/log/httpd/access_log >/dev/null 2>&1

*集計の結果
集計の結果は，''管理ツール'' -> ''アクセス解析''で確認できます．
*/

/**
@manual $manualpage$/en/Administration/Analyzer

&title Access analysis settings
This page is aimed at the administrator of the web server, someone at home with
operating the OS.

NextForm builds the
[[access counter:../../Wiki/Function/counter]] and
[[popular pages:../../Wiki/Function/popularpages]]
features by totalling up the access log of the web server.
To use these features you therefore have to run a script that totals up the access log
at a regular interval.

*The totalling script

The script that does the totalling is used as follows.
 $ php <install dir>/app/tool/analyze_weblog <path to index.php> <URL> <path to resume file> <log file>
:<install dir>|the directory NextForm was installed in
:<path to index.php>|the path to the index.php of the site (that is, the settings file of the site)
:<URL>|the URL of the site
:{<path to resume file>|the path to the resume file.
It does not have to exist already, but you need the rights to create and write it.
This file records which access log has been totalled up to where.
Removing it, or totalling up while naming a different file, risks counting twice.}
:{<log file>|the path to the access log of the web server.
The formats supported at present are common and combined, and those two with the host
name of a virtual host in front.
Totalling skips ahead to where the last run finished, based on the resume file, so
running it many times against the same log file does not count twice.
''Always name the log file by either a relative path or an absolute path, consistently.''
This script treats a different path as a different log file and counts twice.
When the inode number has changed since the last run, or the file has become smaller,
it takes the log to have been rotated and totals from the start of the file.
If it does count twice, removing the resume file at the moment the log rotates may
put it right.
}
Run the script ''as a user who has the right to write into the NextForm directory and
to read the access log''.

Only while the access log is still there, if it has counted twice, running
 $ php <install dir>/app/tool/analyze_weblog <path to index.php> <URL> <path to resume file> --delete-all
removes every total and the resume file, so that you can total again from the start.

*Running the script at a regular interval

Before running it automatically, we recommend running the command by hand and
checking that nothing is wrong.

To run it every 10 minutes with cron, for example, set up crontab like this
(mind the rights of the user).
 # NextForm access log totalling
 $comment_end$10 * * * * php /var/www/nextform/app/tool/analyze_weblog /var/www/html/index.php http://example.jp/wiki/ /var/www/nextform-resume.txt /var/log/httpd/access_log >/dev/null 2>&1

*The results
The results can be seen at ''Admin tools'' -> ''Access analysis''.

/**
@manual $manualpage$/ja/Markdown/Basic
&title Markdown記法の基本要素

Markdownの土台([[CommonMark:https://spec.commonmark.org/]])の範囲の書き方です．
表や脚注などの拡張は[[拡張要素:../Extra]]に，
ページへのリンクと画像は[[リンク・画像・添付:../Link]]にあります．

*段落と改行
空行で区切ると別の段落になります．
段落の中でソースを改行しても，表示は改行されません(語の区切りとして扱われます)．
段落を分けずに表示も改行したいときは，行末に''半角スペースを2つ''置くか，
''バックスラッシュ''を1つ書きます．

*見出し
行頭に ""#"" と半角スペースを書きます．""#"" の数(1〜6個)がそのまま見出しの深さになります．

 # 一番大きい見出し
 ## 二番目の見出し
 ### 三番目の見出し

行の''下''に ""==="" の行を書くと1段目，""---"" の行を書くと2段目の見出しになる，
別の書き方もあります．文のすぐ下の行にうっかり ""---"" を書くと，
区切り線ではなくその文が見出しになるので注意してください．

Wiki記法の節と違い，Markdown記法の見出しは折りたたみを持たず，範囲も持ちません．
本文の一部をたたみたいときは[[折りたたみ:../Extra#折りたたみ]]で囲んでください．

*強調
|書き方|出るもの|h
|""**重要**""|太字|
|""*強調*""|斜体|
|""***重要かつ強調***""|太字の斜体|

アスタリスクの代わりにアンダースコア(""__重要__"" ""_強調_"")でも同じです．

*文中のコード
""$bq$"" で囲むと文中のコード(等幅の文字)になります．
コードの中に ""$bq$"" 自体を書きたいときは ""$bq$$bq$"" で囲みます．

*箇条書き
行頭に ""- "" を書きます．項目の頭を半角スペース2つ下げると入れ子になります．

 - 項目
 - 項目
   - 入れ子の項目

数字と ""."" で始めると番号つきになります．
最初の数字が開始番号になり，2つ目からの番号は表示のときに振り直されます．

 1. 番号つきの項目
 2. 番号つきの項目

1つの項目に複数の段落やコードブロックを入れたいときは，
空行を挟んで項目の字下げに合わせて続けます．

項目と項目のあいだに空行を挟んでも，箇条書きは''分かれません''．
前後は1つの箇条書きのままです([[CommonMark:https://spec.commonmark.org/]]の決まりです)．
2つに分けたいときは，片方の記号を変えてください．

 - ハイフンの箇条書き
 * アスタリスクの箇条書き

見た目も変わりません．空行があってもなくても項目の間隔は同じです．

*引用
行頭に ""> "" を書きます．""> > "" と重ねると引用の中の引用になります．

 > 吾輩は猫である。
 > 名前はまだ無い。

*コードブロック
""$bq$$bq$$bq$"" だけの行で囲むと，中身が書いたとおり(改行も含めて)表示されます．
開始の行に続けて言語名を書けます(例: ""$bq$$bq$$bq$php"")．
言語名はソースに意味を添えるだけで，
[[対応表:../../Comparison]]にあるとおり色分けはされません．

 $bq$$bq$$bq$
 int func(int a) {
     return a * 2;
 }
 $bq$$bq$$bq$

""~~~"" の行で囲んでも同じです(中身に ""$bq$$bq$$bq$"" を書きたいときに使えます)．
行頭を半角スペース4つで下げる書き方もあります(囲みは要りません)．

*区切り線
""---"" ""***"" ""___"" のいずれかだけの行は区切り線になります．
文の直後の行に書くと[[見出しの下線:.#見出し]]と解釈されるので，前に空行を置いてください．
文書の''先頭''の ""---"" は[[フロントマター:../FrontMatter]]の始まりとして扱われます．

*エスケープ
記号を記法としてではなくそのまま表示したいときは，記号の前にバックスラッシュを書きます．

 \*強調ではなくアスタリスクを表示\*

*文字の参照
ソースに &&copy; のようなHTMLの文字参照を書くと，その文字(この例では©)になります．
*/

/**
@manual $manualpage$/ja/Markdown/Extra
&title Markdown記法の拡張要素

[[CommonMark:https://commonmark.org/]]の土台に加えて，
[[GitHub Flavored Markdown:https://github.github.com/gfm/]]の拡張
(表・打ち消し線・チェックボックス・自動リンク)と脚注が使えます．
GitHubやObsidianで通じる書き方は，おおむねそのまま通じます．
折りたたみだけはNextForm独自の書き方です．

*表
""|"" でセルを区切って，1行に表の1行分を書きます．
1行目がヘッダになり，2行目には ""---"" を並べた区切りの行を書きます．

 | 品名 | 値段 |
 | --- | --- |
 | りんご | 120円 |
 | みかん | 80円 |

区切りの行にコロンを添えると，列ごとに揃える向きを指定できます．

 | 左揃え | 中央揃え | 右揃え |
 | :--- | :---: | ---: |

セルの中では強調や文中のコードなどの記法が使えます．
Wiki記法の表と違い，セルの結合はできません．
保存のときに桁をそろえる整形も行われません(ソースは書いたとおりに残ります)．

*打ち消し
""~~"" で囲むと打ち消し線が引かれます．

 ~~これは違いました~~

*チェックボックス
箇条書きの項目を ""[ ]"" か ""[x]"" で始めるとチェックボックスになります．

 - [ ] まだの項目
 - [x] 済んだ項目

表示されるチェックボックスは見るためだけのもので，画面から付け外しはできません．
変えるにはソースを編集します．

*脚注
本文に ""[^1]"" のような印を書き，別の行に ""[^1]: 中身"" を書きます．
脚注はページの末尾にまとめて表示され，本文との行き来のリンクが付きます．

 むかしむかし[^1]あるところに．
 
 [^1]: 具体的な年代は分かっていない．

印は数字でなくても構いません(""[^note]"" など)．表示は通し番号になります．

*自動リンク
URLをそのまま書くとリンクになります．""www."" で始まる語もリンクになります．
""<"" と "">"" でURLを囲んで書くこともできます．

*折りたたみ
コロン3つに続けて ""details"" と書いた行から，コロン3つだけの行までが
折りたたみになります．""details"" の後ろに書いた文字が，たたまれているときの
見出しになります．

 :::details 詳しい手順
 中身はふつうのMarkdownです．見出しでも表でも書けます．
 :::

既定では閉じた状態で表示されます．最初から開いておくには，
""details"" の直後に ""+"" を付けるか，""open"" と書きます．どちらも同じ意味です．

 :::details+ 最初から開いている
 中身
 :::

 :::details open 最初から開いている
 中身
 :::

見出しを ""open"" という語で始めたいときは，""+"" のほうを使ってください．

 :::details+ open な話
 中身
 :::

入れ子にするときは，外側のコロンを増やします．
閉じるコロンは，開いたときと同じ数以上でなければなりません．
閉じ忘れたときは，ページの終わりで閉じられます．

 ::::details 外側
 :::details 内側
 中身
 :::
 ::::

見出しの文字に記法は効きません(そのままの文字として表示されます)．
""details"" 以外の語(""note"" など)を書いても折りたたみにはなりません．

この書き方はNextForm独自のもので，Markdownの標準ではありません．
他のツールに貼り付けると，コロンの行が文字として見えます(中身は残ります)．
またブラウザの「ページ内検索」は，閉じている中身を見つけられません
(サイトの検索には中身も載ります)．印刷でも閉じたまま印刷されます．

*記法の例
コロン3つに続けて ""example"" と書いた行から，コロン3つだけの行までが，
「ソース」と「表示」を並べた形になります．
記法の説明を書くときに，同じ原文を2度書かなくて済みます．

 :::example
 - 項目
 - 項目
 :::

「ソース」には書いたとおりの文字が，「表示」にはそれを変換した結果が出ます．
中身はふつうのMarkdownです．表でもコードブロックでも書けます．
コードブロックの中にコロン3つを書いても，そこでは閉じません．

入れ子にするときは，外側のコロンを増やします．
閉じるコロンは，開いたときと同じ数以上でなければなりません．
閉じ忘れたときは，ページの終わりで閉じられます．

 ::::example
 :::example
 中身
 :::
 ::::

折りたたみと違い，""example"" の後ろに文字は書けません．
""exampleX"" のように続けて書いた場合は，囲みになりません．

引用や箇条書きの中にも書けます．そのときも，
""> "" や字下げが「ソース」側に混ざることはありません．

この書き方はNextForm独自のもので，Markdownの標準ではありません．
Wiki記法の[[&&wikiexample:../../Wiki/Function/wikiexample]]に当たります．

*生のHTML
既定では，Markdownの中に書いたHTMLはHTMLとして解釈されず，そのまま文字として表示されます．
編集できる人が誰でもスクリプトを埋め込める状態を避けるためです．
サイトの設定([[MARKDOWN_ALLOW_HTML:../../Administration/Settings]])で解釈させることもできます．
また，""javascript:"" などの危険なURLへのリンクは，設定によらず作られません．
*/

/**
@manual $manualpage$/ja/Markdown/Link
&title Markdown記法のリンク・画像・添付

*ページへのリンク
&[&[ と &]&] で囲むと，このサイトの中のページへのリンクになります．

|書き方|意味|h
|""[[ページ名]]""|そのページへのリンク|
|&[&[ページ名&|表示名&]&]|表示名を変えたリンク|
|""[[../隣のページ]]""|相対指定([[相対ページ名:../..#相対ページ名]]と同じ解決)|
|""[[ページ名#見出し]]""|そのページの見出しへのリンク|

Wiki記法と違い，&[&[ &]&] の中は''対象が先，表示名が後''です．
ObsidianやMediaWikiと同じ並びに合わせてあります．

存在しないページへのリンクは，Wiki記法と同じく色を変えて示されます．
見出しの位置の決め方は種別をまたいで同じなので，
種別wikiのページの見出しにも ""[[ページ名#見出し]]"" で届きます．

同じページの中の見出しへは ""[表示名](#見出し)"" でも届きます．
見出しの文字をそのまま書くほか，GitHubの形(英字を小文字にし，空白を ""-"" にしたもの．
""[概要](#getting-started)"" など)でも見つけます．
空白を含む見出しの文字をそのまま書くときは ""[表示名](<#見出し 1>)"" のように囲みます．
どの見出しにも当たらない ""#"" はそのまま残るので，脚注などへのリンクは変わりません．

表の中でも ""[[ページ名|表示名]]"" はそのまま書けます．
間の ""|"" が表の区切りとして読まれることはありません
(Markdownの決まりどおり ""\|"" と書いてもかまいません)．

*外部リンク
""[表示名](URL)"" で外部サイトへのリンクになります．
URLをそのまま書いても[[リンクになります:../Extra#自動リンク]]．

同じURLに何度もリンクするときは，URLを本文から離して書く参照の形式も使えます．

 本文は[こちら][ref]を見てください．
 
 [ref]: https://example.com/

*画像と添付
""![説明](ファイル名)"" は，まずそのページの子ページとして探します．
添付はページの子ページとして保存されるので，
''添付''でアップロードしたファイル名をそのまま書けば埋め込めます．

子ページに無ければ，Wiki記法と同じ規則でページ名として解決します
(''./'' や ''../'' で始めれば相対指定，そうでなければトップからの名前)．
まだ無いファイルを指した場合は，作りに行けるようリンクになります．

URLを書けば外部の画像もそのまま表示します．

""[表示名](ファイル名)"" と書くと，埋め込まずに添付へのリンクになります．
行き先の探し方は ""![説明](ファイル名)"" と同じです．
""[表示名](../隣のページ)"" や ""[表示名](../隣のページ#見出し)"" のように，
ページへのリンクにも使えます．
""?"" ""/"" ""#"" で始まるものと ""?"" を含むものは，URLとしてそのまま扱います．
*/

/**
@manual $manualpage$/ja/Markdown/FrontMatter
&title フロントマター

文書の先頭を ""---"" の行で囲んだ部分はメタ情報(フロントマター)として扱われ，
本文には表示されません．
ObsidianやNotionから持ってきた文章に付いていても，そのまま貼り付けられます．

 ---
 title: 会議メモ
 tags: [議事録, 打合せ]
 ---

NextFormが読むのは ""title:"" と ""tags:"" です．
他の項目が書いてあっても，そのままソースに残るだけで害はありません．

*題名
""title:"" を書くと，それがそのページの題名になります．
Wiki記法の &&title{} と同じで，ページ名とは別に表示される名前です．

*タグ
""tags:"" を書くと，それがそのページのタグになります．
''タグ''の画面で付けるものと同じもので，タグ一覧にも出ます．
書き方は次のどれでもかまいません．

 tags: [議事録, 打合せ]
 tags: 議事録, 打合せ
 tags: 議事録 打合せ
 tags:
   - 議事録
   - 打合せ

タグは半角スペースで区切って保存されるので，''タグ自体に空白は入れられません''．
「議事録 2026」と書くと2個のタグになります．

*書いていないものは消えます
題名とタグは，''フロントマターに書いてあるとおり''になります．
""title:"" を消して保存すれば題名も消え，""tags:"" を消して保存すればタグも消えます．
''メタ情報''や''タグ''の画面で付けた値も，次に本文を保存したときに置き換わります．
ソースを見ればページの状態が分かるようにするためです．

Wiki記法の [[&&title{}:../../Wiki/Function/title]] も同じ約束です．
*/

@manual $manualpage$/en/Markdown
&title Markdown notation

*Overview
Pages of type Markdown are written in [[Markdown:https://commonmark.org/]].
NextForm follows [[CommonMark:https://spec.commonmark.org/]] and also supports
extensions such as tables and strikethrough
([[GitHub Flavored Markdown:https://github.github.com/gfm/]]) and footnotes.
Unless you choose otherwise when creating a page, the type will be Markdown.

Text written in another tool (Obsidian or Notion, for example) can be pasted in
as it is and will look much the same.

(In a hurry? Go [[here:./CheatSheet]])

*Guides to writing
-[[Markdown Cheat Sheet>./CheatSheet]]
-[[Basic elements>./Basic]] (headings, emphasis, lists, quotes, code and so on)
-[[Extra elements>./Extra]] (tables, checkboxes, footnotes, folding and so on)
-[[Links, images and attachments>./Link]] (links to pages and embedding files)
-[[Front matter>./FrontMatter]] (the metadata at the top; title and tags)

How the same things are written in Wiki notation is collected in
[[Wiki notation and Markdown notation:../Comparison]].

*How to edit
''Double click a part of the page to edit just that part.''
The units you can edit are paragraphs, headings, list items, tables, code blocks,
quotes and folds.
Double clicking a heading edits ''the whole section'' (up to the next heading of the
same or a shallower level).
Alt and click works instead of a double click.

Unlike Wiki notation, you cannot edit a part of a line (emphasis or strikethrough on
its own) or a single row of a table. A table is one unit as a whole.

Another way is to click ''Edit'' in the ''page menu'', which lets you edit the source
of the whole page.
Press ''Preview'' on the editing screen to check the converted result before saving.
The editing screen also links to the cheat sheet.

*When to use it
Types Markdown and wiki are both first-class ways of writing.
You can use Markdown notation for documents meant to be read, and Wiki notation for
"living pages" that use [[functions:../Wiki/Function]] (embedding page lists,
calendars and so on).
Functions cannot be used in pages of type Markdown.
For what can and cannot be written, see
[[Wiki notation and Markdown notation:../Comparison]].
*/

/**
@manual $manualpage$/en/Markdown/Basic
&title Basic elements of Markdown notation

These are the ways of writing that belong to the base of Markdown
([[CommonMark:https://spec.commonmark.org/]]).
Extensions such as tables and footnotes are in [[Extra elements:../Extra]], and
links to pages and images are in [[Links, images and attachments:../Link]].

*Paragraphs and line breaks
An empty line separates paragraphs.
A line break inside a paragraph does not appear in the output
(it is treated as a separator between words).
To break the line without starting a new paragraph, put ''two spaces'' at the end of
the line, or write a single ''backslash''.

*Headings
Write ""#"" and a space at the start of the line.
The number of ""#"" (from one to six) is the depth of the heading.

 # the largest heading
 ## the second heading
 ### the third heading

There is another way to write them: a line of ""==="" ''below'' the text makes a first
level heading, and a line of ""---"" makes a second level heading.
Take care not to write ""---"" on the line right below a sentence by accident:
it turns that sentence into a heading instead of drawing a horizontal rule.

Unlike sections in Wiki notation, headings in Markdown notation cannot be folded and
do not span a range. To fold part of the text, wrap it in a
[[folding block:../Extra#Folding]].

*Emphasis
|notation|result|h
|""**strong**""|bold|
|""*emphasis*""|italic|
|""***strong and emphasized***""|bold italic|

Underscores work the same as asterisks (""__strong__"", ""_emphasis_"").

*Code in a sentence
Surround text with ""$bq$"" to make code inside a sentence (a fixed width font).
To put a ""$bq$"" itself inside the code, surround it with ""$bq$$bq$"".

*Lists
Write ""- "" at the start of the line.
Indenting an item by two spaces nests it.

 - item
 - item
   - nested item

Starting with a number and ""."" makes a numbered list.
The first number is the number the list starts from, and the rest are renumbered
when the page is shown.

 1. numbered item
 2. numbered item

To put several paragraphs or a code block into one item, leave an empty line and
continue at the indent of the item.

An empty line between items does ''not'' split the list.
What is above and below it stays one list ([[CommonMark:https://spec.commonmark.org/]]
defines it this way). To split it in two, change the marker of one of them.

 - a list with hyphens
 * a list with asterisks

The look does not change either. Items are spaced the same with or without the
empty line.

*Quotes
Write ""> "" at the start of the line.
Repeating it as ""> > "" makes a quote inside a quote.

 > It was the best of times,
 > it was the worst of times.

*Code blocks
Lines of ""$bq$$bq$$bq$"" around the text show it exactly as written, line breaks and all.
A language name can follow the opening line (""$bq$$bq$$bq$php"", for example).
The language name only records what the source is; as the
[[comparison table:../../Comparison]] notes, it is not coloured.

 $bq$$bq$$bq$
 int func(int a) {
     return a * 2;
 }
 $bq$$bq$$bq$

Lines of ""~~~"" work the same way (useful when the text itself contains ""$bq$$bq$$bq$"").
Indenting the lines by four spaces also makes a code block, with no fence.

*Horizontal rules
A line consisting only of ""---"", ""***"" or ""___"" becomes a horizontal rule.
Written right after a sentence it is read as [[the underline of a heading:.#Headings]],
so leave an empty line before it.
A ""---"" at the very ''top'' of the document starts the
[[front matter:../FrontMatter]] instead.

*Escaping
To show a symbol as itself rather than as notation,
write a backslash before the symbol.

 \*asterisks, not emphasis\*

*Character references
An HTML character reference such as &&copy; written in the source becomes that
character (© in this example).
*/

/**
@manual $manualpage$/en/Markdown/Extra
&title Extra elements of Markdown notation

On top of the base of [[CommonMark:https://commonmark.org/]] you can use the extensions
of [[GitHub Flavored Markdown:https://github.github.com/gfm/]]
(tables, strikethrough, checkboxes and automatic links) and footnotes.
Ways of writing that work on GitHub or in Obsidian mostly work here too.
Only the folding notation is specific to NextForm.

*Tables
Separate the cells with ""|"" and write one row of the table per line.
The first row is the header, and the second must be a separator row of ""---"".

 | item | price |
 | --- | --- |
 | apple | 1.20 |
 | orange | 0.80 |

Adding a colon to the separator row sets how each column is aligned.

 | left | center | right |
 | :--- | :---: | ---: |

Notation such as emphasis and code in a sentence can be used inside cells.
Unlike tables in Wiki notation, cells cannot be merged.
The columns are not lined up when the page is saved either
(the source stays exactly as you wrote it).

*Strikethrough
Surrounding text with ""~~"" strikes it out.

 ~~that was wrong~~

*Checkboxes
Starting a list item with ""[ ]"" or ""[x]"" makes a checkbox.

 - [ ] item still to do
 - [x] item that is done

The checkbox that is shown is only there to be read; it cannot be ticked from the
screen. Edit the source to change it.

*Footnotes
Write a mark such as ""[^1]"" in the text and ""[^1]: the note"" on a line of its own.
Footnotes are shown together at the foot of the page, with links back and forth.

 Once upon a time[^1] there was.
 
 [^1]: The exact date is not known.

The mark does not have to be a number (""[^note]"" works too).
What is shown is a running number.

*Automatic links
A URL written as it is becomes a link. So does a word starting with ""www."".
You can also surround a URL with ""<"" and "">"".

*Folding
A line of three colons followed by ""details"", down to a line of three colons on
its own, becomes a folded block. What you write after ""details"" is the heading
shown while it is folded.

 :::details The detailed steps
 The contents are ordinary Markdown. Headings and tables work too.
 :::

It is shown folded by default. To have it open from the start, put ""+"" right
after ""details"", or write ""open"". The two mean the same thing.

 :::details+ open from the start
 contents
 :::

 :::details open open from the start
 contents
 :::

Use the ""+"" form when the heading itself has to start with the word ""open"".

 :::details+ open questions
 contents
 :::

To nest them, add colons to the outer one. The closing colons must be at least as
many as the opening ones. If you forget to close it, it is closed at the end of
the page.

 ::::details outer
 :::details inner
 contents
 :::
 ::::

Notation does not apply inside the heading; it is shown as plain characters.
A word other than ""details"" (""note"", for instance) does not fold anything.

This notation is specific to NextForm and is not part of standard Markdown.
Pasted into another tool, the colon lines show up as text (the contents remain).
The browser's own find-in-page cannot find contents that are folded away
(the site search does index them). Printing keeps them folded as well.

*Notation examples
A line of three colons followed by ""example"", down to a line of three colons
alone, becomes a pair of ''Source'' and ''Display''. It saves writing the same
text twice when you explain a notation.

 :::example
 - item
 - item
 :::

''Source'' shows the characters exactly as written, ''Display'' shows the result of
converting them. The contents are ordinary Markdown; tables and code blocks work.
Three colons inside a code block do not close it.

To nest them, add colons to the outer one. The closing colons must be at least as
many as the opening ones. If you forget to close it, it is closed at the end of
the page.

 ::::example
 :::example
 contents
 :::
 ::::

Unlike folding, nothing can be written after ""example"".
Written as ""exampleX"", it is not treated as a block at all.

It also works inside a quote or a list. The ""> "" and the indent do not leak
into the ''Source'' side.

This notation is specific to NextForm and is not part of standard Markdown.
It corresponds to [[&&wikiexample:../../Wiki/Function/wikiexample]] in Wiki notation.

*Raw HTML
By default, HTML written inside Markdown is not interpreted as HTML and is shown as
plain characters. This avoids a state in which anyone who can edit can embed a script.
It can be interpreted through the site setting
([[MARKDOWN_ALLOW_HTML:../../Administration/Settings]]).
Links to dangerous URLs such as ""javascript:"" are never created, whatever the setting.
*/

/**
@manual $manualpage$/en/Markdown/Link
&title Links, images and attachments in Markdown notation

*Links to pages
Surrounding a name with &[&[ and &]&] makes a link to a page inside this site.

|notation|meaning|h
|""[[page name]]""|a link to that page|
|&[&[page name&|display name&]&]|a link with a different display name|
|""[[../the next page]]""|a relative name (resolved as [[relative page names:../..#Relative page names]] are)|
|""[[page name#heading]]""|a link to a heading in that page|

Unlike Wiki notation, what comes first inside &[&[ &]&] is ''the target, and the
display name comes second''. This matches the order used by Obsidian and MediaWiki.

A link to a page that does not exist is shown in a different colour,
just as in Wiki notation.
Positions of headings are decided the same way whatever the type of the page, so
""[[page name#heading]]"" reaches headings in pages of type wiki as well.

A heading in the same page can also be reached with ""[display name](#heading)"".
Besides the text of the heading as it is, the GitHub form (letters in lower case and
spaces turned into ""-"", as in ""[Overview](#getting-started)"") is found as well.
To write the text of a heading that contains spaces as it is, enclose it as in
""[display name](<#heading 1>)"".
A ""#"" that matches no heading is left as it is, so links to footnotes and the like
do not change.

""[[page name|display name]]"" can be written as it is inside a table as well.
The ""|"" in it is not read as a cell separator
(writing ""\|"", as Markdown requires, also works).

*External links
""[display name](URL)"" makes a link to an external site.
A URL written as it is [[also becomes a link:../Extra#Automatic links]].

When you link to the same URL many times, you can also write the URL away from the
text, in the reference form.

 See [here][ref] for details.
 
 [ref]: https://example.com/

*Images and attachments
""![description](file name)"" first looks for a child page of the current page.
Attachments are saved as child pages, so writing the name of a file uploaded through
''Attach'' embeds it.

If there is no such child page, the name is resolved as a page name by the same rules
as Wiki notation (starting with ''./'' or ''../'' makes it relative, otherwise it is
a name from the top).
Pointing at a file that does not exist yet makes a link, so that it can be created.

Writing a URL shows an external image as it is.

Writing ""[display name](file name)"" makes a link to the attachment instead of
embedding it. The target is looked up in the same way as for ""![description](file name)"".
It also links to pages, as in ""[display name](../the next page)"" or
""[display name](../the next page#heading)"".
Anything that starts with ""?"", ""/"" or ""#"", or that contains ""?"", is treated
as a URL as it is.
*/

/**
@manual $manualpage$/en/Markdown/FrontMatter
&title Front matter

A part at the very top of the document surrounded by lines of ""---"" is treated as
metadata (the front matter) and is not shown in the text.
Text brought over from Obsidian or Notion can be pasted in with it still attached.

 ---
 title: Meeting notes
 tags: [minutes, meeting]
 ---

What NextForm reads is ""title:"" and ""tags:"".
Other entries do no harm; they simply stay in the source.

*Title
Writing ""title:"" makes it the title of the page.
It works like &&title{} in Wiki notation: a name shown separately from the page name.

*Tags
Writing ""tags:"" makes them the tags of the page.
They are the same tags you set from the ''Tag'' screen, and they appear in the tag list.
Any of the following ways of writing them will do.

 tags: [minutes, meeting]
 tags: minutes, meeting
 tags: minutes meeting
 tags:
   - minutes
   - meeting

Tags are saved separated by spaces, so ''a tag cannot contain a space''.
Writing "minutes 2026" gives two tags.

*What is not written is removed
The title and the tags become ''exactly what the front matter says''.
Remove ""title:"" and save, and the title is removed too;
remove ""tags:"" and save, and the tags are removed.
Values set from the ''Meta information'' or ''Tag'' screens are replaced the next time
the text is saved.
This is so that the state of a page can be seen from its source.

The same promise applies to
[[&&title{}:../../Wiki/Function/title]] in Wiki notation.

&title Wiki notation and Markdown notation

Pages of type wiki and pages of type Markdown are both first-class ways of writing.
You can use Wiki notation for "living pages" that use functions, and Markdown notation
for documents meant to be read.
This page puts the two side by side, showing how the same thing is written in each.

Each notation is described in [[Markdown notation:../Markdown]] and
[[About Wiki notation:../Wiki]].

*Things that carry over directly
|what you want|Wiki notation|Markdown notation|h
|paragraph|insert an empty line|insert an empty line|
|strong|&'&'strong&'&'|""**strong**""|
|emphasis|&'&'&'emphasis&'&'&'|""*emphasis*""|
|strikeout|&%&%strikeout&%&%|""~~strikeout~~""|
|list (unordered)|&- item|""- item""|
|list (ordered)|&+ item|""1. item""|
|quote|&>quoted text|""> quoted text""|
|preformatted text|a space at the start of the line|surround with ""$bq$$bq$$bq$""|
|horizontal rule|&=&=&=&=|""---""|
|link to a page|&[&[display name:page name&]&]|&[&[page name&|display name&]&]|
|external link|&[&[display name:URL&]&]|""[display name](URL)""|
|page title|&&title{title}|""title:"" in the front matter|
|table (basic)|&|cell1&|cell2&||&|cell1&|cell2&||
|notation example (source and display side by side)|&&wikiexample{target}|wrap it in "":::example"" and "":::""|

The order inside &[&[ &]&] is ''the other way round''.
Wiki notation puts the display name first, Markdown notation puts the target first.

*Things that mean the same but work differently
|what you want|Wiki notation|Markdown notation|difference|h
|heading|&* heading|""# heading""|A section in Wiki notation ''spans a range'', up to the next section. A heading in Markdown notation spans no range|
|folding|&*(optional)|wrap it in "":::details heading""|Wiki notation folds a ''section'' (it is put on the heading, so the range runs to the end of the section). Markdown notation folds ''the range you wrapped''|
|marking the end of a section|&*(end)|none|as above|
|unit of partial editing|down to a part of a line or a table row|paragraph, heading (section), list item, table, code block, quote|Both are edited by double clicking. Markdown notation cannot take a part of a line or a single table row|
|empty line inside a list|the list ''ends'' there|it does not end; it stays one list|In Wiki notation an empty line is how you split a list in two. In Markdown notation you change the marker of one of them (""- "" and ""* ""). In both notations the spacing between items is the same with or without the empty line|
|description list|&:item&|description|none|In Markdown notation use a list or a table instead|
|table formatting|h f c l r n and so on at the end of the row|column alignment in the separator row|All you can set in Markdown notation is the column alignment|
|merging table cells|&< &> &^ &_|none|Markdown notation cannot merge cells|
|lining up table columns|done automatically when saved|not done|The source in Markdown notation stays exactly as written|
|highlighting code|(code) after the leading space|""$bq$$bq$$bq$php""|Wiki notation colours the code. Markdown notation only records the language name; it is not coloured|
|checkbox|none|""- [ ] item""|Only Markdown notation has this|
|footnote|none|""text[^1]"" and ""[^1]: the note""|as above|

A link to a heading, &[&[page name#heading&]&], reaches the same place
whatever the type of the page.

*Things Markdown notation cannot write
Functions of Wiki notation cannot be used in pages of type Markdown.
Create a page of type wiki when you want to do any of the following.

|what you want|Wiki notation|h
|pulling in another page|&&include|
|lists of pages|&&pages &&index &&subpage|

Wiki notation is a notation for writing structured and decorated text easily.

-[[Functions>./Function]]

Double clicking replaces just that part with its source and lets you edit it.
For a list, double clicking switches to a display in which items can be removed or

of the whole page.

@manual $manualpage$/en/Wiki/Basic
&title Basic elements
*Ordinary text
Write ordinary characters in the source and the wiki engine shows them as they are.
A line break in the source means no more than a single space, though.

&wikiexample{
Some text
and a second line in the source..
}

*Paragraph
Text separated by an empty line is treated as a separate paragraph.

&wikiexample{
Some text

and an empty line in the source...
}

*URL
A URL written as it is appears as a link.

&wikiexample{The NextForm site is at `OFFICIAL_URL`.}

*Strong
Surrounding text with &'&' and &'&' marks it as strongly important.
Use it for the important parts of a piece of writing.

&wikiexample{... this article is ''about cooking''. ...}

*Emphasis
Surrounding text with &'&'&' and &'&'&' emphasizes it.
Use it for the part of a sentence you want to stand out.

&wikiexample{I like '''Japanese food'''.}

*Strikeout
Surrounding text with &%&% and &%&% strikes it out.

&wikiexample{%%Good morning%%Good evening}

*Link
Text surrounded by &[&[ and &]&] becomes a link to another page.
Writing &[&[Cooking/Japanese&]&] makes a link to the page ''Cooking/Japanese''.
Writing &[&[the food I like:Cooking/Japanese&]&] also links to ''Cooking/Japanese'',
but the link is shown as ''the food I like''.
The separator can be &| or &> or &>&> as well as &:.
Separating with &>&> makes a link that opens in a new window (tab).
The page name can be a [[relative page name:../..#Relative page names]]
using ''.'' or ''..''.
Adding ''#heading name'' after the page name links to a section within that page.
A URL can be written instead of a page name.
Use [[&&link:../Function/link]] when you want to build a link with finer control.

&wikiexample{
[[Cooking/Japanese]]
[[the food I like:Cooking/Japanese]]
[[../Italian]]
[[$manualpage$/en#Backup]]
[[NextForm official page:`OFFICIAL_URL`]]
}

*Comment
Characters from where &/&/ is written to the end of the line are ignored.
A part surrounded by &/&* and &*&/ (several lines allowed) is ignored in the same way.
Use this to put notes in the source.

&wikiexample{
Good moring //fix the spelling later
$comment_begin$
Text we do not want shown yet
but want to keep
$comment_end$
}

*Line break
Writing &~ at the end of a line breaks the line.
In ordinary writing, though, you should not break lines just to tidy the look or to
make it easier to read.
If the break carries meaning, we recommend inserting an empty line and separating it
as a paragraph instead.
And when you want to show text with its line breaks exactly as they are, we recommend
[[preformatted text:../LineHead#Preformatted text]].
To break a line somewhere other than the end of a line, you can write &&br; instead.

*Symbols
To show a symbol used by Wiki notation as it is, put && in front of it.
For example, write &&/&&/ to show &/&/ as it is, and &&&& to show && as it is.

HTML character entity references and numeric character references can be used,
such as &&copy; &&nbsp; and &&#9834;.

The following emoticons can also be used.
|notation|shown|hlc
|&&heart;|&heart;|
|&&smile;|&smile;|
|&&bigsmile;|&bigsmile;|
|&&huh;|&huh;|
|&&oh;|&oh;|
|&&wink;|&wink;|
|&&sad;|&sad;|
|&&worried;|&worried;|

*Showing text as it is
To show symbols as they are across a long stretch of text, surround the range with
&"&" (two double quotes) and &"&".
The range surrounded that way is not read as Wiki notation and is shown as it is.
To do the same across several lines, use [[&&plain:../Function/plain]].

&wikiexample{
""when you use many symbols of Wiki notation such as & or [[, surrounding them with two double quotes shows them as they are""
}

&title 行頭記法

*行頭記法の基本
ソースの行頭に決められた記号を書くことで特別な意味になります．基本的な書き方は以下のようになります．
 記号 対象となる文
例えば行頭の''&-(マイナス)''記号は箇条書きを意味し，箇条書きを作るには以下のようにします．
 - パスタ
対象となる文が複数行になる場合は
 記号{
 対象となる文1
 対象となる文2
 }
のように&{と&}で囲んで記述します．&{と&}の中でもWiki記法が使えます．例えば以下のように記述します．
 -{パスタは
 おいしい}
例外として&{が先にあっても行頭記法と解釈されます．例えば上の例は以下のようにも書けます．
 {-パスタは
 おいしい}

行頭記法の記号のすぐ後に&(と&)で囲まれた部分があると特別な指定と解釈されます．
記号のすぐ後に&(を記述した場合は記号の後にスペースを入れてから&(を記述して下さい．

*節
行頭に&*を書くと節の始まりになります．&*のあとに文をかくとそれが節の見出しになります．
節は次の節かページの終わりに到達するまで続いていると解釈されます．
&*&*のように&*を複数続けて書くことで節の中の節を作ることもできます．&*の数に制限はありません．

もし節の終わりを明示したい場合は終わらせたい節の深さに対応した分だけ行頭から&*を書き，その直後に''(end)''と書きます．
また&*の直後に''(optional)''と書くと折りたたまれた状態で表示されます．

&wikiexample{
*パスタの作り方について
**材料
材料は...
***生地の材料
生地の材料は..
***ソースの材料
ソースの材料は..
*(optional)ちょっとひと工夫
ごにょごにょするとおいしくなります．
}

*箇条書き
行頭に&-または&+を書くと箇条書きになります．&-は順序に依存しない箇条書き，&+は順序に意味のある箇条書きになります．
空行をいれずにこれらを続けることでひとまとまりの箇条書きとして扱われます．
&-と&+は混在させることもできます．
どちらも記号を連続して書くことで入れ子になった箇条書き(箇条書きの中の箇条書き)を表現できます．
入れ子の深さに制限はありません．

&-または&+の直後に''(optional)''と書くと折りたたまれた状態で表示されます．

&wikiexample{
-食材
--肉
---牛肉
---豚肉
--野菜
---キャベツ
---にんじん

+下ごしらえ
++以下の材料をきざむ
---キャベツ
---にんじん
+ソースを作る
++{フライパンに火を付け
油をひく そして複数行にわたり...}
++きざんだ材料をいれる
}

*関連リスト
ある項目とその項目の説明のような，対応関係を列挙したもの(関連リスト)を記述できます．
関連リストを記述するには行頭に&:を書きます．
その後に項目と説明を書きます．項目と説明は&|で区切ります．
空行をいれずにこれらを続けることでひとまとまりの関連リストとして扱われます．

&wikiexample{
:包丁|包丁とは調理をするための刃物である．
:{おたま|
おたまとは．．．
複数行にわたる場合は:のあとに{と}を書きます．
}
}

*整形済みテキスト
行頭に半角スペースを書くと，半角スペース以降に書いたものが改行も含めそのまま表示されます．
テキストをそのまま表示させたいときに便利です．
編集画面で整形済みテキストにしたい範囲を選択し''引用''のボタンを2回押すと簡単に整形済みテキストが作成できます．
プログラム言語等を書く場合は最初の行で半角スペースに続いて(code)と書くとハイライト機能が有効になります．
詳細な使い方は[[&&pre:../Function/pre]]のページを参考にして下さい．

&wikiexample{
 あいうえお
 かきくけこ

 (code)
 int func(int a) {
     return a * 2;
 }
}

*引用

行頭に&>を書くと他の情報源から引用されたテキストとして表示されます．
空行をいれずにこれらを続けることでひとまとまりの引用として扱われます．
編集画面で引用にしたい範囲を選択し''引用''のボタンを押すと引用を素早く作成できます．

&wikiexample{
>吾輩は猫である。
>名前はまだ無い。
}

*区切り線
行頭から4つ以上の&=を書くと区切り線になります．

&wikiexample{
====
}

*数値計算
行頭に&=をひとつだけ書き，続けて式を書くとその式の計算結果に置き換わります．
式の最後に&=を書くと結果を置き換えずに数式と結果の両方を表示します．
数式内の&[と&]で囲まれた部分は無視されます．
&=の直後に&(を書く場合はスペースを入れて下さい．

[[数値計算の詳細>../Calc]]ページも参照して下さい．

&wikiexample{
= (1 + 2) * 3 ^ 2 / 4
= sin(pi/4) + cos(pi/4) + log(2 & 1024) =
= 1,000[ml] * 20[本] / 1000[L換算] = [L]
}

*表
行頭に&|を書くと表になります．ソースでの1行がテーブルの1行になります．
行中でさらに&|で区切ることでテーブルの列を記述できます．

|文字|効果                                            |h
|h   |その行をヘッダーにする                          |
|f   |その行をフッターにする                          |
|c   |そのセルを中央揃えにする                        |
|l   |そのセルを左揃えにする                          |

またセルの記述の中に &^ &_ &< &> だけを記述することで
それぞれ上下左右のセルと結合ができます．

セルの先頭に&~を書くとそのセルは見出しのセルとして扱われます．
セルの先頭に&=を書くと式を書くことができ，表計算をすることができます．

&title Line head notation

*The basics of line head notation
Writing a set symbol at the start of a line in the source gives that line a special
meaning. The basic form is
 symbol the text it applies to
For example ''&-(minus)'' at the start of a line means a list, so a list is made
like this:
 - pasta
When the text it applies to runs over several lines, surround it with &{ and &}:
 symbol{
 first line of the text
 second line of the text
 }
Wiki notation can be used inside &{ and &} as well. For example:
 -{pasta is
 delicious}
As an exception, a &{ that comes first is still read as line head notation.
The example above can therefore also be written:
 {-pasta is
 delicious}

A part surrounded by &( and &) right after the symbol of a line head notation is read
as a special setting.
When you write &( right after the symbol, put a space before the &(.

*Sections
Writing &* at the start of a line begins a section.
Text after the &* becomes the heading of that section.
A section is read as continuing until the next section or the end of the page.
Writing several &* in a row, as in &*&*, makes a section inside a section.
There is no limit to the number of &*.

To mark the end of a section, write as many &* from the start of the line as the depth
of the section you want to end, and write ''(end)'' right after them.
Writing ''(optional)'' right after the &* shows the section folded.

&wikiexample{
*How to make pasta
**Ingredients
The ingredients are...
***Ingredients for the dough
The dough needs..
***Ingredients for the sauce
The sauce needs..
*(optional)One small extra touch
A little fiddling makes it taste better.
}

*Lists
Writing &- or &+ at the start of a line makes a list.
&- makes a list whose order carries no meaning, &+ a list whose order does.
Continuing them without an empty line makes them one list.
&- and &+ can be mixed.
Writing the symbol several times in a row expresses a nested list
(a list inside a list). There is no limit to the depth.

Writing ''(optional)'' right after the &- or &+ shows the list folded.

&wikiexample{
-Ingredients
--Meat
---Beef
---Pork
--Vegetables
---Cabbage
---Carrot

+Preparation
++Chop the following
---Cabbage
---Carrot
+Make the sauce
++{Heat the frying pan
and add oil, over several lines...}
++Add the chopped ingredients
}

*Description lists
You can write a list of pairs, such as an item and its description
(a description list).
To write one, put &: at the start of the line.
Then write the item and the description, separated by &|.
Continuing them without an empty line makes them one description list.

&wikiexample{
:knife|A knife is a blade used for cooking.
:{ladle|
A ladle is...
When it runs over several lines, write { and } after the :.
}
}

*Preformatted text
Writing a space at the start of a line shows everything after that space exactly as
written, line breaks included.
It is handy when you want text shown as it is.
On the editing screen, select the range you want as preformatted text and press the
''Quote'' button twice to make preformatted text quickly.
When writing a programming language, write (code) after the space on the first line
to turn on highlighting.
See the [[&&pre:../Function/pre]] page for how to use it in detail.

&wikiexample{
 abcde
 fghij

 (code)
 int func(int a) {
     return a * 2;
 }
}

*Quotes

Writing &> at the start of a line shows the text as quoted from another source.
Continuing them without an empty line makes them one quote.
On the editing screen, select the range you want quoted and press the ''Quote'' button
to make a quote quickly.

&wikiexample{
>It was the best of times,
>it was the worst of times.
}

*Horizontal rules
Writing four or more &= from the start of a line makes a horizontal rule.

&wikiexample{
====
}

*Calculation
Writing a single &= at the start of a line, followed by an expression, replaces it with
the result of that expression.
Writing &= at the end of the expression shows both the expression and the result
instead of replacing it.
A part surrounded by &[ and &] inside an expression is ignored.
When you write &( right after the &=, put a space before it.

See the [[details of calculation>../Calc]] page as well.

&wikiexample{
= (1 + 2) * 3 ^ 2 / 4
= sin(pi/4) + cos(pi/4) + log(2 & 1024) =
= 1,000[ml] * 20[bottles] / 1000[to L] = [L]
}

*Tables
Writing &| at the start of a line makes a table.
One line in the source is one row of the table.
Separating further with &| within the line writes the columns of the table.
Write a &| after the last column as well.

Listing the following characters ''after the &| at the end of the row'' sets the format
of the cells. Writing them several times sets the cells in order from the left
(except for h and f).
With nothing set, a cell follows the format of the cell before it or of the row.

|character|effect                                                    |h
|h        |make the row a header                                     |
|f        |make the row a footer                                     |
|c        |centre the cell                                           |
|l        |align the cell left                                       |
|r        |align the cell right                                      |
|n        |clear centre, left and right alignment                     |
|#        |highlight the background of the cell                      |
|&=       |clear the background highlight                            |
|%        |highlight the text of the cell                            |
|/        |clear the text highlight                                  |
|&,       |show the expression in the cell with thousands separators  |
|.        |clear the thousands separators                            |
|w        |set the width of the cell, written as w100 or w14em        |
|e        |set the height of the cell, written as e100 or e14em       |
Width and height can be cleared by writing ''w'' or ''e'' on their own.

Writing only &^ &_ &< or &> inside a cell merges it with the cell above, below,
to the left or to the right.

Writing &~ at the start of a cell makes that cell a heading cell.
Writing &= at the start of a cell lets you write an expression, giving you a
spreadsheet. See [[details of calculation>../Calc]].

Even when the &| are out of line in the source, the columns are lined up when the page
is saved, so the table is easy to read in the source too.

Clicking a header (a row formatted with h) while reading sorts the table freely.

&wikiexample{
|ingredient   |amount   |price     |h,
|cabbage      |quarter  |=100      |lcr
|carrot       |half     |=50       |
|good tomatoes|<        |=1200     |
|salt         |a pinch  |unknown   |%/
|pepper       |a pinch  |=10       |/
|love         |plenty   |=100000000|#
|total        |<        |=sum(up)  |f=
}

Making a column in the header or footer of the form
''@item name/choice1/choice2/...@'' shows the choices when a cell in that column is
double clicked to be edited.

*Tables in CSV form
Writing &, at the start of a line and CSV data after it shows the CSV data as a table.

&wikiexample{
,apple,1.00
,"orange, mandarin",2.00
}
*/

&title Functions
*The basics of functions
A notation called function notation is provided for using more involved features.
Function notation is written in one of the following forms.

 &function name(parameters) the target..

 &function name(parameters) the target..; text after it that is not the target

 &function name(parameters) { target 1
 target 2
 target 3..
 }

The function name is the fixed name given to each feature.
The parameters are additional instructions to that feature.
The target is the text and so on that the feature applies to.

For example [[&&color:./color]] is the function that changes the colour of text.
It is used like this:

&wikiexample{Now I write &color(red){text in red}.}

Here color is the function name, red is the parameter and "text in red" is the target.
The end of the target can also be marked with a &; symbol or with a line break,
as follows.

 Now I write &color(red)text in red;.

 Now I write &color(red)text in red
 here.

A function can also be used inside another function or inside other Wiki notation.
[[&&size:./size]] is the function that changes the size of text.

&wikiexample{
- &color(green)a list item in green
&size(150%) { &color(blue) { big blue text }}
}

**Parameters
The &( and &) can be left out along with the parameters.
When there are several parameters, separate them with a &, symbol.
How the parameters are written differs from feature to feature, but as a rule they
follow the patterns below.
:a particular English word|turn an additional feature on
:!a particular English word|turn an additional feature off
:a particular English word=value|set a value
:&[&[page name&]&]|name the page to act on
:a number|set an amount

**(optional)Marking the target with repeated braces
The target can also be surrounded by runs of ''&{&{&{'' and ''&}&}&}'' symbols
(any number of them, as long as the two runs match).
Written that way, the target works as expected even when it contains
''&{ symbols'' or ''&} symbols''.

&wikiexample{{{{{
&color(green) {{{{green text with a brace } in it.}}}}
}}}}}

The following functions are available.
&include([[../CheatSheet/Function]]);
*The functions (advanced)
There are also functions with more involved features, as follows.
&include([[../CheatSheet/FunctionAdvanced]]);

&title エクスポート機能

NextFormにはNextFormで作成したページをhtmlファイル,画像ファイル,cssファイル等に書き出し，
静的コンテンツのサイトを構築できる機能があります．
これをエクスポート機能と呼びます．

エクスポート機能を用いるとサイトの内容やデザイン，サイトを管理する画面を[[Wiki記法:../Wiki]]で管理することができます．
大げさに表現するならばNextFormはCMS(Content Management System)自体を構築，管理できるCMSMSであるといえます．
すなわち，サイトの管理者がサイトの編集者に必要最低限のCMSや，親切な説明を加えたCMSを簡単に提供することができます．

*有効化

エクスポート機能はデフォルトでは無効になっています．
使用する場合はindex.phpに
 define('EXPORT_ENABLE', 'true');
を追記します．(index.phpについては[[サイトの高度な設定:../Administration#サイトの高度な設定]]参照)

またエクスポート機能を使用できるのは管理者かエクスポートの権限を与えられたユーザーのみです．

*基本的な設定
エクスポート機能を使用するにはどのページをどのファイルに書き出すかを設定する必要があります．
この設定をするには好きなページに[[Wiki記法の表:../Wiki/LineHead#表]]を用いて設定表を書きます．
設定表は1列目にページへのリンク, 2列目に書き出すファイル名を書きます．
例えばWiki記法で
 |ページ名          |ファイル名   |h
 |[[トップページ]]  |index.html   |
 |[[スタイルシート]]|css/style.css|
のように書きます．ヘッダ行(上記の例では1行目)は無視されますので省略しても，お好みのヘッダにしても構いません．

設定表を書いたら，表でリンクにしたページを作成しておいて下さい．
htmlファイルにしたいページは種別wikiのページで，その他のページは種別textか種別fileのページで作成するのがおすすめです．

次にこの設定にしたがって実際にファイルの書き出しを行うためのボタンを作成します．
このボタンを作成するには
 &export;
と書きます．これは先ほどの設定表の上でも下でも構いませんし，別のページ書いても構いません．
ただし，別のページに書いた場合は
 &export([[設定表のあるページ]]);
と書いてください．
&&export;のより高度な使用方法は[[こちら:../Wiki/Function/export]]を参照して下さい．
これでボタンが作成され，押せば実際にファイルの書き出し(エクスポート)が行われます．

ファイルは設定表の2列目に設定したファイル名で，
[[設定項目:../Administration/Settings]]の''EXPORT_DIR_PATH''
で設定されているディレクトリの下に保存されます．
このディレクトリに対してWebサーバーの設定を行い，公開することでhtmlファイル等で構成された静的なサイトが構築できます．
もしNextFormを設置したWebサーバーとは別のWebサーバーにあるコンテンツを管理したい場合は[[エクスポート後の処理:.#エクスポート後の処理]]を参照して下さい．

*テンプレート
上記の例ではindex.htmlとcss/style.cssというファイルを書き出しましたが，
index.htmlはcss/style.cssをスタイルとして使用するようにはなっていないためcss/style.cssが無意味になってしまいます．
この問題は，エクスポート用のテンプレートを設定することで解決できます．
テンプレートを使用するには設定表の3列目を作成し，テンプレートになるページへのリンクを書きます．例えば
 |ページ名          |ファイル名   |テンプレート              |h
 |[[トップページ]]  |index.html   |[[通常ページテンプレート]]|
 |[[スタイルシート]]|css/style.css|                          |
のように書きます．設定表にテンプレートを書いたらテンプレートを作成します．
テンプレートになるページは種別textか種別fileにして下さい．
例えば以下のような内容にします．
 (code)
 <!DOCTYPE html>
 <html>
   <head>
     <meta charset="UTF-8">
     <title>$title$</title>
     <link rel="stylesheet" type="text/css" href="./css/style.css"/>
   </head>
   <body>
     $contents$
   </body>
 </html>
このようなテンプレートを設定しエクスポートをすると，index.htmlにはテンプレートの内容が書き出されますが，
テンプレート内の$title$の部分がページ名になり，
$contents$の部分が設定表の1列目で指定したページの内容になります．

設定表の3列目，すなわちテンプレートの欄に何も書かなければ1列目の内容がそのまま書き出されます．

エクスポート機能でのテンプレートとWiki記法の[[&&pages:../Wiki/Function/pages]]や[[&&writepage:../Wiki/Function/writepage]]でのテンプレートは異なるものです．注意して下さい．

**テンプレートの書き方
上記の$title$や$contents$のようにテンプレート内で特定のキーワードを書けば別の内容に置き換わります．
キーワードには以下のようなものがあります．

:$title$|ページ名または[[&&title:../Wiki/Function/title]]で設定されたタイトル
:$contents$|ページの内容
:{$&[&[ページ名&]&]$|ページ名で指定したページの内容に置き換えます．
ページ名はテンプレートのページから見た[[相対的な名前:..#相対ページ名]]でも構いません．
}
:{$mtime$|ページの更新日時
 $mtime?format=%Y/%m/%d$
のように書くことで任意のフォーマットにできます．
フォーマットは[[strftimeのフォーマット:http://php.net/manual/ja/function.strftime.php]]に従います．
}
:$btime$|ページの作成日時 (フォーマットの指定は$mtime$と同様)
:$exporttime$|エクスポートした日時 (フォーマットの指定は$mtime$と同様)
:{$tags$|ページのタグ一覧を表示します．
 $tags?list=[[ページ名]]$
上のように書くことでタグのリンク先を指定できます．
ページ名には[[&&pages:../Wiki/Function/pages]]等でページの一覧表示を行っているページを指定します．
こうすることでこのタグをクリックした先はページ一覧のうちこのタグを持っているものに限定されます．
さらに
 $tags?list=[[ページ名]]&prefix=この記事は&sep=と&suffix=のタグを持っています$
のようにタグがあった場合に前に表示する内容，後に表示する内容，タグの区切り文字を指定できます．
} 

*複数のページに対する設定
複数のページをエクスポートする際にすべてのページとファイル名の対応を設定表に書く必要はありません．
設定表の1列目に書かれたページから別のページにリンクがある場合，リンクされているページもエクスポートされます．
同様にリンクされているページからさらにリンクされているページもエクスポートされます．
すなわち設定表に書かれたページからリンクでたどることのできるページはすべてエクスポートされます．

このようにリンクによって派生的にエクスポートされるページには，
書き出すファイル名やテンプレートが設定されていません．
この場合はファイル名やテンプレートは自動で決定されますが，設定表で明示することもできます．例えば以下のように設定します．
 |ページ名          |ファイル名       |テンプレート              |h
 |[[トップページ]]  |index.html       |[[通常ページテンプレート]]|
 |[[スタイルシート]]|css/style.css    |                          |
 |ブログ/&*         |                 |[[ブログ用テンプレート]]  |
 |type=wiki         |                 |[[通常ページテンプレート]]|
 |&*.jpg            |images/$basename$|                          |

設定表の1列目にページへのリンクではなくページ名のパターンをワイルドカードを用いて指定できます．
このパターンと一致するページはこの行を設定として使用します．
''Wiki記法で&*や&/&*や&*&/は見出しやコメントの意味になってしまうので&*の前に&&記号をつけてエスケープする必要があるので注意して下さい．''
上記の設定表の例では''ブログ''というページの子ページはすべて''ブログ用テンプレート''というテンプレートして使用し，ファイル名は空欄なので自動で決定するように設定されています．

同じく設定表の1列目に
 type=ファイル種別
の形式でページ種別を指定することもできます．上記の設定表の例では種別wikiのページはすべて''通常ページテンプレート''をテンプレートして使用するように設定されています．

設定表の1列目の条件は上から順に検査され，最初に一致した行を設定として使用します．

設定表の2列目には書き出すファイル名を書きますが，特定のキーワードを書けばページに応じたファイル名を設定できます．
キーワードには以下のようなものがあります．

:$id$|自動で決定された他のページと重複しない英数字の羅列になります．
:$basename$|ページ名のうち最後の/(スラッシュ)より後ろの部分になります．
:$extension$|ページ名をファイル名とみなしたときの拡張子の部分になります．ドットも含みます．
:$filename$|$basename$のうち拡張子に相当する部分を除いたものになります．
:{$args$|ひとつのページに複数のバリエーションがある時
([[&&pages:../Wiki/Function/pages]]のcontentsパラメータを使用した際に一覧が複数ページにまたがる時や，
一覧を特定のタグで限定できるとき)
にそのバリエーションを一意に識別する英数字列に置き換わります．}

*エクスポート後の処理
エクスポートを行った後にUNIXコマンドを実行することができます．
実行するコマンドは[[設定項目:../Administration/Settings]]の''EXPORT_POST_COMMAND''で設定できます．
このコマンドはコマンド引数にエクスポート先のディレクトリを渡され，
標準入力から実際にエクスポートされたファイル名をNUL文字('\0')区切りで入力されます．

このコマンドにrsyncやftpコマンドでファイルを送信するスクリプトを設定すれば，
リモートホストにあるWebサーバーのコンテンツを管理することができます．

''コマンドに入力される文字列はNextFormのサイトで自由に編集できる文字列であることに注意して下さい．''

コマンドは0以外のステータスで終了することでエラー扱いになります．

例えばエクスポートの結果をログとして残すシェルスクリプトは以下のようになります．
 (code)
 #!/bin/bash
 dir="$1"
 log() {
     local time
     time=$(date '+%F %T')
     echo "$time: $1" >> log.txt
 }
 log "start export $dir"
 while read -d $'\0' file; do
     log "export $file"
 done
 log "end export $dir"
 exit 0

*エクスポート先の切替え
ひとつの設定表に対してエクスポート行うボタンを複数作成しても構いません．
[[&&export:../Wiki/Function/export]]のdirectoryパラメータを用いると，
同じコンテンツを異なるディレクトリにエクスポートできます．
例えば以下のように書きます．
 &export(directory=test, label=テスト環境へエクスポート);
 &export(directory=real, label=本番環境へエクスポート);
これはテスト環境と本番環境のディレクトリ(testとreal)を用意し，それぞれに対してボタンを作成しています．
テスト環境でエクスポート結果を確認した後で本番環境に反映させるといったような使い方ができます．
*/

/**
@manual $manualpage$/en/Export
&title Export function

NextForm can write out the pages you made with it as HTML files, image files, CSS files
and so on, letting you build a site of static content.
This is called the export function.

With the export function you can manage the contents and the design of a site, and the
screens that administer it, in [[Wiki notation:../Wiki]].
Put grandly, NextForm is a CMSMS that can build and manage a CMS (Content Management
System) itself. That is, the administrator of a site can easily hand the editors of the
site a minimal CMS, or a CMS with helpful explanations added.

*Enabling it

The export function is disabled by default.
To use it, add
 define('EXPORT_ENABLE', 'true');
to index.php. (For index.php see
[[advanced site settings:../Administration#Advanced site settings]].)

Only an administrator, or a user granted the export right, can use the export function.

*Basic setup
To use the export function you have to set which page is written out to which file.
To do so, write a setup table on any page you like, using a
[[table in Wiki notation:../Wiki/LineHead#Tables]].
The setup table has a link to the page in the first column and the name of the file to
write in the second column.
In Wiki notation, write something like
 |page name       |file name    |h
 |[[Top page]]    |index.html   |
 |[[Style sheet]] |css/style.css|
The header row (the first row above) is ignored, so you may leave it out or make it
whatever you like.

Once the setup table is written, create the pages you made into links in the table.
We recommend making the pages you want as HTML files pages of type wiki, and the
other pages of type text or type file.

Next, make a button that actually writes the files out following this setup.
To make this button, write
 &export;
This may go above or below the setup table, or on another page entirely.
When it is on another page, though, write
 &export([[the page with the setup table]]);
For more advanced ways of using &&export;, see
[[here:../Wiki/Function/export]].
That makes the button, and pressing it actually writes the files out (exports them).

The files are saved under the name set in the second column of the setup table, in the
directory set by ''EXPORT_DIR_PATH'' in the [[settings:../Administration/Settings]].
Configuring the web server for that directory and publishing it builds a static site
made of HTML files and so on.
To manage content on a web server other than the one NextForm is installed on, see
[[what happens after an export:.#What happens after an export]].

*Templates
The example above wrote out the files index.html and css/style.css, but index.html was
not made to use css/style.css as its style, so css/style.css is meaningless.
Setting a template for the export solves this.
To use a template, make a third column in the setup table and write a link to the page
that is the template. For example
 |page name       |file name    |template                |h
 |[[Top page]]    |index.html   |[[Normal page template]]|
 |[[Style sheet]] |css/style.css|                        |
Once the template is written in the setup table, create the template.
Make the page that is the template type text or type file.
Give it contents such as the following.
 (code)
 <!DOCTYPE html>
 <html>
   <head>
     <meta charset="UTF-8">
     <title>$title$</title>
     <link rel="stylesheet" type="text/css" href="./css/style.css"/>
   </head>
   <body>
     $contents$
   </body>
 </html>
Set a template like this and export, and the contents of the template are written to
index.html, with the $title$ part of the template becoming the page name and the
$contents$ part becoming the contents of the page named in the first column of the
setup table.

Write nothing in the third column, the template column, and the contents of the first
column are written out as they are.

The templates of the export function and the templates of
[[&&pages:../Wiki/Function/pages]] and
[[&&writepage:../Wiki/Function/writepage]] in Wiki notation are different things.
Take care.

**How to write a template
Write a particular keyword in the template, such as the $title$ and $contents$ above,
and it is replaced by something else.
The keywords are as follows.

:$title$|the page name, or the title set by [[&&title:../Wiki/Function/title]]
:$contents$|the contents of the page
:{$&[&[page name&]&]$|replaced by the contents of the page named.
The page name may be a [[relative name:..#Relative page names]] seen from the template
page.
}
:{$mtime$|the time the page was modified
 $mtime?format=%Y/%m/%d$
Written like this it can take any format.
The format follows the
[[strftime format:http://php.net/manual/en/function.strftime.php]].
}
:$btime$|the time the page was created (the format is set as for $mtime$)
:$exporttime$|the time of the export (the format is set as for $mtime$)
:{$tags$|shows the list of tags of the page.
 $tags?list=[[page name]]$
Written as above it sets where the tags link to.
Name a page that lists pages with [[&&pages:../Wiki/Function/pages]] or the like.
Clicking a tag then leads to the page list narrowed to those carrying that tag.
Furthermore
 $tags?list=[[page name]]&prefix=This article has the tags &sep= and &suffix=.$
sets what is shown before the tags, what is shown after them, and the separator
between them, when there are any tags.
}

*Settings for several pages
When exporting several pages you do not have to write every page and file name into the
setup table.
When a page named in the first column of the setup table links to another page, the
linked page is exported too.
Likewise pages linked from those linked pages are exported.
That is, every page that can be reached by following links from the pages in the setup
table is exported.

Pages exported as a knock-on effect of a link like this have no file name or template
set for them.
The file name and template are then decided automatically, but they can also be stated
in the setup table. For example:
 |page name       |file name        |template                |h
 |[[Top page]]    |index.html       |[[Normal page template]]|
 |[[Style sheet]] |css/style.css    |                        |
 |Blog/&*         |                 |[[Blog template]]       |
 |type=wiki       |                 |[[Normal page template]]|
 |&*.jpg          |images/$basename$|                        |

The first column of the setup table can name a pattern of page names using wildcards,
instead of a link to a page.
Pages matching the pattern use that row as their setup.
''Note that &* and &/&* and &*&/ mean a heading or a comment in Wiki notation, so the
&* has to be escaped by putting an && in front of it.''
In the example above, every child page of the page ''Blog'' uses the template
''Blog template'', and the file name is blank so it is decided automatically.

The first column of the setup table can also name a page type, in the form
 type=page type
In the example above every page of type wiki uses ''Normal page template''.

The conditions in the first column are checked from the top down, and the first row
that matches is used as the setup.

The second column of the setup table holds the name of the file to write, and writing
particular keywords there sets a file name that follows the page.
The keywords are as follows.

:$id$|a run of letters and digits, decided automatically, that no other page shares.
:$basename$|the part of the page name after the last / (slash).
:$extension$|the extension of the page name taken as a file name. The dot is included.
:$filename$|$basename$ with the part that is the extension removed.
:{$args$|replaced by a run of letters and digits that uniquely identifies a variation,
when one page has several of them
(when a list runs over several pages because the contents parameter of
[[&&pages:../Wiki/Function/pages]] is used, or when a list can be narrowed to a
particular tag).}

*What happens after an export
A UNIX command can be run after an export.
The command to run is set by ''EXPORT_POST_COMMAND'' in the
[[settings:../Administration/Settings]].
The command is passed the directory exported to as a command argument, and the names of
the files actually exported are fed to its standard input, separated by NUL
characters ('\0').

Set this command to a script that sends the files with rsync or ftp and you can manage
the content of a web server on a remote host.

''Note that the strings fed to the command are strings that can be edited freely on the
NextForm site.''

The command is treated as having failed when it exits with a status other than 0.

For example, a shell script that keeps a log of the export looks like this.
 (code)
 #!/bin/bash
 dir="$1"
 log() {
     local time
     time=$(date '+%F %T')
     echo "$time: $1" >> log.txt
 }
 log "start export $dir"
 while read -d $'\0' file; do
     log "export $file"
 done
 log "end export $dir"
 exit 0

*Switching where you export to
You may make several buttons that export against one setup table.
The directory parameter of [[&&export:../Wiki/Function/export]] lets you export the
same content to different directories.
For example, write:
 &export(directory=test, label=Export to the test environment);
 &export(directory=real, label=Export to the live environment);
This prepares directories for a test environment and a live environment (test and real)
and makes a button for each.
You can use it to check the result of an export in the test environment before
reflecting it in the live one.
*/
