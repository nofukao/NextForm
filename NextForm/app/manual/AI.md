# AI が NextForm のページを読み書きする手順

AI (Claude Code など) が、NextForm のサイトのページを一覧する・読む・新しく書く・
書き直すための手順。

NextForm のサイトには、ページを読み書きするコマンドラインの道具 `app/tool/page` が
入っている (**NextForm 0.17.0 以降**)。ページはこの道具だけで扱う。Web の画面を
操作したり、`storage/` のファイルを直に読み書きしたりしない。

道具はサイトのサーバーの上で動かす。サイトが手元に無ければ、**サイトのサーバーに
SSH で入れることが前提**。SSH で入れないサイトには、この手順では書けない。

道具の詳しい説明は NextForm のリポジトリの `docs/page-tool.md`。

## この手順の受け取り方

人は AI に、たとえば次のように頼む。

> https://〈サイト〉/?〈ページ名〉 に○○を書いてください。書き方は
> https://〈サイト〉/?NextFormManual/AI を読んでください。
> サーバーには SSH の別名 〈別名〉 でつながります。

- この手順は、サイトの組み込みマニュアル `?NextFormManual/AI` にある (NextForm 0.20.0 以降)。
  サイトの NextForm と一緒に新しくなるので、そのサイトの版に合った手順が読める。
- Web の読み込みが要約して、細部 (コマンドの引用符など) が落ちることがある。そのときは
  本文をそのまま取る。`curl -s 'https://〈サイト〉/?NextFormManual/AI&action=source'` の
  `<pre>` の中身が本文 (`&lt;` `&gt;` `&amp;` `&quot;` を元の文字に戻す)。
- ログインしないと読めないサイトでは、§1 で接続先を決めてから、SSH の先で
  `read NextFormManual/AI --user <書き手> --body` を使う (§3。`--user` を省くと
  ログインしていない人として読むので断られる)。
- 何度も使うなら、AI の手元に入れておける。Claude Code ではプラグイン
  (`/plugin marketplace add nofukao/NextForm` → `/plugin install nextform@nextform`。
  明示して呼ぶときは `/nextform:nextform-pages`)。ほかの AI ツールでは、この手順を
  `SKILL.md` としてスキルのフォルダーに写す (NextForm の README)。**入れるかどうかは
  利用者が決める。** 手元に入れたものは自動では新しくならない。

## 1. 接続先を決める (推測しない)

**ページ名**は、依頼にページの URL があればそこから取る。URL は `〈サイトの URL〉?〈ページ名〉`
の形で、ページ名は `?` のあとから最初の `&` (無ければ `#`) の手前まで。`/` で区切った
1 つずつが URL エンコードされている (`+` は空白)。それを戻す。

```
https://〈サイト〉/?%E4%BD%9C%E6%A5%AD%E8%A8%98%E9%8C%B2/2026-10  →  作業記録/2026-10
```

短縮 URL (`?option=shorturl&key=...`) にはページ名が入っていないので、利用者に聞く。

URL からは、サイトのサーバーの場所はわからない。次の値は**利用者に聞くか、
利用者が示す台帳 (ファイルなど) から読む**。名前の似たものから推測したり、
サーバーの中を探し回ったりしない。

| 値 | 例 (形だけ) |
|---|---|
| サイトが手元か、SSH の先か。SSH なら**別名** (`~/.ssh/config` の Host) | `wiki-server` |
| サイトの `index.php` の場所 | `/var/www/html/wiki/index.php` |
| サイトの所有者 (`index.php` の所有者) | `apache` |
| 書き手の名前 (`--user`)。NextForm の利用者の名前 | `editor` |

道具は `<サイト>/app/tool/page`。サイトの所有者として動かす。所有者が自分でなければ
`sudo -n -u <所有者>` を付ける (`-n` はパスワードを求められたら待たずに失敗させる)。

```bash
# 手元
sudo -n -u <所有者> php <サイト>/app/tool/page <サイト>/index.php <操作> [引数..]

# SSH の先
ssh -o BatchMode=yes <別名> \
    "sudo -n -u <所有者> php <サイト>/app/tool/page <サイト>/index.php <操作> '<ページ名>' [引数..]"
```

SSH の先のシェルはコマンドをもう一度読むので、ページ名は**内側の単一引用符**で囲む。
ページ名に単一引用符が入るときは、利用者に相談する。

最初に道具があることを確かめる。`users` が JSON を返せばよい。道具が無い
(`Could not open input file`) なら、サイトの NextForm が 0.17.0 より前なので、
利用者に伝えて止まる。

## 2. 守ること

- **SSH**
  - `ssh -o BatchMode=yes <別名>` でつなぐ。パスワードや確認を求められたら失敗させる。
  - ホスト鍵の確認に答えない。`StrictHostKeyChecking=no` や `accept-new` を使わない。
    初めてつなぐサーバーは、利用者が自分でつないでから頼む。
- **秘密を読まない・出さない**
  - SSH の鍵、パスワード、`index.php` の中身 (`$AUTH_DIGESTS` などの認証情報) を
    読まない。表示しない。`index.php` を `cat` しない。利用者の名前と権限は `users` で見る
    (ダイジェストは出ない)。
- **書く前に承認を得る** (§4)。上書きは特に、はっきり示す。
- root で動かさない (道具も `not_site_owner` で断る)。
- `deploy/scripts/gen-pages.php` (テストデータ用) をページを書くのに使わない。題名が入らない。

## 3. 読む

| 操作 | 使い方 |
|---|---|
| `users` | 利用者の名前と権限。`--user` に使える名前を確かめる |
| `list [<ページ名>] [--user <名前>]` | ページの一覧。ページ名を渡すとそのページと配下だけ |
| `read <ページ名> [--user <名前>]` | meta と本文 (JSON)。`--body` で本文だけをそのまま |

- 出力は JSON。断ったときも JSON で、`error` に理由の語が入る。
- `--user` を省くと、ログインしていない人の権限で読む。読めないページは一覧に出ない。
- **ページがあるかどうかは `read` で確かめる。** Web の URL は無いページでも
  HTTP 200 を返すので、応答コードでは確かめられない。

## 4. 書く

### 原稿の置き場所

原稿は**依頼元のリポジトリ**に Markdown のファイルとして置き、フォルダーの階層を
ページ名にする。

```
docs/wiki/作業記録.md         → ページ 作業記録
docs/wiki/作業記録/2026-10.md → ページ 作業記録/2026-10
```

置き場所 (`docs/wiki/` など) が決まっていなければ、利用者に聞く。

### 手順

1. **`--dry-run` で確かめる。** 何も書かない。

   ```bash
   ssh -o BatchMode=yes <別名> \
       "sudo -n -u <所有者> php <サイト>/app/tool/page <サイト>/index.php \
        write '作業記録/2026-10' --user <書き手> --dry-run" < docs/wiki/作業記録/2026-10.md
   ```

   - `action`: `create` (新しく作る) か `overwrite` (既にあるページを書き換える)
   - `title` / `tags`: 本文から取り出される題名とタグ。`title` が `null` なら、
     一覧と検索にはページ名で出る (§5 の書き方を見直す)
   - `same_body`: 既にあるページと本文が同じか
   - 既にあるページなら、`--overwrite` を付けずに試すと `"error": "exists"` (終了コード 1)
     になる。これで上書きかどうかがわかる

2. **利用者に見せて承認を得る。** 次を並べて見せる。
   - 原稿 (ファイルの場所と中身、または要点)
   - ページ名
   - **新規か上書きか**。上書きなら「既にあるページ『…』を書き換えます。前の版は
     履歴に残ります」のように、はっきり書く。`same_body` が `true` なら、本文は同じで
     meta (題名など) だけが変わることも書く
   - 書き手 (`user`) と権限 (`permission`)
   - 取り出される題名

3. **承認されたものだけを書く。** `--dry-run` を外す。上書きは、承認を得たときだけ
   `--overwrite` を付ける。承認のあとで原稿を変えたら、もう一度 1 から。

4. **書いたあとに `read` で確かめる。** `read <ページ名> --user <書き手> --body` の出力を
   原稿と比べる (`diff`)。改行は LF になる (CR は落ちる) ので、CRLF の原稿とは
   改行だけが違って見える。`read` の JSON の `title` が期待どおりかも見る。
   Web の応答コードでは確かめない。

### 書き込みの決まり (道具が守る)

- 画面から保存したときと同じ扱い。題名とタグは本文から取って meta に入る。
- 既にあるページは `--overwrite` のときだけ書き換える。前の版は必ず履歴に残る
  (Web の履歴の「この版に戻す」で戻せる)。
- 新しいページの種別は `--type` (省くと `markdown`)。既にあるページの種別は変わらない
  (違う `--type` を渡すと `type_mismatch`)。
- 空の本文、UTF-8 でない本文は断る。添付ファイルは書けない (画面の「添付」から付ける)。

## 5. Markdown の書き方

- **題名**: フロントマターの `title:` を書く。無ければ、本文の先頭の `#` 見出しが題名に
  なる (本文に `#` の見出しが 1 つだけのとき。`#` が 2 つ以上あると題名にならない)。

  ```markdown
  ---
  title: 10 月の作業
  tags: [作業記録, サーバー]
  ---

  ## 概要
  ```

- **ページへのリンク**は、ページをフォルダーと見なした URL の規則 (NextForm 0.13.0 以降)。
  標準の Markdown の形 `[表示](行き先)` で書く。**近いページへは相対パス、遠いページへは
  `/` から書く。**

  | 行き先 (`作業記録/2026-10` の中から) | 書き方 |
  |---|---|
  | 子孫 (子 `作業記録/2026-10/子`、孫 `作業記録/2026-10/子/孫`、その下も) | `[表示](./子)`、`[表示](./子/孫)` |
  | 親 `作業記録` | `[表示](..)` |
  | 兄弟 `作業記録/2026-09` とその子孫 `作業記録/2026-09/子` | `[表示](../2026-09)`、`[表示](../2026-09/子)` |
  | それより遠いページ `手順書/バックアップ` | `[表示](/手順書/バックアップ)` (トップの階層から) |

  - 相対パスで使う `..` は 1 つまで。`..` を 2 つ以上重ねることになるページ (祖父母 `../..`、
    親の兄弟 `../../x` など) は `/` から書く。
  - 子孫は `./子`、`./子/孫` のように `./` を付けて書く。`子` だけでも同じ子を指すが、
    Wiki 記法の `[[子]]` はトップの階層を指すので、読む人が取り違えないように付ける。
  - トップの階層のページ (`作業記録` など) には親が無い (`..` はサイトのトップページになる)。
    兄弟とその子孫もトップの階層の別の木なので、`/` から書く (`[表示](/手順書)`、
    `[表示](/手順書/バックアップ)`)。
  - 原稿のフォルダー (`docs/wiki/作業記録/2026-10.md`) から見た相対パスとは、基準が 1 段違う。
    ページ `作業記録/2026-10` から子 (原稿は `docs/wiki/作業記録/2026-10/子.md`) へは
    `./子` で、`./2026-10/子` ではない。兄弟の `作業記録/2026-09` へは `../2026-09` で、
    `./2026-09` ではない (それは子になる)。
  - 空白は `%20` と書く。拡張子 `.md` は付けない。
  - 理由: 「以下の子ページもリネームする」で名前を変えても、「子ページを含む」でクローンしても、
    リンクの文字は書き換わらない。相対パスのリンクは、一緒に動いたページのあいだで
    つながったまま。`/` からのリンクは、書いたページが動いても同じ名前のページを指す
    (クローンなら、クローン先のサイトにある同じ名前のページ)。ページを親の外へ移すと、
    そのページの `..` と `../兄弟` は、移った先の親と兄弟を指す。
- 添付した画像は `![説明](./図.png)` (そのページの子として添付したもの)。
- **図**は言語名 `mermaid` のコードブロックに Mermaid の記法で書く (NextForm 0.18.0 以降。
  それより前の版ではコードのまま出る)。ラベルの HTML は `<b>` `<br>` などの飾りだけが残り、
  `style`・リンク・画像は消える。色は Mermaid の `style` や `classDef` の行で付ける。
  Mermaid の組み込みのアイコン (architecture 図の `database` など) も出ない。

## 6. 終了コード

| 終了コード | 意味 | 主な `error` |
|---|---|---|
| 0 | 成功 (`--dry-run` なら「書ける」) | — |
| 1 | 断った。何も変えていない | `unknown_user` `guest_user` `no_permission` `exists` `locked` `type_mismatch` `not_text` `manual` `interrupted` |
| 2 | 使い方の誤り | `invalid_name` `invalid_type` `empty_body` `invalid_encoding` `not_site_owner` |
| 3 | ページが無い (`read`) | `not_found` |
| 4 | 保存できなかった | `write_failed` (`message` に理由) |

- `unknown_user`: 名前を `users` で確かめる。推測した名前で試し直さない。利用者に聞く。
- `no_permission` `locked`: 権限の問題。利用者に伝えて止まる。
- `interrupted`: 本文が参照するページ (`&mtime([[ページ]])` など) を書き手が読めない。
  `read` で書けたかどうかを確かめ、利用者に伝える。
- `invalid_name`: 先頭・末尾の `/`、`//`、`./`、`../` はページ名に使えない。
