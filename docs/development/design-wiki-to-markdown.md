# 設計メモ: Wiki 記法のページを Markdown に変換する

> **このドキュメントの位置づけ**
> Wiki 記法 (種別 wiki) のページを、1 ページずつ Markdown (種別 markdown) に変換する
> 機能と、そのために Markdown 側に足す 3 つの機能の設計。2026-10-18 に利用者が承認した。
> 決めたことは [project-overview.md](project-overview.md) §7 に移していく。
> このファイルは「なぜその形にしたか」を残すための記録。
>
> 前提として、履歴の「この版に戻す」(`option/restore.inc`) が先に入っている。
> 変換を元に戻すのはそれで行う。

---

## 1. 何を作るか

| 順 | 内容 | ブランチ |
|---|---|---|
| 3a | `![](..)` でページを取り込む。大きさや配置の指定とキャプション | `feat/markdown-embed` |
| 3b | 目次 `[TOC]` と、折りたたみ `:::details` の見出しの働き | `feat/markdown-toc` |
| 3c | 子ページのツリー `[PAGES]` | `feat/markdown-pages` |
| 3d | 3a〜3c で見え方が変わるページを探す道具と、アップグレードの案内 | `feat/markdown-change-check` |
| 3e | 変換器 | `feat/wiki-to-markdown` |

3a〜3c は、変換で落ちていた機能のうち、利用者が必要とした 3 つ
(`&include` のページの取り込み・`&index`・`&treepages`) の Markdown 側の相手。
3e は 3a〜3c を書き出し先に使う。

## 2. 利用者が決めたこと (2026-10-18)

- 見出しは 1 段下げる。`&title` → 本文の先頭の `#`、`*` → `##`、`**` → `###` …
  (Markdown の「本文の先頭の唯一の `#`」は題名になる。v0.10 の規則)
- 変換前の版は**子ページを作らず履歴に残す**。末尾に「このページは、wikiページから
  変換して作りました。[(変換前の版)](その版の URL)」を付ける
- 戻すのは履歴の汎用の「この版に戻す」で行う (変換専用の「戻す」は作らない)
- Markdown で書けない記法: 装飾 (色・大きさ・配置) は中の文字だけ残す。動く機能
  (カレンダー・計算・フォームなど) は原文をコードの枠で残す
- `&include` は `![](..)` に写す。指定は説明の後ろに `|` を付けて書く (Obsidian と同じ形)
- 目次とツリーは `[TOC]` / `[PAGES]` とだけ書いた行が置き換わる形
- 子ページの一覧はツリーの形だけを作る
- 折りたたみの節 `*(optional)` は、`:::details` に見出しの働き (飛び先の id と目次) を
  足して写す
- 3a〜3c で既存の Markdown のページの見え方が変わるので、v0.13 と同じく、探す道具と
  アップグレードの案内を作る
- 他のページがこのページの Wiki 記法に頼っている場合 (親の `&tracker` の表、
  `&blogpages` の抜粋) は検出しない。マニュアルに書く

## 3a. `![](..)` でページの取り込みと指定

### 書き方

```
![説明|指定](対象 "キャプション")
```

- **指定**は `&include` と同じ語: `幅x高さ` (`640x`・`x400`・末尾の `!`)、幅だけの数字
  (`300`。Obsidian の `![説明|300](…)` と同じ)、`拡大率%`、`max`、`!adjust`、`open`、
  `!link`、`left`、`right`。空白かカンマで区切る
- `max` は単独の語ではなく、すぐ後ろの大きさの前置き (`max 640x400`。`image_parse_size()`)
- 説明の**最後の `|` より後ろが、すべて指定として読めるときだけ**指定とみなす。
  読めないときは全体を説明のままにする (説明に `|` を書いた既存のページを壊さない)
- **キャプション**はタイトルの欄。wiki の `&include{...}` と同じく `figure.figure` +
  `figcaption` で出す。`left` / `right` も `figure` に `gravity_left` / `gravity_right`。
  **figure にするのは段落にそれ 1 つだけのとき**。文中で figure を出すと段落が割れる
  (README のバッジの並びが縦に積まれる)。文中のタイトルは今までどおり (外部の画像はヒント)
- 指定もキャプションも無い `![](x.png)` の出力は今のまま (ゴールデンマスターを動かさない)

### 外部の画像

数字で書いた大きさだけを当てる (`640x400!` は幅と高さ、`640x400` は比率を保ったまま
その大きさに収める max-width / max-height、`300` や `x400` は片方だけ。片方ならブラウザが
比率を保つ)。**拡大率と `max` は使わない。** 元の大きさを知るには、サーバーからその URL を取りに行く必要がある
(wiki 記法の `&include` は `getimagesize()` で取りに行っている)。Markdown は今まで
外部の画像を取りに行かなかったので、ページを書く人の指定でサーバーが外へ取りに行く口を
新しく作らない。

### ページの取り込み

- 対象がふつうのページ (wiki / Markdown / text) で、**`![](..)` が段落にそれ 1 つだけ**のとき、
  今はリンクにしているところを取り込みに変える。文の途中はリンクのまま (段落の中に
  ブロックを入れて文を割らない)
- 読めない・無いページは今どおりリンク

### 作り

- 描画の途中で Markdown のページを取り込むと変換器に再入する (`MarkdownConverter` は
  解析中の状態を持ち回す)。そこで、**描画では今と同じリンクを出し、印を付けるだけ**にする。
  変換が終わったあとの DOM の後処理 (`markdown_convert()` の最後) で、印の付いたリンクの
  段落を取り込んだページに置き換える
- 印は要求ごとの乱数の番号 (`data-markdown-embed`)。解決済みのページ名・指定・キャプションは
  PHP 側の表に置き、表に無い印は無視する (`MARKDOWN_ALLOW_HTML` のサイトで、生の HTML で
  印を偽造できないように)。印は 1 度使ったら表から消す
- 権限・存在・ループは展開するときに確かめる (`auth_has_permission()` → `page_read()` の順。
  `page_read()` は権限が無いと画面ごと止まる)。ループの判定は wiki の `&include` と同じ
  `$page['include_pages']`
- `depend_pages` を立てる (書き出しの差分のため)
- 展開は後処理の一番最後。見出しの id・`#` リンクの向け直し・検索語の印が、取り込んだ
  中身に及ばないようにする
- **検索の文字 (`texts`) には取り込んだ中身を入れない。** `markdown_texts()` は描画だけを
  通るので、印の付いたリンクの文字 (今と同じ) だけが入る。索引は保存した人の権限で、
  テキストキャッシュは最初に検索した人の権限で作られるので、入れると読めないページの語で
  検索に当たり、スニペットに中身が出る

## 3b. 目次 `[TOC]` と、折りたたみの見出しの働き

- `:::details 見出し` の見出しにも、wiki と同じ規則 (`page_get_section_id()`) で id を振り、
  目次に載せる。振るのは本文として描くとき (`is_main`) だけ
- 目次での深さは、見出しの先頭に `#` を書いて指定できる (`:::details ### 見出し`)。
  無ければ直前の見出しの 1 段下。変換器は wiki の深さから `#` の数を決めて書く
- 中身が `[TOC]` だけの段落を、ツールの「目次」と同じ形の目次に置き換える。
  プレビューでも保存前の見出しが出るよう、描いている途中の DOM から組み立てる。
  サイドや取り込まれた先でも出す (`&index` と同じ。項目は「ページの URL + `#id`」)。
  検索の文字には出さない

## 3c. 子ページのツリー `[PAGES]`

- 中身が `[PAGES …]` だけの段落を、`&treepages` と同じツリーに置き換える
- 指定: 対象のページ (Markdown のリンクの規則。`/` だけならサイト全体)、
  `sort=mtime|btime|size`、`reverse`、`withsystem`、`children`、件数
- `depend_pages_unknown` を立てる。検索の文字には出さない

## 3d. 見え方が変わるページの道具と案内

v0.13 の `markdown_link_check` と同じ形。3a〜3c で見え方が変わるページを一覧にする
読み取り専用の道具、アップグレードのツールの案内、手順書の節、`tests/upgrade.sh` から
実際に走らせる検査。

## 3e. 変換器

### 入口と流れ

- 種別 wiki のページのページメニューに「Markdownに変換」。編集できる人だけ
- 確認画面: 変換後の本文 (読むだけ)、落ちるもの・原文の枠で残るものの一覧、
  id が変わる見出しの一覧、「履歴の変換前の版で『この版に戻す』を押せば戻せます」
- 「変換する」で保存。確認画面の ticket を渡す
- 1 ページだけ (一括変換・子ページの変換はしない)
- 同じ変換を画面なしで試せる読み取り専用の道具 `app/tool/wiki_to_markdown`
- 何が写せるかの分類は変換器が持つ 1 つの表にし、`wiki_syntax_survey` もそれを読む

### 保存

- `page_write()` の `write_meta` で種別を変える (履歴の「この版に戻す」と同じ口)
- `backup_now` に時刻を渡して、変換前の版を必ずその時刻で残す。末尾のリンクに同じ時刻を
  書くので、時刻は書く前に決める (同じ時刻の版が既にあれば 1 秒ずらす)

### 写し方

土台は `app/tool/wiki_syntax_survey` の木の辿り方 (wiki 記法のパーサが作る木を辿る)。
「数える」所を「Markdown を書き出す」に替える。表示の処理と同じく、行頭のトークンを足してから
辿る (`survey_walk_tokens()` は足していないので、そのままでは複数行の対象の 1 行目を取りこぼす)。
**文中 (表のセル・箇条書きの項目・関連リストの説明など) の中身が空白で始まるときは足さない**
(`wiki_convert_from_tokens()` の `!ctype_space($tokens[0]->t)` と同じ)。足すと `- 項目` や
`| セル |` の空白を整形済みとして読み、中のリンクや強調が文字になる (v0.14.0 のアップグレード
確認で、実データの 315 ページのうち 289 ページに出た。手元の入力は `-項目` の形だけだった)。

- **題名とタグ**
  - `&title` → 本文の一番先頭の `#`。途中に書いてあっても先頭に移す
  - `&title` が無く、メタ情報の画面で付けた題名だけがあるときも、それを `#` に出す
  - タグ (`meta['tag']`) → フロントマターの `tags:` (書かないと保存でタグが消える)。
    カンマや `[ ]` を含むタグがあれば、1 行に 1 つの並びの形 (`  - タグ`) で書く
    (`[a, b]` の形は読む側がカンマで分けるだけなので)
- **見出し**
  - 深さ N → `#` を N+1 個。6 個で止める
  - `*(optional)` → `:::details ###… 見出し` (3b の書き方で wiki と同じ深さ)。中身は節の終わりまで。
    入れ子は外側のコロンを長くする
  - `*(end)` が示す節の範囲は落ちる
- **ブロック**
  - 箇条書き・引用 (中身はエスケープ)・区切り線はそのまま
  - 整形済み → コードの枠 (`(code)` は枠の言語)。`&pre` / `&code` / `&paa` → コードの枠
  - 関連リスト `:語|説明` → `- **語**: 説明`
  - 表・CSV → GFM の表。見出しの行は、行の末尾の `h` か、1 行目のセルが全部見出しのセル (`~`)
    のとき。無ければ 1 行目を見出しの行にし、落ちるものに数える (2026-10-19 に変更。
    それまでは空の見出しの行を作っていた)。CSV も同じ。
    桁は wiki_normalize() と同じくそろえて書き出す。2 行目からの見出しのセルはふつうのセルになる
    (Markdown の表で見出しにできるのは 1 行目だけ)。結合・幅・計算は落ちる。
    セルの中の `|` は `\|`
- **文中**
  - `''` → `**`、`'''` → `*`、`%%` → `~~`、改行 → `\` + 改行、`""..""` → エスケープした文字
  - `[[表示:ページ]]` → `[[ページ|表示]]` (並びの入れ替えだけ。行き先の規則は同じ)
  - `[[表示:URL]]` → `[表示](URL)`。新しいタブで開く `>>` は落ちる
  - 独自の絵文字の実体参照 → Unicode の絵文字
- **ファンクション**
  - `&include(ページ・添付・画像 URL, 指定){キャプション}` → 独立した段落の
    `![|指定](パス "キャプション")`。wiki の「名前だけ」(= トップ階層) のパスは `/名前`
  - `&direct([[行き先]]){説明}` (`&link` の `raw`) → 行き先を読み、埋め込みが文字のリンクに
    なる種類 (PDF・テキスト・種類の分からないもの・添付 HTML・md) は `![説明](行き先)`。
    画像・音声・動画・ふつうのページ・まだ無い/読めないページは `[説明](行き先)` (落ちるもの)。
    表示名が `&include` の画像だけなら、同じ画像は `![|指定](画像)`、それ以外は
    `[![|指定 !link](画像)](行き先)` (`&link(URL)` の行き先が URL でも同じ)。
    画像でないものは原文の枠 (追記 2026-10-19)
  - `&index;` → `[TOC]`。別のページの目次は原文の枠
  - `&treepages` / `&listpages` / `&childpages` / `&pages(show=list|tree)` → `[PAGES …]`。
    `[PAGES]` で書けない指定や、表・中身ごと・新着の形は原文の枠
  - 装飾 `&color` `&bgcolor` `&size` `&align` → 中の文字だけ。`&more` → 落とす
  - それ以外 (カレンダー・計算・フォーム・`&redirect`・`&wikiexample` など) → 原文をコードの枠
    (文中は `` `...` ``)。別名は展開先の名前で分類する
  - **登録されていない名前** (`&VoIP製品` や、名前に文が続いた `&calcの方は…`) → 文字のまま。
    表示は `&` から木の終わりまでを、先頭の `&` を文字にしてから読み直す (中の記法は効く。
    `wiki_convert_from_tree()` の else) ので、同じく読み直して写す。コードの枠にすると、
    文の残りまで等幅になる
  - 文中の行頭の `~` (`-~項目`) → `~` だけを消し、中の記法は効かせる (`wiki_operator_through()`)
- **エスケープ**: CommonMark の記号に加えて、NextForm が足した記法 (単独の行の `[TOC]` /
  `[PAGES …]`、行頭の `:::`、`[[`、先頭の `---`、`![..|..]`) も対象。原文にただの文字として
  書いてあったものが、変換後に機能として動き出さないようにする。GFM の自動リンク
  (`www.` と `http://` などの `:`) と、トークンをまたいだ実体参照 (`&&copy;`) も対象 (追記 2026-10-19)
- **行頭のトークン**: 中身を読むときに行頭の印を足すかは、表示 (`wiki_convert_from_tokens()`) と
  同じ条件にする。強調・打ち消し・リンクの名前・`~` の行は足さない。項目などは中身が空白で
  始まるときだけ足さない。食い違うと、頭の `-` `,` `|` などが記号として読まれて消える (追記 2026-10-19)
- **行末の `~`**: 1 行の項目・見出しの最後の改行は書かない (表示に出ない)。関連リストの説明の
  行末の `~` は、表示では文字のまま出る (説明に行末の印が渡らない) が、改行のつもりで書いたもの
  なので書かない (追記 2026-10-19)
- 日本語の約物の隣の `**` が強調にならない場合があるので、テストで押さえる

### やらないこと

- 一括変換、子ページの変換、Markdown → Wiki 記法の逆変換 (戻すのは履歴で行う)
- `&pages` の表・中身ごと・テンプレートの形、別のページの目次
- 他のページが原文に頼っている場合の検出
