## 1. 何を作るか

### 1.1 利用者が決めたこと (2026-11-07)

**(1) カレンダーで、同じ日に複数のページを作れるようにする。**

- ページの名前は `YYYY-MM-DD` (1 つ目)、`YYYY-MM-DD_2`、`YYYY-MM-DD_3`…。1 つ目に `_1` は付けない
  (今あるページがそのまま 1 つ目になる)。`-2` にしないのは、日付と見分けにくいため。
- 使うのは `show=title` のときだけ。
- **ページの無い日**: 日付は今までどおり、ページを作るリンク。見た目も小さい画面の動きも今と同じ。
- **ページのある日**: 日付はただの文字にする。その下にタイトルを並べ (それぞれページへのリンク)、
  最後に小さく「＋」(次の番号のページを作るリンク) を置く。
- 「＋」は、書ける人にだけ出す。
- 2 ページ目以降は、子ページの一覧から `YYYY-MM-DD` と `YYYY-MM-DD_N` を拾い、番号順に並べる。
  「＋」は、いちばん大きい番号の次。(`_2`、`_3` と順に探すと、`_2` を消したときに `_3` 以降が見えなくなる)
- `&datepages` が `_N` のページを拾わないのは、**リスクが低いなら直す**。

**(2) マスに出す文字数に上限を付けられるようにする。**

- 書き方は **`maxlength=`** (例 `&calendar(show=title, maxlength=20)`)。書かなければ今までどおり。
- 数えるのは **1 ページごと** (1 日の合計にしない。合計にすると、2 つ目のページのタイトルが丸ごと
  切れて、カレンダーからたどれなくなることがある)。
- 全角も半角も 1 文字と数える。
- 切ったところに「…」を付け、マウスを載せると全文が出るようにする。
- 目次を出すとき (`show=title` でないとき) にも効く。見出しを順に数え、上限に来たところで切る
  (先頭の見出しの途中で切れることもある)。残った見出しはリンクのまま。

### 1.2 利用者の新しい案 (2026-11-08、§4 で検討)

- `&calendar` の既定を `show=title` にする。→ **変える** (利用者の判断 2026-11-08。§9)
- `&pages` の既定を `show=toc` にする。→ **変えない** (利用者の判断 2026-11-08。§9)

> 既定が `show=title` になるので、§3 で「`show=title` のとき」と書いたものは、`show=` を書かないときにも
> 当てはまる。今の目次の表示は `show=toc` と書いたときだけになる (§4.1)。

## 2. 調べてわかったこと (2026-11-08)

- **カレンダーのマス** (`wiki_calendar.inc`)。マス (`<td>`) ごとに `日付のページ名` を作り、
  `page_is_exists()` と読む権限で「ページのある日」(`td.exists`) を決める。日付 (`dt.day`) は
  いつも `<a href="?親/YYYY-MM-DD">` で、ページが無ければ `rel="nofollow"` (押すと作る画面)、
  あれば `data-link-pagename`。`<td>` には `data-ref-pagename` (日付のページ名) と、ページがあれば
  `data-ref-ticket` が付く。`show=title` では、`<dd>` に短いタイトル → タイトルのリンク (`a.title`) を
  1 つ置き、どちらも無ければ `handle(…, 'summary')` で目次を置く (`handle()` を通すので、描くたびに
  その日のページを「読んだ」と記録する)。
- **小さい画面とサイド** (`nextform.js` の `calendarHelperSetup()`)。CSS が `td.exists` の `<dd>` を隠して
  「...」を出し、マスを押す (机の上の画面のサイドではマウスを載せる) と `<dd>` を浮かせて見せる。
  小さい画面・サイドかどうかは、`span.day_detail` が隠れているかで見分ける。浮かせるとき、先頭に見出し
  (`h1.pages`) を足し、その行き先を **`td.down('dl > dt > a')` の `href`** から取る。日付をただの文字に
  すると、ここで JavaScript が止まる (浮かない)。同じ処理が 2 つ書いてあるが、動いているのは
  `handlerOn` / `handlerOff` / `handlerToggle` で、`handler` はどこにも付いていない。
  - 小さい画面・サイドで、ページのある日に**キーボードで届くのは日付のリンクだけ** (`<dd>` は隠れている)。
- **ダブルクリックの編集** (`wikiRefPageObserve`)。`data-ref-pagename` の付いたものごとに付き、内側の
  ものが先に受けて止める (`event.stop()`)。一覧 (`&pages`) は項目ごとに付けている
  (`pagelist_set_page_attributes()`)。個人設定で切れる。
- **目次 (summary) とリンク。** Wiki 記法の目次は、`summarize_link` を立てたときだけ見出しがリンク
  (中身は見出しの文字だけの 1 本のリンクになり、見出しの中のリンクや飾りは落ちる)。見出しの無いページの
  書き出しは、引数 `$is_link` のときだけリンクで、そのリンクには `data-link-pagename` が付かない。
  Markdown の目次は見出しがいつもリンクで、見出しの無いページの書き出しは文字だけ (文字も無ければ空、
  変換に失敗すれば何も出さない)。text のページは書き出しの 1 語を、外枠 (`section.summary`) 無しで
  直に出す。file のページは埋め込み (画像など)。`&pages(show=toc)` (`pagelist_append_toc()`) は
  「読んだ」にしないために、種別の関数を直に呼んでいる。
  - つまり、**日付をただの文字にすると、マスからたどれないページが出る**: タイトルも見出しも無い
    Wiki のページ、本文が空・画像だけの Markdown のページ、file のページ (§3.2 で塞ぐ)。
- **静的エクスポート** (`export.inc`)。書き出したページの中で、`data-link-pagename` の付いたリンクを
  たどって、つながったページを書き出す。今は**日付のリンクが日のページへの道**になっている。
  無いページへの `data-link-pagename` は「存在しません」のエラーになる。エクスポートで描くときは
  `$page['is_export']` が立つ。既定のテンプレートには CSS が無い。
- **子ページの探し方** (`page_find()`)。`is_pagename_only` なら、名前と更新時刻を集めるだけ (本文も meta も
  読まない。読む権限も確かめない)。ページの保存先は事実上 1 段の平らなディレクトリなので、親の名前の
  前方一致の `glob` は**サイト全体のページ数**にも比例して重くなる。0.01 秒より長くかかった結果は
  キャッシュする。キャッシュは書き込みの前に消え、集め終わったあとに作られるので、同時に表示があると
  古い結果が次の書き込みまで残りうる (今の `&pages` も同じ)。親を空にすると、サイト全体を探す。
- **ページの削除** は現行版 (`head`) を消すだけで、版のファイルは残る。同じ名前で作り直すと、履歴に
  消したページの古い版が出る。消したページは `page_find_deleted()` で拾える。
- **`&datepages`** (`wiki_datepages.inc`)。名前が `/YYYY-MM-DD` で終わる子ページだけを拾う
  (`name_regex` と `datepage_is_datepage()`)。`datepage_is_datepage()` を使うのはここだけ。
- **文字数。** mbstring は事実上必須 (同梱の CommonMark が要求している)。ただ、絵文字の組み合わせ・国旗・
  異体字セレクタ付きの文字・濁点を分けて書いたかな (NFD) は、文字コードの数 (`mb_strlen()`) で数えると
  見た目の 1 文字の途中で切れる。不正な UTF-8 があると、`/u` 付きの正規表現は結果を返さない。
- **`&pages` の既定** (`pagelist.inc`)。`show=` を書かなければ `list`。`toc` のときは `each=` を
  書かなければ 50 件で区切る。この既定は `&pages` だけでなく、すべての一覧の画面 (ページの一覧・
  サブページ・削除・名前の変更・タグ・添付・クローンが読むサブページの一覧など) が使っている。
  `&datepages` (既定 `contents`、30 件) と `&popularpages` は自分で決めている。
- **JavaScript の読み込み** は、ファイルの更新時刻で URL が変わる。古い JavaScript が新しい HTML を
  読むことはない。

## 3. 設計

### 3.1 同じ日に複数のページ

**拾うページ。** カレンダーを 1 回描くごとに、親のページの子ページを 1 度だけ探す
(`page_find()`、名前だけ、子だけ、下の形の名前だけ (`name_regex`))。

- `親/YYYY-MM-DD` — 1 つ目 (番号 1)
- `親/YYYY-MM-DD_N` — N は **2 以上、先頭に 0 を付けない、4 桁まで** (`_2`〜`_9999`)

`_1`・`_02`・`_x`・5 桁以上は拾わない (カレンダーが作らない名前。`_1` を拾うと「1 つ目」が 2 つになる)。
4 桁までにしたのは、とても大きな番号を手で作られたときに、「次の番号」が整数からあふれないようにするため。

- 見つかった名前は、表示する範囲の日付のものだけ `page_is_exists()` で確かめる (キャッシュに残った、
  消したページを出さない)。
- **読めないページは並べない** (今のカレンダーと同じく、無いページと同じに扱う)。
- 日ごとにまとめ、番号順 (`_10` は `_9` の後) に並べる。
- 親が空 (`&calendar([[]])`) のときは探さない (サイト全体を探すことになるため)。今と同じく 1 つ目だけを見る。

**ページのある日** (読めるページが 1 つ以上):

```
6                       ← 日付。ただの文字
・カレンダーの手直し     ← 1 つ目のタイトル (リンク)
・検索の整理             ← 2 つ目のタイトル (リンク)
＋                       ← 書ける人にだけ。3 つ目を作るリンク
```

- 日付はただの文字 (`dt.day` の中にリンクを置かない)。`span.day_detail` (月の初めの「2026-11-」) は
  今と同じく `dt.day` の中に置く (JavaScript と CSS が小さい画面の見分けに使う)。
- ページは `<dd>` の中の箇条書き (`ul.day_pages > li`) に 1 つずつ置く。CSS の無い静的エクスポートでも
  1 行ずつ並ぶ。
- **ページごとの項目 (`li`) に、そのページの `data-ref-pagename` と `data-ref-ticket` を付ける**
  (一覧 `&pages` の項目と同じ)。2 つ目のタイトルの上でダブルクリックすると、2 つ目を編集する。
  項目の外 (日付・余白) でダブルクリックすると、今と同じく 1 つ目を編集する (無ければ新しく書く)。
  `<td>` の `data-ref-ticket` は、1 つ目があって読めるときだけ付ける。
- 各ページの中身は、今の `show=title` と同じ順: 短いタイトル → タイトル → (どちらも無ければ) 目次 (§3.2)。
  タイトルのリンクは `dom_append_page_link()` で作る (`data-link-pagename` が付き、静的エクスポートが
  たどれる)。
- 「＋」は `親/YYYY-MM-DD_{いちばん大きい番号 + 1}` へのリンク。
  - `class="create"`、`rel="nofollow"`、`title` と `aria-label` に「この日にページを足す」
    (英語 "Add a page for this day")。
  - `data-link-pagename` は付けない (`dom_append_link()` で作る。付けると、エクスポートが無いページを
    書き出そうとしてエラーになる)。
  - **「いちばん大きい番号」は、読めないページと消したページも含めて数える**。読めないページの名前に
    重ねて作らせないため。消したページの名前を使い回すと、新しいページの履歴に消したページの古い版が
    出るため。消したページは `page_find_deleted()` で同じ条件で拾う (書ける人に「＋」を出すときだけ)。
    番号が飛ぶことで、そこにページがあると分かる人がいるのは、読めないが書ける人だけで、そういう権限の
    組み方はまれ。
  - 出すのは、作るページの名前に書く権限がある人だけ (`auth_has_permission(…, 'write')`)。
  - 次の番号が 4 桁を超えるなら出さない (作っても拾われないため)。
  - 静的エクスポート (`is_export`) では出さない。
  - 2 人が同時に押して同じ名前を書いても、保存のときの ticket の食い違いで後の人が止まる (今と同じ)。
- 1 つ目が無く `_2` だけがある日も「ページのある日」。「＋」は `_3`。1 つ目は、日付の付近をダブルクリック
  すると作れる。
- 1 日に出すページの数に上限は付けない。ページを作れるのは書ける人だけで、タイトルのあるページは meta を
  読むだけ (軽い)。目次を描くのはタイトルの無いページだけで、1 ページの重さは今の目次と同じ
  (書ける人は今でも重いページを書ける)。

**ページの無い日**: 今のまま。日付は 1 つ目 (`親/YYYY-MM-DD`) を作るリンク。「＋」は出さない。

**`show=title` でないとき** (目次): 今のまま。1 つ目のページだけを見て、日付はリンク。`_N` のページは
マスに出ない (§4.1 で既定を変えるなら、目次の書き方 `show=toc` のとき)。

**重さ。** 実装で、日記 (1 年分・3 年分) と、ほかのページの多いサイト (実データの複製。性能の計測は
実データを使ってよい場面) で測る。カレンダー 1 回で今より 0.05 秒を超えて重くなるなら、月ごとの
名前の前方一致 (表示する月とその前後で 1〜3 回の `glob`) に替える (作る人の判断)。サイドに置いた
カレンダーは全部のページの表示で描かれるので、そこでも測る。

### 3.2 マスからページに行けるようにする (§2 の穴を塞ぐ)

`show=title` で、短いタイトルもタイトルも無いページは、今と同じく目次を出す。ただし日付がリンクで
なくなるので、**どのページにも、そのページへのリンクが少なくとも 1 本あるようにする**。

- 目次は、種別の summary の関数を直に呼ぶ (`handle()` を通さない。一覧の目次と同じく、カレンダーを
  開いただけで「読んだ」にしない)。見出しはリンクにする (ツールの「目次」と同じ。見出しの中の
  リンクや飾りは文字だけになる)。
- 項目の中に、そのページへのリンク (`data-link-pagename` がそのページのもの) が 1 本も無いときは
  (見出しの無いページ、text、file、本文が空、変換の失敗)、中身をそのページへのリンク 1 本に置き換える。
  リンクの文字は中身の文字 (書き出し) で、文字が無ければページ名の最後の部分 (`2026-11-06_2`)。
- `show=title` でないとき (目次) は変えない (日付がリンクのまま、`handle()` も今のまま)。

### 3.3 小さい画面とサイド

- CSS は今のまま: ページのある日は `<dd>` を隠して「...」、押すと浮いて出る。浮いた中身は
  タイトルのリンクと「＋」なので、**小さい画面でも 2 つ目以降のページを開け、作れる**。
- `nextform.js` の `calendarHelperSetup()` (動いている `handlerOn` のほう):
  - 日付にリンクが無いとき、浮かせた中身の見出し (`h1.pages`) は、日付のページ名の**文字**にする
    (リンクにしない。`createTextNode` で組む。Prototype の `update()` は HTML として読むので使わない)。
    リンクがあるとき (目次の表示) は今のまま。
  - **キーボードで届くようにする。** 日付がリンクでないマスでは、中身が隠れているとき (小さい画面と
    サイド) だけ、JavaScript が `dt.day` に `tabindex="0"` を付け、Enter・Space で浮き出しを開け閉めする
    (今は日付のリンクがその役)。画面の幅が変わるたびに付け直す。HTML には付けない (広い画面と静的な
    書き出しに、押しても何も起きない止まり場所を作らない。`dt` に `role="button"` は付けられない。§12)。
- 動いていない `handler` は直さない (§10 に別件として書く)。

### 3.4 `&datepages` で `_N` のページも出す

- 拾う名前を `/YYYY-MM-DD` と `/YYYY-MM-DD_N` (§3.1 と同じ形) にする。`past` / `future` の比べ方は
  日付の部分で行う (`_N` を除いた日付)。
- 形の判定は `util.inc` の `datepage_is_datepage()` に寄せ、カレンダーと同じ決まり (§3.1) を使う。
  この関数を使うのは `&datepages` だけなので、ほかには響かない。
- 並びは今までどおり名前順: `2026-11-06`、`2026-11-06_2`、`2026-11-07`。既定の `reverse` では逆なので、
  同じ日の `_2` が 1 つ目より前に来る。1 日に 10 ページ以上あると `_10` が `_2` の前に来る (名前順)。
  `each=` (既定 30) は日数ではなくページ数。マニュアルに書く。
- 影響: 今まで出なかった `_N` の名前のページが一覧に出る。`_N` を手で作っていたサイトはまれと見る。

### 3.5 `maxlength=` (マスの文字数の上限)

- `&calendar(…, maxlength=N)`。N が 1 以上の整数 (数字だけ) のときだけ効く。書かない・0・負・数字で
  ない値 (`20abc` も) は上限なし (今までどおり)。
- **見た目の 1 文字を 1 と数える** (書記素。`preg_match_all('/\X/u', …)`。全角も半角も、絵文字の
  組み合わせも国旗も 1)。正規表現が結果を返さない (不正な UTF-8) ときは切らない。
- **タイトル**: ページごとに、N 文字を超えたら N 文字に切って「…」を付ける。リンク (`a.title`) の
  `title` 属性に全文を入れる (マウスを載せると出る)。切らなかったときは付けない。
- **目次** (`show=title` でないとき、または §3.2 の目次): ページごとに、目次の文字 (見出しの文字。見出しが
  無ければ書き出し) を出てくる順に数え、N 文字に来たところで切って「…」を付ける。その後ろの見出しは
  出さない (空になった項目と入れ子の箇条書きも消す)。残った見出しはリンクのまま。切ったときは、目次の
  外側 (`show=title` ではページの項目 `li`、目次の表示では `<dd>`) の `title` 属性に、見出しの全文を
  1 行に 1 つずつ入れる。
- 1 日に複数のページがあれば、それぞれで数える (1 日の合計にしない)。
- **タッチの画面では `title` 属性が出ない**ので、切った全文はページを開いて見る (浮き出しの中でだけ
  切らない形は、同じ文字を 2 度書くことになり、CSS の無いエクスポートで両方出るので採らない)。
- 表示の行数で切る (CSS) 案は採らない (入れ子の箇条書きでうまく効かないことがある)。

### 3.6 CSS

`app/theme/common/style/.base.css` の `&calendar` の節に足す (全テーマが読む):

- `table.calendar ul.day_pages`: 印と字下げを付けない (今の 1 ページのときと同じ見た目)。
- `table.calendar a.create`: 小さい「＋」。指で押せるように余白を付け、24×24px 以上にする。
- ページのある日の日付 (リンクでない `dt.day`) は、ふつうの文字の色 (押せないことが分かるように)。

## 4. 既定の表示を変える案 (2026-11-08 の利用者の案)

### 4.1 `&calendar` の既定を `show=title` にする — **変える** (利用者の判断 2026-11-08)

**変えると、上げたあと次のようになる** (`show=` を書いていないカレンダーすべて):

- タイトル (か短いタイトル) のある日のページは、マスに目次ではなくタイトルが出る。
- タイトルの無いページは、今と同じく目次が出る。見出しはリンクになる (§3.2)。
- ページのある日の日付は、ただの文字になる。書ける人には「＋」が出て、同じ日に 2 つ目を作れる。
- タイトルのあるページは本文を描かないので軽くなる (v0.21 の実測で、日記の形のひと月が 0.64 秒 →
  0.04 秒)。カレンダーを描くたびに子ページを 1 度探す (§3.1。測って確かめる)。
- **今の見え方 (目次・日付がリンク・1 日 1 ページ) に戻したいページには `show=toc` と書く。**
  古い版はこの値を知らないが、知らない値は目次で出すので、同じ見え方になる。
- 知らない `show=` の値は既定 (タイトル) で出す (v0.21 では目次)。`show=title` は今までどおり書ける。

**よい点**: 新しく書く `&calendar` が、書き足さなくても見やすく軽い。同じ日の複数のページと
`maxlength=` も、`show=title` を覚えなくても使える。

**気になる点**:

- 上げただけで、今あるカレンダーの見え方が変わる。とくに、タイトルを付けて書いていた日のページ
  (例「2026-11-06 定例会議」) は、目次の代わりにそのタイトルが出る。CHANGELOG と `UPGRADE.md` に書く。
- v0.21 で決めたこと (§7「カレンダーのタイトル」: `show` を書かないときと知らない値は目次、CSS と
  JavaScript は変えない) を変えることになる。§7 に新しい決定として書く。
- v0.21 の依頼では「カレンダーの既定は今のまま (目次)」を依頼元の前提として書いていた。依頼元の日記は
  `show=title` と書いてあるので、見え方は変わらない。依頼元に知らせるときに、既定が変わったことを書く。

### 4.2 `&pages` の既定を `show=toc` にする — **変えない** (利用者の判断 2026-11-08)

**変えると、上げたあと次のようになる** (`show=` を書いていない `&pages` すべて):

- どの一覧にも、項目ごとに「▶ 目次」の折りたたみが付く (見出しのあるページ)。
- **50 件を超える一覧は、50 件ずつの画面に分かれる** (「次」「最後」のリンクが出る)。目次は 1 件ごとに
  本文を変換して作るので、区切らないと時間切れになるため (v0.21 で決めた)。今「全部のページを 1 画面で
  並べている」一覧も分かれる。
- **重くなる。** 1 画面で最大 50 ページ分の本文を変換する (日記の形で約 0.9 秒)。サイド (サイドバー) に
  `&pages` を置いているサイトでは、**どのページを開いても**これだけ遅くなる (マニュアルで「目次の一覧は
  サイドに置かない」と書いた理由)。Wiki 記法のページは保存のときにも一覧を描くので、保存も遅くなる。
- 戻すには、今ある `&pages` のすべてに `show=list` を書き足すことになる。
- (作るなら、既定は `&pages` の関数の中で変える。一覧の部品の既定を変えると、ページの一覧の画面や、
  クローンが読むサブページの一覧まで 50 件で区切られ、クローンが 51 件目から先を取りこぼす。)

目次が要るのは日記のような「中身で選ぶ」一覧で、ページの一覧の多くはタイトルで足りる。日記のページには
`show=toc` と書いてあるので、既定を変えなくても困らない。

## 10. 調べている途中で見つけた別の問題

2026-11-08 に利用者が 3 件とも直すと決めた。カレンダーの機能より先に、別のブランチ
(`fix/calendar-findings`) で、1 件 = 1 コミットで直す。

### 10.1 差分のエクスポートで、新しい日のページが書き出されない

エクスポートは、`force` を付けない限り、2 回目からは差分だけを書き出す。前に書き出したファイルより
ページが新しくなければ書き直さず、そのページからは**前回覚えたリンク先**だけをたどる
(`export.inc` の `export_convert()`)。カレンダーのページの本文は `&calendar` の 1 行だけで、日のページを
足しても変わらないので、2 回目からは飛ばされる。

- 新しく作った日のページが書き出されない (ほかのページからリンクしていれば書き出される)。
- 書き出したカレンダーのマスが古いまま (新しい日が出ない。日のページのタイトルを直しても変わらない)。
- `&datepages` の一覧も同じ。

`&pages` と Markdown の `[PAGES]` は、ほかのページの増減で中身が変わるので、「何に依るか分からない
(毎回書き直す)」の印 (`depend_pages_unknown`) を立てている。**`&calendar` と `&datepages` でも同じ印を
立てる。** カレンダーや日付の一覧のあるページは毎回書き直され、エクスポートの時間がその分だけ増える
(`&pages` のあるページと同じ扱い)。

### 10.2 URL の日付 (`?calendar=`) の読み方

URL の値を `2026` → `2026-01-01`、`2026-08` → `2026-08-01` と補うつもりの作りだが、正規表現に始まりと
終わりの決まりが無く、4 桁の数字があればいつも `-01-01` を足す。`2026-08-06` は `2026-08-06-01-01` に
なり、PHP は最後の `-01` を「UTC−1 時間」と読む。

| サイトの時間帯 | `?calendar=2026-08-06` が指す時刻 | 影響 |
|---|---|---|
| 日本 | 2026-08-06 10:00 | たまたま正しい日 |
| ロンドン | 2026-08-06 02:00 | たまたま正しい日 |
| ニューヨーク | 2026-08-05 21:00 | 前の日になる。月の表示で ▶ を押しても前の月の末日に読まれ、次の月へ進めない |

もう 1 つ、表のマスは起点から 24 時間ずつ足して作るので、夏時間の時間帯で起点が深夜 0 時台・23 時台だと、
日付が重なったり抜けたりする (ニューヨークの 11 月 10 日 23:30 を起点にすると 1 日重なり、3 月 20 日
00:30 では 1 日抜けた)。URL を直しただけ (0 時) だと、この形で崩れる。

**直し方:**

- URL の値は、全体が `YYYY` か `YYYY-M(M)` のときだけ補う。それ以外はそのまま読み、読めなければ今と
  同じく今日にする。
- 表示の起点 (URL の日付と、URL が無いときの「今」) を、その日の**正午**にそろえる。夏時間で 1 時間
  ずれても日付が変わらない。
- 日本のサイトでは出る日付は変わらない (起点が 10:00 から 12:00 になるだけ)。

### 10.3 どこからも使われていない処理

`nextform.js` の `calendarHelperSetup()` の `handler` は、上流 (ToraToraWiki 1.3.10 の `toratora.js`) から
引き継いだ、使われている `handlerOn` とほぼ同じ写しで、どこにも付いていない。**消す。** 今回、浮き出しの
見出しを作るところを直すので、写しが残っていると次に直す人が使われていないほうを直すおそれがある
(この設計メモの最初の版でも「2 か所とも直す」と書きかけた)。消しても動きは変わらない。

## 12. 実装のあとのレビュー (2026-11-08)

別のレビュアーに、2 本のブランチの差分 (`main..feat/calendar-day-pages`) を読ませた。指摘を確かめて、次のようにした。

| 指摘 | どうしたか |
|---|---|
| **`maxlength=` を書くと 500 になる。** 目次の後ろの文字と空になった要素を 1 つずつ消していたので、先に消した要素の中の文字に当たって `removeChild()` が null で止まった。見出しがリンクや強調で終わる (空白だけの文字が残る)、中身の無い子の見出しがある、で起きる | 複製で再現するテストを先に書いた (500 を確かめた)。2 段に分けた: 先に後ろの文字だけを消し、そのあと空になった要素を、まだ `$node` につながっているものだけ消す |
| 目次を切ったあとに空の要素が残らないことを確かめていない | 空の `li`・`ul`・`a` を数える確かめを足した |
| `future` の確かめは、名前の全体で比べても通ってしまう | `past` で基準を `2026-08-04` にし、`2026-08-04_9` が出ることを見る (名前の全体で比べると出ない) |
| マスの ticket が 1 つ目のものかを確かめていない | 1 つ目の項目の ticket と同じであることを見る |
| 「読めないページも『＋』の番号に数える」を確かめていない | 未ログインの人に、読めないが書けるページを作って確かめた (「＋」は `_3`) |
| 「読んだにしない」の比べる相手が無い | `show=toc` (今までどおり `handle()` を通る) では読んだになることを並べて見る |
| ページの無い日の確かめは、マスが見つからなくても通る | マスがあることも見る |
| 見出しも文字も無い Wiki のページは、リンクの文字がページ名の全体になる (`wiki_summary()` がそう出す) | ページ名の全体なら最後の部分にする |
| 日付の `tabindex` と `role="button"` が、広い画面と静的な書き出しにも付く。広い画面では押しても何も起きない止まり場所がひと月で 40 ほどできる。`dt` に `role="button"` は付けられない | HTML には付けず、JavaScript が中身の隠れているときだけ `tabindex` を付ける (§3.3)。`role` は付けない |
| 起点を正午にそろえる `mktime()` は、年が 0〜100 だと 1970〜2069 年として読む (`?calendar=0050-03` が 2050 年) | 害が無いのでそのまま |

確かめて問題が無かったこと: 短いタイトルと見出しに HTML を入れても、文字も `title` 属性もエスケープされる。
読めないページは並ばない。「＋」は日付のページと次の名前の両方に書く権限が要り、書き出しには出ない。
番号の決まり (`_1`・`_02`・`_x`・`_10000` は拾わず、`_10` は `_9` の後)。親が空のカレンダーは探さない。
`show=toc` は `maxlength=` を書かなければ今と同じ。
