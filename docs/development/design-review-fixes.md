# 設計メモ: 短いタイトルの作業で見つけた別の問題の直し方 (v0.21 の候補)

> **このドキュメントの位置づけ**
> [design-short-title.md](design-short-title.md) の作業中とレビューで見つけ、§9 に記録した別の問題。
> 2026-11-07 に利用者が「リスクが低いならすべて直す」と決めた。ここには、それぞれの直し方と、
> 直し方で選んだこと (利用者の判断ではなく、この作業で決めたもの) を残す。
> ブランチは `fix/review-findings` (`feat/short-title` の上に重ねる)。

---

## 1. 直すもの

| # | 問題 | 直し方 | 振る舞いが変わるところ |
|---|---|---|---|
| 1 | `&popularpages` を区切ると「次」のリンクがサイトのトップを指し、いつも 1 画面目が出る | `&pages` と同じく、ページ (`context`) と URL の引数を `pagelist_append()` に渡す。`context` は引数を読んだ**後で**入れる | 区切りのリンクがそのページを指し、2 画面目以降が出る。`?tag=` で絞る働きは今までどおり持たせない (先に入れると `&pages` と同じく `?tag=` で絞るようになる) |
| 2 | Wiki 記法から Markdown への変換で、短いタイトルを引用符で囲まずにフロントマターに書く。両端の `"` `'` は読むときに落ち、`#` で始まる値はよそのツールではコメントになる | 書く側: YAML で囲みが要る値 (記号で始まる、`: ` や ` #` を含む、引用符で始まるか終わる、など) は `"…"` で囲み、`\` と `"` を `\` で逃がす。読む側 (`MarkdownFrontMatterParser`): 値の全体が同じ引用符の 1 組で囲まれていれば、その 1 組だけを外し、中の逃がしを戻す (`"…"` は `\"` と `\\`、`'…'` は `''`)。囲まれていなければ今までどおり両端の空白と引用符を落とす | 1 組で囲んだ値の中の引用符が残る (`title: "'90s 特集"` は今まで `90s 特集`、これからは `'90s 特集`)。`title:` と `short_title:` で効く。タグは `markdown_parse_tags()` が項目ごとにもう一度引用符を落とすので、今までどおり |
| 3 | メタ情報の画面で「説明」を空にして保存しても消えない | 題名と同じ約束にする。`meta_write()` は空文字を渡し、`page_write()` が空文字なら `meta['description']` を消す (古い ngram を数えた後) | 空にすると消える。消した説明の語は検索の索引からも消える |
| 4 | メタ情報の画面でタイトルを消すと、古いタイトルの語が検索の索引に残る | `meta_write()` が `meta['title']` を直に落とすのをやめ、`$page['title'] = ''` を渡す (`page_write()` が古い ngram を数えた後に消す) | 消したタイトルの語で当たらなくなる |
| 5 | カレンダーの日のページに読めないものが 1 つあると、カレンダーのあるページ全体が 403 (未ログインならログインの要求) になる | 読めない日のページは、無いページと同じに描く (`exists` を付けない、目次・タイトルを出さない、ticket を付けない)。`&pages` が読めないページを一覧から落とすのと同じ考え | カレンダーのページが開ける。読めない日は空のマスに見える |
| 6 | 週表示の範囲 (`calendar_behind` / `calendar_ahead`) を URL で上限なく指定でき、誰でも重い表示を走らせられる | URL から来た値を 0〜12 週に収める (`WIKI_CALENDAR_URL_WEEKS_MAX`)。本文に書いた `behind=` / `ahead=` は書き手の値なので収めず、本文で 12 週より広く書いてあれば、URL の上限もその値にする (▲▼と「移動」は今の範囲を URL に写すので、狭めないため) | URL で 12 週 (か本文の値) より先は出ない。負の値は 0 |

## 2. 直し方で選んだこと

- **6 の上限は 12 週** (前後それぞれ約 3 か月)。週表示の「▲」「▼」は 1 回で 2 週ずつ広げる。
  前後 12 週なら最大 25 週 (175 マス) で、日のページがすべてある日記でも月の表示 (42 マス) の約 4 倍に収まる
  (目次を出すマスで 1 マス約 14 ms、約 2.5 秒)。
- **5 は「無いページと同じ」にする** (読めないことも出さない)。マスに「読めません」と出す案は、
  そのページがあることを読めない人に見せる。
- **2 の読む側は、1 組で囲んだ値だけを変える。** 囲んでいない値 (`title: '90s 特集` のように片方だけ)
  は今までどおり両端の引用符を落とす。ほかのツールで書いた正しい YAML の値は、これまでより正しく読める。

## 3. やらないこと

- `&popularpages` に `?tag=` で絞る働きを足すこと。
- 変換で、短いタイトル以外 (タグ) の書き方を変えること (タグは空白を含まず、今の書き方で困っていない)。
- 変換で、Wiki 記法の文字の飾り (`''強調''` など) を短いタイトルから外すこと (題名の書き出しと同じ作り)。

## 4. テスト

`tests/short-title.sh` に足す (同じ複製サイトで、メタ情報の画面・カレンダー・一覧を見ているため)。

- 1: 2 ページに閲覧数を入れ、`&popularpages(.., each=1)` の「次」がそのページの `pages=1` を指し、
  2 画面目に 2 位のページが出る。
- 2: `tests/wiki-to-markdown.sh` に引用符・`#` で始まる短いタイトルの例。`tests/markdown.sh` に、
  1 組で囲んだ値の読み方 (`"'90s 特集"`、`'It''s'`、`"a \"b\""`) と、囲んでいない値が今までどおりのこと。
- 3・4: メタ情報の画面 (`meta_write()`) で説明とタイトルを空にすると meta から消え、索引に古い語が残らない。
- 5: 未ログインで読めない日のページがあっても、カレンダーのページが 200 で、そのマスは空。
- 6: `calendar_behind=100000&calendar_ahead=-3` で 200、週の数が上限に収まる。

## 5. 直しのあとのレビュー (2026-11-07)

別のレビュアーに、直しの差分 (コードを読むだけ) を見せた。指摘を確かめて、次のようにした。

| 指摘 | どうしたか |
|---|---|
| `?pages=` に大きすぎる値 (`9999999999999999999`) で、掛け算が整数からあふれてまだ 500 | 何画面目かを件数で抑えた。テストに足した |
| 本文で 12 週より広く書いた週表示が、▲▼や「移動」で 12 週に狭まる | URL の上限を「12 週か本文の値の大きいほう」にした。テストに足した |
| 引用符の読み方はタグには効かない (`markdown_parse_tags()` がもう一度落とす) のに、文書は効くように書いていた | 文書を直した (タグは今までどおり)。タグは空白を含められず、引用符を残す使い道も無いので、読み方は変えない |
| `markdown.sh` §21 の 4 項目は古いパーサでも通る | 「今までどおり」を確かめる項目だと名前に書いた |
| `&popularpages` が URL の `?pages_show_hidden=true` を読み、閲覧数の無いページが出るようになった | その引数だけ渡さない (今までどおり出さない)。テストに足した |
| 変換で、日付・真偽値・数に見える値を囲まない (よそのツールでは型の付いた値になる) | 囲むようにした。テストに足した |
| 囲んでいない YAML としては正しくない書き方 (`title: ''強調''`) の読み方が変わる (`強調` → `'強調'`) | そのまま (正しい YAML の値と、今までの変換の出力の読み方は変わらない) |
| 前からある、誰でも開ける URL の 500: `?calendar[]=x` (`trim()` に並び)。本文の `behind=abc`・`limit=abc` の 500 | 同じ種類の小さな直しなので直した (並びは使わない、本文の値は整数)。テストに足した |
