# 配布物からのアップグレードを実サイトで確かめる

## 0. この文書は何か

**リリース前に、配布物 (`NextForm.tar.gz`) を実際のサイトに当てて確かめる**ための
手順書。開発者が手で行う。[workflow.md](workflow.md) §6「リリース」の手順 9 の中身。

紛らわしいものが 2 つあるので、先に線を引く。

| | 何を確かめるか | 誰が走らせるか |
|---|---|---|
| `tests/upgrade.sh` | ツールと手順書が**壊れていない**こと。tora2 の複製が相手 | 機械。作業のたび |
| **この文書** | **実データの入ったサイトが、上げたあとも使えること** | 人。リリース前に 1 回 |
| `docs/upgrade-guide.md` | — (利用者向けの正本。配布物に `UPGRADE.md` として同梱) | サイト運用者 |

`tests/upgrade.sh` が通ることは前提。あれは 2015 年当時のページが 2 枚しかない
複製に対する検査で、**件数・サイズ・古い書き方**は見ていない。ここで見るのは
自動テストが原理的に踏めない部分だけ。

> **この文書に環境固有の値を書かないこと。** リポジトリは public。
> サーバ名・ホスト名・実際のパスは書かず、`/var/www/html/mywiki` のような
> 仮の名前を使う。向け先は `tests/env.local` (追跡外) に置く。

## 1. 始める前に

### 対象サイトの版を確かめる

サイトに管理者でログインし、`?option=admin_info` の「バージョン」を見る。

| 表示 | アップグレードツールの反応 |
|---|---|
| ToraToraWiki 1.3.10 のみ (NextForm の表記なし) | そのまま通る |
| NextForm が配布物より**古い** | そのまま通る |
| NextForm が配布物と**同じか新しい** | 止まる。`--force` が要る (→ 6 章) |

### PHP の版を確かめる

対象サーバの `php -v`。**PHP 8.3 未満ならツールが何も書き換えずに止まる**
(`app/version.inc` の `NEXTFORM_PHP_MIN`)。`--force` でも素通りしない。

**CLI と web サーバの PHP は別の版であることがある**。ツールが見られるのは
CLI 側だけなので、web 側 (PHP-FPM / mod_php) も確かめる。web 側が古い場合は
アップグレードは通ってしまい、ブラウザで開いたときに
`app/php_version.inc` が理由を書いた 500 を返す。

> 以前ここには「コードを上げてから PHP を上げる順番になる」と書いていたが、
> **それは v0.2 までの話**だった。v0.3 以降は PHP 8.3 でなければ 1 ページも
> 開けない。どちらを先にしてもサイトは一度止まるので、続けて上げるか、
> 新しい環境を用意して切り替える (→ `docs/upgrade-guide.md` §2)。

### バックアップを確かめる

ツールは既定で `app/` `resource/` `theme/` `license.txt` と設定ファイルだけを控える
(数 MB)。**`storage/` は控えない。**ページと添付が数 GB になるため。

`storage/` の控えが別に無いなら `--full-backup` を付けるか、スナップショットや
`rsync` で先に控えておく。実データで試す以上、ここは省かない。

## 2. 配布物を作って送る

```bash
./deploy/scripts/make-dist.sh          # NextForm.tar.gz ができる
```

**手で `tar` しないこと。** `NextForm/` を直接固めると、`.gitignore` で無視して
いるだけの生成物 (`theme/` `storage/` `install-info.dat`) や作業中のファイルが
紛れ込む。`make-dist.sh` は `git archive` で追跡されているファイルだけを固め、
`UPGRADE.md` (手順書の正本の複製) も同梱する。

作った `NextForm.tar.gz` を対象サーバへ送り、展開する。

```bash
tar xzf NextForm.tar.gz
```

**`NextForm` に移動しない。** ツールは `NextForm/app/tool/upgrade` にあり、
以降のコマンドは展開した場所 (`NextForm/` の親) から実行する。

---

## 3. `--dry-run` で読む

何も書き換えない。`sudo` も要らない。

```bash
php NextForm/app/tool/upgrade /var/www/html/mywiki/index.php --dry-run
```

```
  対象サイト    /var/www/html/mywiki
  現在の版      NextForm 0.6.0
  更新後の版    NextForm 0.8.0
  実行中の PHP  8.3.31

  置き換えるファイル    718 件
  配布物に無いファイル  13 件 (削除せずそのまま残します)
      ...

  やること:
    1. バックアップ → /var/www/html/mywiki.backup-YYYYMMDD-HHMMSS
       必要 2.9 MB / 空き 5.8 GB
    2. app/ resource/ license.txt を新しいものに置き換える
    3. 静的テーマ (theme/) を再生成する
    4. 所有者とパーミッションを元に戻す

  触らないもの: index.php  install-info.dat  storage/  .htaccess
```

読むところは 4 つ。

- **現在の版 / 更新後の版** — 意図した組み合わせか
- **配布物に無いファイル** — ここには 2 種類が混ざる。
  ①自分で置いたもの (プラグイン、独自テーマ) と
  ②**古い版の NextForm が置いていて、今は無くなったファイル**。
  ②の例: `app/theme/basic/style/.base.css` は `app/theme/common/style/` へ移った、
  `app/theme/common/.tones.php` は `app/tone/` の JSON になった。
  ツールは消さないので残るが、読まれないだけで害はない。
  **身に覚えのないものがあれば、先に中身を見る**
- **バックアップの必要容量と空き** — 足りているか
- **触らないもの** — `storage/` が入っていること

---

## 4. 実行する

サイトを書き換えるので `sudo` が要る。

```bash
sudo php NextForm/app/tool/upgrade /var/www/html/mywiki/index.php
```

`続行しますか? [y/N]` に `y`。

```
  1. バックアップ .. done  (/var/www/html/mywiki.backup-YYYYMMDD-HHMMSS)
  2. コード更新 .. done
  3. テーマ再生成 .. done  (basic)
  4. 所有者の復元 .. done

完了しました。NextForm 0.8.0 になりました。
```

**最後に出る案内を読み飛ばさない。** ツールは版数ではなく**サイトの状態**を見て
案内を出す (`.htaccess` の中身、古いマニュアルの有無、索引の状態)。
索引の再構築や古いページの後片付けが要るかどうかは、ここに出る。

## 5. 確かめること

### 5.1 どの版でも見るもの

上げた版が何であっても毎回見る。

- [ ] `?option=admin_info` の「バージョン」が上がっている
- [ ] トップページが開く。**見た目が崩れていない**
      静的 CSS の URL には生成物の更新時刻が付く (`main.css?t=<mtime>`) ので、
      再生成されていればブラウザは新しいものを取りに行く。それでも古いままなら、
      **キャッシュではなくテーマの再生成 (工程 3) を疑う**。
      前に置いたプロキシや CDN がある場合はそちらも見る
- [ ] **PHP のエラーログが増えていない** — 一番効く検査。
      巡回の前後で行数を数える
      ```bash
      sudo wc -l /var/log/php-fpm/www-error.log     # 巡回の前後で比べる
      ```
      置き場所は環境による (PHP-FPM の既定。mod_php なら Apache のログ)
- [ ] `storage/` が変わっていない — ツールは触らないと言っているので確かめる。
      例外は「焼き付けた古いマニュアルの削除」だけ (実行後の案内に件数が出る)
- [ ] 所有者とパーミッションが元に戻っている
      ```bash
      ls -l /var/www/html/mywiki/app | head
      ```
      `root` 所有のものが残っていたら、web サーバから読めない
- [ ] 既存のページが開く。**添付ファイルと画像が出る**
- [ ] **検索が効く**。索引の再構築を求められていないか
      (`?option=search_index` の「詳しく検査する」)
- [ ] 編集して保存できる (POST の経路。スモークテストは GET しか回らない)
- [ ] マニュアル (`?NextFormManual/ja`) が読める

### 5.2 その版で見るものの決め方

`CHANGELOG.md` のその版の節を上から読み、次の 3 つに当たるものを拾う。
**自動テストが原理的に踏めないもの**だけを拾えばよい。

| 拾う基準 | なぜ自動テストで見つからないか |
|---|---|
| **既存ページの見え方**が変わるもの | ゴールデンマスターは HTML しか見ない。CSS が変わっても落ちない |
| **POST の経路** (編集・添付・ロック・改名・管理画面) | スモークテストは GET しか回らない |
| **実データでしか踏めないもの** (件数・サイズ・古い書き方・古い設定) | フィクスチャは 5 ページ。tora2 の複製は 2 ページ |

拾った項目は 9 章にその版の節を作って書く。テストの**前に**書く。

## 6. 繰り返すとき

不具合を直して配布物を作り直した場合、**同じ版数のままなので 2 回目は止まる**。

```
エラー: 対象はすでに NextForm 0.8.0 です (配布物は 0.8.0)。することがありません。
       やり直したい場合は --force を付けてください。
```

版数はリリースまで上げない (`project-overview.md` §7「リリースの単位」)。
テストのたびに `.1` `.2` と刻むと、誰も見たことのない版が CHANGELOG に並ぶ。

進め方は 2 つある。

**(a) 控えから戻してやり直す — こちらが本来の検査**

`--force` で上書きし続けると、2 回目以降は「0.8.0 → 0.8.0」を試すことになる。
確かめたいのは「**元の版 → 新しい版**」なので、毎回同じ出発点に戻す。
戻し方は 7 章。

**(b) `--force` で上書きする**

```bash
sudo php NextForm/app/tool/upgrade /var/www/html/mywiki/index.php --force
```

置き換えとテーマ再生成だけを見たいときはこれで足りる。
版ごとの案内 (索引の再構築、古いマニュアルの後片付け) は**状態**を見て出るので、
1 回目で片付いたものは 2 回目に出ない。そこも見たいなら (a) にする。

## 7. 戻し方

**実行後の案内にそのまま貼れるコマンドが出ている。** それを使う。

```
  問題があれば戻せます:
    rm -rf .../app .../resource .../theme
    cp -a <バックアップ>/app <バックアップ>/resource ... <サイト>/
```

`storage/` は戻らない。ツールが `storage/` に触れるのは
「焼き付けた古いマニュアルのページを消す」1 か所だけで、これは論理削除なので
`?option=deletedpage`「削除されたページ」から戻せる。
2 回目以降は何も消さない (冪等)。

ページの中身ごと何度も試すなら、`--full-backup` で `storage/` を含めて控えておく。

#### 確かめる項目

`CHANGELOG.md` の v0.8.0 の節から拾ったもの。

**見え方が変わるもの**

#### 結果

**1 回目 (2026-08-28) — 工程 0 で中断。項目は 1 つも消化していない。**

対象は 2018 年から動いている実運用サイト (約 1,100 ページ)。元の版は
NextForm 0.2.0。`sudo php NextForm/app/tool/upgrade <サイト>/index.php` は
最後まで通ったが、**その後サイトが全ページ 500 になった**。

```
PHP Parse error: syntax error, unexpected 'class' (T_CLASS)
  in <サイト>/app/handler/markdown.inc on line 77
```

対象サーバの PHP が **5.4.16** (CentOS 7 / Apache 2.4.6 / mod_php) だった。
`Foo::class` は PHP 5.5 以降の構文なので、読み込んだ時点で落ちる。
`php -l` を全ファイルに当てると、`app/handler/markdown.inc`、
`app/handler/markdown/wikilink.inc`、同梱の `app/vendor/` (commonmark 一式) が
5.4 では構文解析できない。**元の 0.2.0 は全ファイル通る**。たまたま古い PHP でも
読める書き方だっただけで、0.8.0 で Markdown 対応と同梱ライブラリが入った時点で
境界を越えていた。

`storage/` は無傷。ツールが作ったバックアップから 0.2.0 に戻して復旧した
(この文書の 7 章の手順どおり)。**再実施は、サーバを新しい OS で作り直してから。**

#### 見つけたこと

**① ツールが PHP の版数を検査していなかった (直した)**

「実行中の PHP」を**表示するだけ**で、下限との突き合わせが無かった。版数の
取り違えには `upgrade_fatal` があるのに、PHP には無いという非対称。しかも
ツール本体は 5.4 でも構文が通るので、素通りしてサイトを壊せてしまった。

`app/version.inc` に `NEXTFORM_PHP_MIN` を置き (composer.json の `require.php`
と同じ 8.3)、**バックアップより前**に検査するようにした。`--force` では
素通りさせない。版数の取り違えはやり直せるが、PHP 不足は復旧作業が要るため。

**② 工程 2 → 工程 3 の順序が問題を増幅していた**

新しいコードを置いてから、その新しいコードを同じプロセスで動かす作りなので、
「動かない PHP だった」と分かる頃にはサイトはもう書き換わっている。だから
PHP の検査は「何も書き換える前」にしか置き場所が無い。

**③ 工程 3 が失敗すると所有者が戻らなかった (直した)**

テーマ生成に失敗すると工程 4 (所有者の復元) を通らずに `exit(1)` していた。
`upgrade_copy_tree()` は配布物側の所有者をそのまま持ってくるので、
**配布物を展開した人の所有のまま残り、web サーバから読めなくなる**。
コードが新しくなったうえに所有者も違う、という二重の壊れ方をする。
`upgrade_restore_all()` にまとめ、工程 2 / 工程 3 の失敗経路からも呼ぶようにした。
戻し方の案内も出すようにした。`tests/upgrade.sh` [16] で実走している
(`theme/` を通常ファイルにして生成先の mkdir を確実に失敗させる)。

**④ ツールは CLI の PHP しか見られない (別に手当てした)**

web サーバ (PHP-FPM / mod_php) が別の版ということがある。`app/php_version.inc`
を足し、`app/boot.inc` が `main.inc` より先に読むようにした。真っ白な 500 では
なく、必要な版数と実際の版数を書いた本文を返す。**このファイルは古い PHP でも
構文解析が通る書き方に限る**こと (新しい書き方が 1 つ混じると検査そのものが
動かない)。ファイル先頭にその旨を書いてある。

**⑤ 手順書が逆の順番を勧めていた (直した)**

`docs/upgrade-guide.md` §2 に「アップグレードしてから PHP を 8 系に上げる、
という順番が安全です」と書いてあった。v0.2 までは正しかったが、v0.3 以降は
誤り。古い ToraToraWiki は PHP 8 で起動せず、新しい NextForm は PHP 8.3 未満で
起動しないので、**どちらを先にしてもサイトは一度止まる**。順番で避けられる
ものではないと書き直した。

#### 確かめる項目

`CHANGELOG.md` の v0.9.0 の節から拾ったもの。この版は**既存ページの
保存経路に触る**ので、重いのは POST の側にある。

**実データでしか踏めないもの**

- [ ] 既存の Markdown ページを 1 枚開き、段落を二重クリックして保存する。
      **本文の他の場所が 1 バイトも変わっていない** (`?option=history` の差分で見る)
- [ ] 長いページ (見出しが 10 個以上) で、見出しを二重クリックすると
      **その節ぜんぶ**がテキストエリアに入る。節の中身は隠れる
- [ ] 節を保存したあと、次の見出しとのあいだの空行が消えていない
- [ ] 表・コードブロック・引用・箇条書きの項目を、それぞれ 1 回ずつ編集して保存する
- [ ] 折りたたみ (`:::details`) の中の段落を編集して保存しても、
      **閉じの `:::` が消えない**
- [ ] 脚注のあるページで、脚注の一覧を二重クリックしても編集が始まらない
      (範囲を持たせていない)
- [ ] CRLF で保存されている古いページで、切り出しがずれない
- [ ] 1MB を超えるページがあれば、開いて 500 にならない
      (`?option=replace` は元から断る作りだが、表示の経路を通ることを見る)

**POST の経路**

- [ ] 種別 wiki のページの二重クリック編集が**今までどおり**動く
      (箇条書きの並べ替え画面、表の行の編集、Alt キー + クリック)
- [ ] 編集画面に「ダブルクリックでも編集できます」の案内が出る
      (種別 Markdown でも出るようになった)
- [ ] Esc で編集を取り消すと、隠れていた節の中身が戻る
- [ ] 二重クリックの編集画面に**「保存して編集続行」**が出る (種別 wiki / Markdown 両方)。
      押すとページが読み直され、**同じ箇所が開き直される**。続けて 2 回保存できる
- [ ] 表を含む Wiki 記法のページで「保存して編集続行」を押したとき、開き直す箇所が
      隣にずれても本文が壊れていない (桁揃えで後ろの位置が動くため、ずれ得る)
- [ ] 添付・ロック・改名・管理画面が今までどおり

**見え方**

- [ ] 4 つのテーマ (basic / plain / docs / card) で Markdown ページの
      見え方が変わっていない (属性が増えただけで構造は変えていないが、
      CSS の属性セレクタと当たっていないことを見る)
- [ ] 静的書き出し (`?option=export`) に `data-twp` が漏れていない
