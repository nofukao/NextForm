# 設計メモ: 検索の高度化 (v0.19)

> **このドキュメントの位置づけ**
> ロードマップの v0.19「検索機能の高度化 (正規表現、AND/OR/NOT、タイトル/本文限定、更新日範囲)」の設計。
> 2026-10-29 に調査と計測をし、承認の前に別の目で見直した (§7)。同日に利用者が承認した (§4)。決まったことは

## 1. 何を作るか

検索欄の書き方を増やす。今は「空白で区切る = すべてを含む」「`"..."` = 空白ごと 1 語」だけ。

| 書き方 | 意味 |
|---|---|
| `語1 語2` | 両方を含む (今と同じ) |
| `語1 OR 語2` | どちらかを含む |
| `-語` | 含まない (ほかに条件があるときだけ。§3.1) |
| `title:語` / `body:語` / `tag:語` | 題名 (ページ名を含む) / 本文 / タグ だけで探す |
| `re:正規表現` | 正規表現で探す (§4 の 1) |
| `after:2026-10-01` / `before:2026-10-31` | 更新日時で絞る |

組み合わせられる (`title:手順 -下書き after:2026-10-01`)。

あわせて:
- **マニュアルを探す範囲を 3 つから選ぶ** (含めない (既定) / 含める / マニュアルだけ)。今の
  「マニュアルは除く」(既定はオフ = 含める) を置き換える。結果の画面に、ほかの 2 つで探し直すリンクを出す。
- **組み込みマニュアルの題名 (`&title`) で検索に当たるようにする** (v0.15.0 で見つけて送った件)。
  当たるようにするのに要る、既にある問題 2 つも直す (§3.7)。

## 2. 調べてわかったこと

### 2.1 今の作り

- `search_parse_query()` (`app/search.inc`) が問い合わせを**平らな語の配列**にする。
  `LANGUAGE_SEARCH_QUERY_REGEX` (`/(".*?"|[^\s]+)/`) で切り出し、`"` を外すだけ。
- `search_builtin()`: 語ごとに 2-gram 索引から候補を集め (`search_word()`)、**全部の語の候補に入った
  ページだけ**を残す (AND = 交差)。残りを `search_page_match()` で照合し直し、スニペットとスコアを作る。
  読む権限は本文を読む前に確かめている (`search.inc:493`)。
- 照合の文字 (題名・説明・タグ・本文) は `search_page_texts()` が作り、ページごとに mtime で
  キャッシュする (`search_page_texts_cached()`、v0.4.0)。題名には meta の題名とページ名が入る。
  本文は句読点と改行で塊に分けて照合するので、語は「。、．，」と改行をまたげない (マニュアルに書いてある)。
- 同じ平らな配列が 3 か所に流れる: 検索結果のスニペットの印 (`dom_append_hightlighted_text()`)、
  結果を開いたページの印 (`handle.inc:93` → `$page['query']` → `sentence_search.inc`)、
  ページの上の「検索キーワード:」(`search_notice_query()`)。
- 印を付ける層 (`sentence.inc`) は正規表現の一覧 (`regexs`) も扱えるが、**そのままでは使えない**:
  検索の印の関数 (`sentence_search.inc:18`) は当たった文字で色の番号を引くので、正規表現の一致では
  警告になる。空の一致 (`x*`) も警告と空の印になる。正規表現用の印の関数を分け、空の一致は捨てる。
- `SEARCH_ENGINE` が `elasticsearch` のときは `app/search/elasticsearch.inc` に渡る。API は Elasticsearch
  1.x の頃のもの (`_all`、`fields`、`DELETE /_query`) で、今の Elasticsearch では動かない見込み。試せる環境も無い。

### 2.2 計測 (実データの複製、2026-10-29)

実データの写し (807 ページ + マニュアル 119 = 926 ページ、wiki 364・markdown 18・file 542) を
複製し、0.18.0 に上げて測った (`tmp/search-measure/measure.php`。開発機、PHP 8.3 の CLI)。
照合に使う文字はサイト全体で **0.8 MB** (添付は名前と説明とタグだけ)。索引は 7.2 MB。

| 何をしたか | 時間 |
|---|---|
| 全ページを読んで照合 (語を含むか)、テキストキャッシュ**無し** (最初の 1 回) | 923 ms |
| 同じ、キャッシュあり | 46〜50 ms |
| 全ページを正規表現で照合 (ふつうの式 2 つ) | 51 ms |
| 全ページで「含まない」 | 48 ms |
| 題名だけで照合 | 47 ms |
| 更新日時だけで絞る | 24 ms |
| 今の検索 (索引) 1 語、結果 46 件 | 10 ms |
| 今の検索 (索引) 2 語、結果 16 件 | 5 ms |
| 今の検索 (索引) よく出る 1 文字、結果 750 件 | 71 ms |

**索引が使えない書き方 (含まない・正規表現・日時だけ) でも、全ページを読んで 50 ms 前後。**
よく出る語の今の検索 (40〜70 ms) と同じくらいなので、索引の作りは変えない。キャッシュの無い最初の
1 回は 1 秒弱 (読んだページの分のキャッシュが作られ、次からは速い)。共用サーバーは数倍を見込む。

### 2.3 正規表現の危うさ (計測)

書き方によって照合に極端に時間がかかる (破滅的なバックトラック)。PHP の上限
(`pcre.backtrack_limit` = 100 万) で 1 回ごとには止まるが、全ページに掛けると積み上がる:

| 式 | 時間 (926 ページ) |
|---|---|
| `(.*)*x` | **4540 ms** |
| `(\w+\s?)+$` | **1858 ms** |
| `(a\|aa\|aaa)*b` | 52 ms |

ほかにも:
- **開いたページの印**: 結果を開く URL (`?ページ&query=…`) は誰でも作れる。印は本文の文字の塊ごとに
  正規表現を掛けるので、検索の画面と同じ守りが要る。`.` のような式では全部の文字に印が付き、
  HTML が何十倍にもなる。
- **一括の抜き出し**: `AKIA[0-9A-Z]{16}` やメールアドレスの形の式で、サイト中の該当箇所が 1 回で
  スニペット付きで並ぶ。読めるページの中身ではあるが、集めるのが格段に楽になる。
- 読めない式は PHP の警告になる (誰でもログを埋められる)。式は警告を出さずに 1 回だけ確かめる。

### 2.4 互換に効くところ

新しい書き方の記号は、今は**ふつうの文字として探されている**。変えると意味が変わる:
`OR` (大文字だけの語)、先頭の `-`、`title:` などで始まる語。

- `--force`・`-rf`・`-1` のような語だけで探すと、全部「含まない」になり、ほぼ全ページが出てしまう。
  → **ほかに条件 (含む語・日時) が無いときの `-語` は、今どおり文字として探す** (§3.1)。
- 正規表現を `/.../` で書く案は、`/api/`・`/etc/`・`/tmp/` のような道の一部が `rapid`・`fetch`・`attempt`
  に当たり、`/c++/` は意味が変わる。技術の wiki で道を探すのはよくあるので、`re:` を推す (§4 の 1)。
- 文字どおりに探したいときは `"..."` で囲めば今と同じ (`"OR"`、`"title:x"`)。知らない名前の `xxx:`
  (`https://…` など) は今までどおりふつうの語。
- 今の書き方 (空白区切り・`"..."`) の結果・順序・印は変えない。

### 2.5 組み込みマニュアルの題名

マニュアルのページは meta に題名を持たないので、題名 (「サイトの管理」など) で検索に当たらない
(v0.15.0 で見つけて送った件)。見直しで次が分かった:

- 題名に当たると +100 点 (`search.inc:594`)。「ページ」「設定」などよく出る語で、マニュアルが
  利用者のページより上に並ぶ。上の検索欄には「マニュアルは除く」の切り替えが無い。
- 未ログインでマニュアルを読めないサイトでは、マニュアルの索引の更新が飛ばされる (`manual.inc:188`)。
  アップグレードは CLI で未ログイン扱いなので、題名が索引に入らない (既にある問題。下の §6)。
- 題名をどこで作るかで、マニュアルを読むたびに本文を全部変換することになる。
- マニュアルの検索用キャッシュが古いまま残ることがある (§6)。題名を足しても、古いキャッシュには入らない。

はじめは別に設計する案にしたが、利用者が「マニュアルは既定で含めない」案を出し、並びの心配が
無くなったので、この版に入れる (§3.7)。ページの一覧・`&pages`・フィード・Markdown の `[PAGES]` は
もともとマニュアルを出さないのが既定で、検索だけが例外だった (`is_ignore_system_page`)。

## 3. 設計

### 3.1 書き方 (問い合わせの文法)

- 切り出しは今と同じく空白 (全角も) で区切る。1 つの語は `"..."` か、空白を含まない文字の並び。
- 語の頭に付けられるもの (この順): `-` (含まない) → `title:` / `body:` / `tag:` (探す場所) →
  `re:` (正規表現)。値は `"..."` でもよい (`-title:"下書き メモ"`、`body:re:"v[0-9]+ 版"`)。
- **`-語` は、ほかに条件 (含む語か日時) があるときだけ「含まない」**。無ければ今どおり文字として探す
  (`-rf` だけなら「-rf」を探す)。
- `OR` (半角の大文字、それだけの語) は前後の語を「どちらか」にまとめる。`a b OR c` は
  「a を含み、かつ b か c を含む」(Google と同じく OR が強く結び付く)。括弧は無い。端の `OR` はふつうの語。
- `after:YYYY-MM-DD` はその日の 0 時以降、`before:YYYY-MM-DD` はその日の終わりまでに更新されたもの
  (どちらも含む。サイトのタイムゾーン。画面の「最終更新」と同じ値)。**読めない日付 (`2026/10/01`、
  `2026-02-30`) は、黙って語にせず「日付は YYYY-MM-DD で書いてください」と出す**。
- `tag:` は**タグの完全一致**。部分一致ではない。大文字小文字は区別しない (検索のほかの語と同じ)。
  `&pages(tag=…)` と違い、ワイルドカードは無い。
- 正規表現は大文字と小文字を区別しない (`iu`。全角の英字も同じとみなす点は今の検索と違う)。
  本文には**塊ごと**に掛ける (今の語と同じく、句読点と改行をまたがない。開いたページの印とも揃う)。
  空の一致は一致としない。読めない式なら結果の代わりに「正規表現が読めません」と出す。
- 演算子の記号は半角だけ (`ＯＲ`・`－`・`：` は文字として探す)。§4 の 7。
- `search_parse_query()` を置き換え、構造を返す `search_query_parse()` を作る: 節 (AND) の並び、
  節は語 (OR) の並び、語は {種類 (文字/正規表現)、値、場所、含まないか}、それと日時の範囲。

### 3.2 実行の流れ (builtin)

1. **候補を索引で絞る**: 「含む」語だけで正規表現を含まない節は、語ごとの候補の**和** (OR) を取り、
   そういう節どうしは**交差** (AND)。場所が付いていても索引は使える (全部の場所の文字から作っている)。
   今の書き方は必ずこの道を通る (今と同じ)。
2. 絞れる節が 1 つも無いとき (含まない・正規表現・日時だけ) は、**全ページが候補**
   (`search_index_target_pages()`。「マニュアルは除く」はここでも効く)。
3. 順に、**読む権限 → 日時 → 文字** で確かめる (権限の無いページは中身を読まない)。日時だけの
   問い合わせは本文を読まない。
4. スニペットとスコアは今と同じ作り (「含む」語と正規表現の一致から作る。「含まない」語は数えない)。
5. 並べ替え・ページ分けは今と同じ。

### 3.3 正規表現と全部読む検索の守り

- `pcre.backtrack_limit` を下げるのは、**利用者の正規表現を呼ぶ 1 回ごとの前後だけ**。検索全体で
  下げると、キャッシュの無いページの本文の変換 (wiki・Markdown の部品も正規表現を使う) まで途中で
  失敗し、誤った中身がキャッシュに残る。上限に当たった塊は「一致しない」とする。値は実装で測って決める。
- **時間の上限は全部読む検索 (§3.2 の 2) と、正規表現を含む検索**に掛ける。今の書き方には掛けない。
  正規表現は塊ごとに掛けるので、1 ページの中でも時間を確かめる (索引で絞れても、正規表現が候補の
  ほぼ全部に掛かることがあるため。§9)。
- 打ち切ったら: それまでに見つけたものを 1 ページ目にだけ並べ (ページ送りは出さない)、
  「時間がかかるので途中で打ち切りました。条件を足して絞ってください」と添える。件数は「n 件 (途中まで)」。
  **全体の件数は出さない** (読めないページの数が分かってしまう。project-overview.md §7 の未ログイン時の方針)。
  Shift+Enter (結果の一番上へ移る) は、打ち切ったときは移らずに結果を出す。
- 開いたページの印 (`handle.inc`): 正規表現は §4 の 2 で使える人のときだけ掛ける。同じ手数の上限と、
  印の数の上限 (例: 1 ページ 500) を掛ける。
- 正規表現を使える人は §4 の 2 で決める。

### 3.4 印 (ハイライト)

- 「含む」語 (場所の付いたものも) と、正規表現の一致に印を付ける。検索結果のスニペット・開いた
  ページ・「検索キーワード:」の 3 か所とも。「含まない」語には付けない。
- 正規表現の印は、別の印の関数で付ける (§2.1)。空の一致は捨てる。
- 結果を開くリンクの `query=` は今と同じく入力した文字列をそのまま渡し、開いた側で同じ関数で読む。

### 3.5 検索の画面

- 検索欄の書き方は §3.1 だけ。書き方のための欄は足さない (§4 の 4)。
- **マニュアルを探す範囲**: 今のチェックボックス「マニュアルは除く」を、並び順の隣の選択
  「マニュアル: 含めない (既定) / 含める / マニュアルだけ」に置き換える。チェックボックスでは
  「マニュアルだけ」を表せず、画面と結果がずれるため。引数は `manual=with` / `manual=only`
  (無ければ含めない)。前の `ignore_system_page=on` は読まない (既定と同じ結果になる)。
- 結果の画面に、選んでいないほうの 2 つで探し直すリンクを出す
  (含めない → 「マニュアルも含めて探す」「マニュアルだけを探す」、含める → 「マニュアルを除いて探す」
  「マニュアルだけを探す」、マニュアルだけ → 「マニュアルを除いて探す」「マニュアルも含めて探す」)。
- 上の検索欄と `&search` は選択を持たず、既定 (含めない) で探す。Shift+Enter は、そのときの選択に従う。
- 「マニュアルだけ」は、候補をマニュアルのページに限る (全部読むときは `manual_page_find()` だけを読む)。
  マニュアルを読めない人には何も出ず、今の「ログインすると…」の案内が出る。
- 検索の画面の欄の下に、書き方の例 (1 行) とマニュアルへのリンクを出す。
- マニュアル (サイトの機能の「検索」、日本語と英語) を書き直す。今の「OR や除外の書き方はありません」を消す。
  マニュアルのページの更新日時はリリースの時刻なので、`after:` でマニュアルが出ることも書く。

### 3.6 Elasticsearch

マニュアルの範囲は、今ある「含めない」(`is_system_page` が false) に、「マニュアルだけ」(true) の条件を
1 つ足す。試せる環境が無いので、動きは確かめられない。

新しい書き方は **builtin だけ**の機能にする。`SEARCH_ENGINE` が `elasticsearch` のとき、新しい書き方の語が
あれば検索せずに「この検索エンジンでは使えない書き方です」と出す (`-下書き` を渡すと記号が落ちて
「含む」になり、意味が逆になるため)。新しい書き方が無ければ今どおり。

### 3.7 組み込みマニュアルの題名

- 題名は、マニュアルのページの本文の `&title` の行から取り、meta の題名にする (マニュアルを作り直す
  ときに 1 度だけ。本文を変換しない)。マニュアルの `&title` は 46 個とも記法を含まない文字だった。
- 検索のほか、題名を出す所 (検索結果の「題名 (ページ名)」) で題名が出る。ページの一覧はもともと
  マニュアルを出さない。
- **既にある問題を 2 つ直す** (直さないと、アップグレードしたサイトで題名が当たらない):
  1. マニュアルを作り直したとき、マニュアルのページの検索用キャッシュを消す (§6 の 2)。
  2. ログインしないとマニュアルを読めないサイトでも、アップグレード (コマンドライン) でマニュアルの
     索引を更新する (§6 の 3)。Web の要求で読めない人が来たときに飛ばすのは今どおり。

### 3.8 テスト (テスト先行)

- **変える前の振る舞いを固定する**: 今の書き方 (空白区切り・`"..."`・全角の空白・1 文字・大文字小文字・
  `-rf` だけ・`OR` だけ・`title:x` だけ・`https://…`) の検索結果 (件数・順序・スコア・スニペット) と
  開いたページの印を、複製サイトのページで固定してから変える。§3.1 で意味が変わるもの
  (`a -b`、`a OR b` など) は、変わることを確かめる側に移す。
- 新しい `tests/search-query.sh` (複製サイト): 書き方の読み取り (構造)、OR・含まない・場所・正規表現・
  日時の結果、組み合わせ、印 (結果・開いたページ、正規表現、空の一致、印の数の上限)、読めない
  正規表現と日付の案内、PHP の警告が出ないこと、手数の上限 (§2.3 の式)、時間の上限と打ち切りの表示
  (ページ送り・Shift+Enter)、正規表現を使える人、権限の無いページが結果にも件数にも出ないこと、
  Elasticsearch のときの案内、マニュアルの範囲 (3 つ・リンク・既定・Shift+Enter)、マニュアルの題名
  (アップグレードのあとに当たる、読めないサイトでも索引に入る、古いキャッシュが消える)。
- 既存の `search-index.sh`・`search-cache.sh`・`golden.sh`・`smoke.sh` が変わらず通ること。
- 実データの複製で §2.2・§2.3 を新しい作りで測り直す (リリース前のアップグレード確認に入れる)。

| # | 項目 | 決定 | 選ばなかった案 |
|---|---|---|---|

## 5. やらないこと

- 括弧 (`(a OR b) c`)。OR は隣り合う語どうしだけ。
- 作成日時での絞り込み (更新日時だけ)。
- 添付ファイルの中身の検索 (今どおり、名前・説明・タグだけ)。
- 索引の作りの変更 (場所ごとの索引、3-gram など)。計測では今の索引 + 全部読むで足りる。
- Elasticsearch の作り直し。

## 6. 見直しで見つけた、既にある問題

1 はこの版では直さない (別に報告)。2 と 3 はマニュアルの題名のために、この版で直す (§3.7)。

1. **印の `source` が次の一致に残る** (`sentence.inc:107-108`)。正規表現の一致が付けた `source` が
  `$sentence_context` に残り、続く一致にも渡る。ページ名の自動リンクを有効にしたサイトで、
  リンクの行き先が変わりうる。
2. **マニュアルの検索用キャッシュが古いまま残ることがある**。アップグレードは配布物のファイルの時刻を
  そのまま写す (`tool/upgrade:249`) ので、マニュアルのページの更新日時はリリースの時刻になる。
  リリースからアップグレードまでのあいだに作られた検索のキャッシュが「新しい」と判定され、
  マニュアルの本文を直した版でも、検索には古い本文が使われる。
3. **未ログインでマニュアルを読めないサイトでは、マニュアルの索引が更新されない** (`manual.inc:188`)。
  アップグレード (CLI) でも更新されず、後から更新される機会も無い (管理画面の索引の再構築で直る)。

## 7. 承認の前の見直し (2026-10-29)
