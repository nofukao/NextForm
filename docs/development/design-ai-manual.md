# 設計メモ: AI 向けのマニュアルのページ (v0.20 の候補)

> **このドキュメントの位置づけ**
> 利用者の案 (2026-10-30)。AI (Claude Code など) にページを書かせるとき、渡すのを URL 1 つで
> 済ませる。2026-10-30 に調べ、承認の前に別の目で見直した (§7)。同日に利用者が承認した (§4)。
> 決まったことは [project-overview.md](project-overview.md) §7 に 1 行ずつ移す。このファイルは
> 「なぜその形にしたか」と、却下した案を残すための記録。

---

## 1. 何を作るか

組み込みマニュアルに、AI 向けのページ `NextFormManual/AI` を足す。中身は、いまの AI 向けの
スキル (`SKILL.md`) の手順そのもの。別のマシンの AI には、次のように頼めば済むようにする。

> https://〈サイト〉/?〈ページ名〉 に○○を書いてください。書き方は
> https://〈サイト〉/?NextFormManual/AI を読んでください。
> サーバーには SSH の別名 〈別名〉 でつながります。

- **手順はサイトの版と必ず合う。** 組み込みマニュアルは `app/` と一緒に配られ、アップグレードで
  一緒に新しくなる。プラグインはマシンに 1 つの版しか入らないので、版の違うサイトを相手にすると
  ずれるが、ページならサイトごとに合う。
- **Claude Code 以外の AI にも使える。** URL を読める AI なら、同じ手順に従える。
- プラグインの入れ方もページに書く。同じマシンで何度も使う人向けの付け足しにする。

**書く経路は変えない。** AI はこれまでどおり、サーバーの上の `app/tool/page` を SSH で動かして書く。
SSH で入れないサイトには書けない。HTTPS で書ける入口は作らない (利用者の判断 2026-10-30。
インターネットから書ける入口が増え、AI のマシンに資格情報を置くことになるため)。

## 2. 調べてわかったこと

- **いまのマニュアルは Wiki 記法だけ。** `manual_parse()` (`app/manual.inc`) が
  `manual/manual-*.txt` や `*.inc` の注釈 `/** @manual ... */` を集めて組み立てる。ページの種別は
  いつも `wiki` (`manual_page_create()`)。題名は `&title` の行から取る。
- **注釈の中のバッククォートは PHP の式として評価される** (`manual_replace()` が `eval`)。
  コマンドの多い Markdown の `SKILL.md` は、そのままでは入れられない。
- **本文はそのまま取れる。** `?〈ページ名〉&action=source` が `<pre>` に本文を出す。開発検証サイトで、
  ログインせずに組み込みマニュアルを取れた。ページの URL は `https://〈サイト〉/?〈ページ名〉`。
- **道具でも読める。** `app/tool/page ... read NextFormManual/ja/PageMenu --body` が本文を返した。
  ログインしないと読めないサイトでも、SSH 経由なら手順を読める。書き込みは `manual` で断る (いまの作り)。
- **マニュアルの名前空間を守るのは組み込みのページだけ。** `page_is_manual()` は「名前空間の下で、
  かつ組み込みにある名前」だけを守る。名前空間の下にある普通のページは、書く権限があれば作れる
  (`page.inc:56`)。0.19.0 以前のサイトでは、`NextFormManual/AI` は誰でも作れる普通のページ名になる (§8)。
- **版数は公開していない。** 画面に版が出るのは管理者向けの情報の画面 (`admin_info`) だけ。
- AI ツールの Web の読み込みは、要約されて細部が落ちることがある (Claude Code の WebFetch は
  小さいモデルを通す)。コマンドの引用符の規則のような細かいところは、本文をそのまま取って読ませたい。

## 3. 設計

### 3.1 正本 — Markdown の 1 ファイル

- 正本は **`NextForm/app/manual/AI.md`** (配布物に入る)。中身は変換せずにそのまま本文にする
  (`eval` も変数の置き換えもしない)。
- `manual.inc` に「`app/manual/*.md` の 1 ファイルを、`MANUAL_PAGENAME/〈ファイル名〉` という
  Markdown のページにする」経路を足す。種別は `markdown`。題名はふつうの Markdown のページと
  同じ取り方 (フロントマターの `title:`、無ければ先頭の `#` 見出し)。読み取り専用・検索・
  キャッシュの作り直しは、いまの組み込みマニュアルと同じ扱いにする (`manual_source_files()` に入れる)。
- **`SKILL.md` は、先頭の `name` / `description` のあとに、`AI.md` と同じ本文を置く。** プラグインは
  プラグインのフォルダーしか写さないので、`AI.md` を参照させられない。食い違わないことは
  テストで確かめる (§3.4)。写すのは `deploy/scripts/sync-skill.sh` (`SKILL.md` の先頭の 2 項目は
  残し、本文を `AI.md` で置き換える)。
- 本文の言葉は「このページ」でなく「この手順」にし、スキルとして読んでもおかしくないようにする。

### 3.2 ページの中身 (いまの `SKILL.md` に足すもの)

1. 冒頭に数行: この手順で何ができるか、**SSH で入れるサーバーだけ**であること、頼み方の例 (§1 の
   引用。利用者が確かめた 2026-10-30)。
2. **URL からページ名を取る**: ページの URL は `〈サイトの URL〉?〈ページ名〉` (`url_make()`)。ページ名は
   `?` のあとから最初の `&` (無ければ `#`) の手前まで。URL エンコードを戻す。短縮 URL
   (`?option=shorturl&key=...`) にはページ名が入っていないので、利用者に聞く。
   SSH の別名・サイトの場所・所有者・書き手の名前は URL からはわからないので、利用者に聞く (いまの §1)。
3. **この手順を正確に読む**: Web の読み込みが要約するときは、
   `curl -s 'https://〈サイト〉/?NextFormManual/AI&action=source'` の `<pre>` の中身を読む。
   ログインが要るサイトでは、SSH の先で `read NextFormManual/AI --user 〈書き手〉 --body` を使う
   (`--user` を省くとログインしていない人として読むので断られる)。
4. **繰り返し使うとき**: Claude Code のプラグイン (`/plugin marketplace add nofukao/NextForm` →
   `/plugin install nextform@nextform`)、ほかの AI ツールは `SKILL.md` を写す。版は固定しない (§4 の 2)。
5. ここから下は、いまの `SKILL.md` の本文 (接続先、守ること、読む、書く、Markdown の書き方、終了コード)。

### 3.3 入口

- マニュアルの入口 (`NextFormManual`) に、Japanese・English と並べて `For AI` を足す。
- 日本語のトップ (`NextFormManual/ja`) の本文の 1 行目に、右寄せで「英語マニュアル | AI向けマニュアル」を
  置く。英語のトップ (`NextFormManual/en`) にも同じ形で「Japanese manual | Manual for AI」を置く。
- 「やりたいこと別の案内」の表には載せない。表のほかのリンクはどれも各言語の子ページを指していて、
  言語の木の外にある AI のページだけが異質になる (利用者の指摘 2026-11-01。最初は表に 1 行足していた)。
- README に 3 つ目の入れ方として「URL を渡す」を書く。`docs/page-tool.md` からも案内する。

### 3.4 テスト (テスト先行)

`tests/manual.sh` に足す。

- **先に固定**: いまの組み込みマニュアルの全ページ (名前・種別・題名・本文) を書き出し、変更のあとも
  1 字も変わらないこと (新しいページが 1 つ増えるだけ) を確かめる。
- `?NextFormManual/AI` が Markdown として描かれる。`&action=source` の本文が `AI.md` と同じ。
- `app/tool/page read NextFormManual/AI --body` が `AI.md` と同じ。`write` は `manual` で断る。
  Web からの書き込みも断る。
- `SKILL.md` のフロントマターを除いた本文が `AI.md` と同じ。
- 入口からリンクがある。日本語・英語のトップでは本文の 1 行目 (最初の見出しより前) にあり、
  もう一方の言語のトップへのリンクも並ぶ。AI のページへのリンクはそれぞれ 1 つだけ (表に残っていない)。
  マニュアルだけを探す検索で題名に当たる。

## 4. 決まったこと (利用者の判断 2026-10-30)

1. 正本の持ち方は **A** (Markdown の 1 ファイルを正本にし、`SKILL.md` と同じ本文にする)
2. プラグインの版の固定は**ページに出さない**
3. 版数は **v0.20.0**

下は、決める前に並べた案と、選ぶと何が起きるか。

1. **正本の持ち方** (推した: A)
   - **A. Markdown の 1 ファイルを正本にし、`SKILL.md` と同じ本文にする** (§3.1)。
     手順を直すときは 1 か所で済み、テストが食い違いを止める。`manual.inc` に Markdown の
     ページを出す経路を足す (いまのマニュアルの出方は変えない)。
   - B. いまの仕組み (Wiki 記法の注釈) で書く。コードは変えずに済むが、`SKILL.md` と別の文章になり、
     直し漏れで食い違っていく。バッククォートが式として評価されるので、コマンドの多い文章は書きにくい。
   - C. `SKILL.md` を「サイトの `NextFormManual/AI` を読む」という案内だけにする。プラグインの更新が
     要らなくなり、いつもサイトの版に合う。代わりに毎回サイトを読みに行き、0.19.0 以前のサイトでは
     使えなくなる。
2. **プラグインの版の固定をページに出すか** (推した: 出さない)
   - 出さない: ページには `/plugin marketplace add nofukao/NextForm` (最新) を書く。最新のスキルは
     0.17.0 以降のサイトに使える (版で違うところは「0.18.0 以降」のように書いてある)。
   - 出す: `nofukao/NextForm#v0.20.0` のように、そのサイトの版を書く。プラグインもサイトと同じ版に
     そろう。代わりに、**いまは管理者にしか見えない版数が、サイトを見る誰にでも見える**ようになる。

- 添付ファイルの書き込み (道具が書かない。いまのまま)。
- いまの組み込みマニュアル (Wiki 記法) を Markdown に移すこと。

## 7. 承認の前の見直し (2026-10-30)

- **セキュリティ**: ページの中身は全サイト共通で、GitHub にあるものと同じ。サイトに固有の値
  (サーバーの中の場所、SSH の別名、利用者名) は書かない。版数も出さない (§4 の 2)。`app/manual/AI.md`
  は `.htaccess` の効かないサーバーで直に読めても、公開しているページと同じ中身なので困らない。
- **運用**: アップグレードで `app/` が入れ替われば、ページも新しくなる (いまのマニュアルと同じ)。
  プラグインのほうは自動では更新されない (いまと同じ。README に書いてある)。
- **互換**: いまのマニュアルの出方は変えない (§3.4 で固定して確かめる)。0.19.0 以前のサイトには
  このページが無い。その URL を渡された AI は「ページが無い」か、普通のページを読むことになる (§8 の 1)。

## 8. 想定リスク

1. **0.19.0 以前のサイトでは、`NextFormManual/AI` を普通のページとして誰でも作れる。** 書く権限の
   ある人が、AI への偽の手順を置ける。README と手順の冒頭に「0.20.0 以降のサイトの URL を渡す」と
   書く。手順を読んだ AI は、書く前に必ず利用者に確かめる (いまのスキルの決まり)。
2. **ログインしないと読めないサイトでは、Web から手順を読めない。** プラグインを使うか、SSH の先で
   `read NextFormManual/AI --body` を使う (道具で読めることは確かめた)。
3. **AI ツールが要約して読み、細部を落とす。** `&action=source` で本文をそのまま取る道を書いておく。
4. **`MANUAL_PAGENAME` を変えたサイトでは、URL が変わる。** 手順にはその旨を書くだけにする。

## 9. 実装して分かったこと (2026-10-31)

- **変更の前後で、いまのマニュアルは変わっていない。** 変更前のコード (main) と変更後のコードで、
  組み込みマニュアルの全ページ (名前・種別・題名・本文) を書き出して比べた。119 ページのうち、
  変わったのは入口を足した `ja` と `en` のトップの 2 ページだけで、`AI` (markdown) が 1 ページ増えた。
- **題名は保存のときと同じ `markdown_normalize()` で取れる。** 本文を変換するので、メモ
  (`$MANUAL_PAGES_CACHE`) に入れたあとに取る (変換の途中で `page_is_exists()` が戻ってくる)。
- **キャッシュは .md の名前の一覧でも作り直す。** 作り直すかどうかは元のファイルの更新時刻の
  最大で決めていて、時刻を保ったまま (`rsync -a` など) 古い時刻の .md を足すと気づかない。
  テストでも、同じ 1 秒のうちに 2 つのファイルを `touch` すると作り直されなかった
  (テストは時刻を少し先にして `touch` する)。
- **ログインが要るサイトで道具から手順を読むには `--user` が要る。** 道具の `read` は `--user` が
  無ければログインしていない人として読む権限を確かめ、`no_permission` で断る (`app/tool/page` の
  `page_tool_read()`)。手順と設計メモの読み方を `read NextFormManual/AI --user 〈書き手〉 --body` に直した。
- 描かれ方: 開発検証サイトで、節 7 つ・表 4 つ・コードブロック 5 つ・頼み方の例の引用が出る。
  例の URL (`https://〈サイト〉/...`) は自動でリンクにならない。

### 見つけた、既にある問題 (直していない)

- 利用者が `app/plugin/` に足したプラグインの注釈も、マニュアルの元になる (`manual_source_files()`)。
  足したファイルの時刻がほかの元のファイルより古いと、上と同じ理由でマニュアルが作り直されず、
  次に版が変わるか、ほかの元のファイルが更新されるまで、そのプラグインの説明が出ない。
  .md と同じく名前の一覧を見れば直るが、今回の範囲の外なので触っていない。

## 10. レビューで直したこと (2026-11-01)

開発検証サイトで見た利用者の指摘で、入口を §3.3 のとおりに改めた。

- マニュアルの入口 (`NextFormManual`) に Japanese・English しかなく、AI のページへ行けなかった。
- AI のページへのリンクが「やりたいこと別の案内」の表にあった。表のほかのリンクは各言語の子ページを
  指していて、AI だけが異質だった。日本語・英語のトップの 1 行目に、もう一方の言語へのリンクと並べて
  置いた。並びは右寄せ (`&align(right);`) にして、本文の始まりと分けた。文字の大きさは変えていない
  (`&size` はマニュアル自身が非推奨としている)。
- 変わったページは入口・`ja`・`en` の 3 つ。`tests/manual.sh` の「入口」の検査を、入口の 3 項目、
  1 行目のリンク、AI へのリンクが 1 つだけであることに改めた。
