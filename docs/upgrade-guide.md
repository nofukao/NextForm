# 既存の ToraToraWiki を NextForm にアップグレードする

> **このドキュメントの読者**
> すでに ToraToraWiki 1.3.10 を運用していて、PHP 8 で動くようにしたい方。
> 開発者向けの資料 (`development/` 配下)
> とは別に、**利用者向け**として書いています。
>
> このファイルが正本です。配布物 (`NextForm.tar.gz`) の中には
> `UPGRADE.md` という名前で同じ内容が入っています。

NextForm は ToraToraWiki 1.3.10 (rev.1285) の fork です。v0.1 の目的は
**PHP 8.3 で警告ゼロで完全に動くこと**であり、機能は上流と同じです。

---

## 1. 変わるもの・変わらないもの

| | 内容 |
|---|---|
| **置き換わる** | `app/` (wiki のロジック全部)、`resource/`、`license.txt` |
| **再生成される** | `theme/` (配信される静的な CSS / JavaScript / 画像) |
| **触らない** | `index.php`、`install-info.dat`、`storage/`、`.htaccess` |

- **ページも添付ファイルも設定もそのまま**です。保存形式は上流から変えていません。
- `index.php` には認証設定 (`$AUTH_DIGESTS` など) が入っているので触りません。
- `app/` の中に置いたご自分のもの — `app/plugin/` のプラグイン、
  `app/theme/<独自テーマ>/` — は**そのまま残します**。
  NextForm が配っていないファイルを消すことはありません。

> ⚠️ `app/theme/basic/` を直接書き換えてカスタマイズしている場合、
> その変更は上書きされます。バックアップと見比べて当て直してください。

### バックアップの範囲

置き換わるのは `app/` `resource/` `theme/` `license.txt` で、
**合わせて数 MB** にしかなりません。一方 `storage/` は、ページと添付ファイルが
入るので数 GB になることがあります (実測で 7.4 GB の例があります)。

そこで既定では、**このツールが書き換える範囲と、サイトの設定ファイルだけ**を
控えます。`storage/` はコピーしません。触らないもののためにディスクを倍使い、
何分も待たされるのは割に合わないからです。

| | 既定 | `--full-backup` |
|---|---|---|
| `app/` `resource/` `theme/` `license.txt` | ✅ | ✅ |
| `index.php` `install-info.dat` `.htaccess` | ✅ | ✅ |
| `storage/` (ページ・添付ファイル) | — | ✅ |
| wiki と無関係なファイル | — | ✅ |

**`storage/` のバックアップが別に無い場合は `--full-backup` を付けてください。**
容量に余裕がなければ、スナップショットや `rsync` など、サイズに見合った手段で
別途控えてから、既定のまま進めるほうが現実的です。

## 2. 始める前に

**1. 現在の版を確認する**

サイトに管理者でログインし、`?option=admin_info` を開いて「バージョン」を見ます。
`1.3.10 (Revision: 1285)` であればそのまま進めてください。
それ以外の版からのアップグレードは検証していません。

**2. PHP の版を確認する**

NextForm v0.1 は **PHP 8.3** で動作確認しています。
アップグレードしてから PHP を 8 系に上げる、という順番が安全です
(古い ToraToraWiki は PHP 8 では起動すらしません)。

**3. 配布物を展開する**

[Releases](https://github.com/nofukao/NextForm/releases/latest) から
`NextForm.tar.gz` をダウンロードします。GitHub が自動で付ける
「Source code」ではなく、**添付されている `NextForm.tar.gz`** のほうです。

```bash
tar xzf NextForm.tar.gz
```

`NextForm/` というディレクトリができます。**これを web サーバに置くのではありません。**
既存サイトを更新するための材料です。

**4. サイトの場所と所有者を確認する**

```bash
ls -l /var/www/html/mywiki/index.php
```

以下の例では、サイトが `/var/www/html/mywiki`、所有者が `apache` だとします。
ご自分の環境に読み替えてください。

---

## 3. 方法 A — スクリプトで行う

配布物に入っている `app/tool/upgrade` が、次章の手順をそのまま自動で行います。

**まず `--dry-run` で、何が起きるかだけ見ます。** 何も書き換えません。

```bash
php NextForm/app/tool/upgrade /var/www/html/mywiki/index.php --dry-run
```

表示される「配布物に無いファイル」が、ご自分で置いたものと一致しているか
確認してください。身に覚えのないものが出たら、先に中身を見てください。

問題なければ実行します。サイトを書き換えるので `sudo` が必要です。

```bash
sudo php NextForm/app/tool/upgrade /var/www/html/mywiki/index.php
```

`続行しますか? [y/N]` に `y` と答えると始まります。

```
  1. バックアップ .. done  (/var/www/html/mywiki.backup-20260803-212243)
  2. コード更新 .. done
  3. テーマ再生成 .. done  (basic)
  4. 所有者の復元 .. done

完了しました。NextForm 0.3.1 になりました。
```

### オプション

| オプション | 意味 |
|---|---|
| `--dry-run` | 何も書き換えず、やることだけ表示する |
| `-y` `--yes` | 確認を求めない (スクリプトから呼ぶとき) |
| `--backup-dir <dir>` | バックアップ先を指定する (既定はサイトの隣) |
| `--full-backup` | `storage/` も含めてサイト全体を控える |
| `--no-backup` | バックアップを取らない。**別途バックアップがある場合だけ** |
| `--force` | 版数の判定を無視して強行する |

**5 章の確認**に進んでください。

## 4. 方法 B — 手作業で行う

方法 A のスクリプトが行うことと同じです。

> 手順 4 と 5 だけ、スクリプトとは順番が逆です。
> スクリプトは全部 `root` で実行してから最後にまとめて所有者を直しますが、
> 手作業では先に所有者を戻し、サイトの所有者になってテーマを再生成するほうが
> 簡単だからです。結果は同じになります。

### 手順 1 — バックアップ

**これを飛ばさないでください。**

書き換える範囲と設定ファイルだけを控えます (数 MB)。

```bash
cd /var/www/html/mywiki
B=/var/www/html/mywiki.backup-$(date +%Y%m%d-%H%M%S)
sudo mkdir "$B"
sudo cp -a app resource theme license.txt index.php install-info.dat .htaccess "$B"/
```

`storage/` (ページと添付ファイル) はこのあと一切触らないので含めていません。
**`storage/` のバックアップが別に無い場合は、代わりにサイト全体を控えてください。**

```bash
sudo cp -a /var/www/html/mywiki /var/www/html/mywiki.backup-$(date +%Y%m%d-%H%M%S)
```

> `cp -a` を使うのは、パーミッション・更新時刻・所有者を引き継ぎ、
> シンボリックリンクをリンクのまま複製するためです。`cp -r` では戻せません。

### 手順 2 — 見覚えのないファイルを確認する

配布物に無いファイルが `app/` にあれば、それはご自分で置いたものです。
手順 3 の `cp` は消さないので、**確認するだけ**です。

```bash
cd /var/www/html/mywiki
sudo LC_ALL=C diff -rq app ~/NextForm/app | grep '^Only in app'
```

`app/plugin/` のプラグインや独自テーマが挙がるはずです。
心当たりのないものがあれば、先に中身を確認してください。

> `LC_ALL=C` を付けているのは、`diff` の見出しがロケールによって
> 日本語になり `grep` に引っかからなくなるためです。

### 手順 3 — コードを置き換える

`src/.` と末尾のドットを付けると、中身だけを重ねて上書きします
(余分なファイルは消えません)。

```bash
cd /var/www/html/mywiki
sudo cp -a ~/NextForm/app/.      app/
sudo cp -a ~/NextForm/resource/. resource/
sudo cp -a ~/NextForm/license.txt .
```

`index.php` と `install-info.dat` と `storage/` と `.htaccess` はコピーしません。

### 手順 4 — 所有者を戻す

`sudo` でコピーしたので、新しいファイルが `root` 所有になっています。
web サーバのユーザーに戻します。**手順 5 より先に行ってください。**

```bash
cd /var/www/html/mywiki
sudo chown -R apache:apache app resource license.txt
```

`storage/` は触っていないので、そのままで構いません。

### 手順 5 — 静的なテーマを再生成する ★飛ばさないこと★

**ここが一番忘れられる工程です。**

`app/theme/basic/style/*.css` は PHP のテンプレートで、実際にブラウザへ
配信される `theme/basic/style/main.css` はそこから**生成**されます。
再生成しないと、コードだけ新しくなって**見た目の修正が一切反映されません**。
サイドバーが本文の下に回り込む、といった形で現れます。

次のどちらかを行います。

**(a) コマンドで行う**

```bash
sudo -u apache php app/tool/update_wiki /var/www/html/mywiki/index.php
```

> `update_wiki` は `index.php` と自分自身の所有者が一致することを要求します。
> 手順 4 を先に済ませておく必要があるのはこのためです。
> また、生成された `theme/` が正しい所有者になるよう、
> `sudo -u apache` のようにサイトの所有者になって実行してください。

**(b) 管理画面で行う**

管理者でログインし、「設定」→「テーマ設定」を開いて、そのまま**適用**します。
値を変えなくても、適用すれば再生成されます。
web サーバ自身が生成するので、所有者は自動的に正しくなります。

## 5. 確認

1. ブラウザでサイトを開く。トップページが表示されること。
2. `?option=admin_info` の「バージョン」に
   **`NextForm 0.6.0`** と `ToraToraWiki 1.3.10 (Revision: 1285)` の
   2 行が出ていること。
3. 見た目が崩れていないこと。
   **崩れて見えるときは、まずブラウザのキャッシュを消して再読み込みしてください。**
   古い CSS が残っていることがあります (Ctrl+F5 / Cmd+Shift+R)。
4. ページの編集と保存ができること。
5. サーバのエラーログに PHP の警告が出ていないこと。

```bash
# PHP-FPM の場合
sudo tail -50 /var/log/php-fpm/www-error.log
```

### 検索インデックスを再構築する ★0.3.0 以降では必須★

v0.3.0 で、本文から検索用の語を切り出すやり方を変えました
(全角スペースを半角と同じに扱うようにしています)。**アップグレードしただけでは
既存のインデックスが古い形式のままなので、一部の語が検索に出てきません。**

`?option=search_index` を開き、**「検索インデックスを再構築」を 1 回実行**してください。
1000 ページ程度で 30 秒ほどです。途中でブラウザを閉じても、それまでの
インデックスがそのまま使われ続けるので、やり直せば済みます。

同じ画面で、再構築が必要かどうかを確かめられます。「詳しく検査する」を押すと
ページごとに突き合わせ、ずれていれば件数を報告します。
コマンドラインからも確認できます。

```bash
php app/tool/search_index_check /path/to/wiki/index.php --deep --user 管理者名
```

### 古いマニュアルのページを片付ける ★0.7.0★

**アップグレード後の操作は要りません。** ここは、以前のマニュアルが
残っているサイトの片付けの話です。

v0.7.0 で、マニュアルが**組み込み**になりました。以前は
`?option=admin_manual` で一般ページとして生成する仕組みで、生成しないと
存在せず、生成先が `storage/` なのでアップグレードでも古いままでした。
いまはページを作らず、`app/` の中のマニュアルをそのまま表示します。
**アップグレードするたびに中身も新しくなります。**

生成の画面 (`?option=admin_manual`) は無くなりました。

以前に生成したページは `storage/` に残ります。放っておいても害はありません。
消したい場合の手順を下に書きます。

対象になるページ名は 2 つあります。v0.5.0 でマニュアルのページ名を
変えているので、古いサイトでは両方残っていることがあります。
**残り方が違います** (消し方は同じです)。

| ページ名 | いま何が起きているか |
|---|---|
| `NextFormManual` 以下 | **中身は表示されません。**組み込みのマニュアルが優先されます。全ページ一覧に名前だけ出ます |
| `ToraToraWikiManual` 以下 (v0.5.0 より前) | **普通のページとして残っています。**表示も検索もされます |

**消し方** — **管理者でログインして** `?option=delete` を開きます。

```
?NextFormManual&option=delete
?ToraToraWikiManual&option=delete
```

生成されたページはロックされていますが、**ロックを外す必要はありません**。
管理者はロックされたページをそのまま削除できます。
削除の画面で「子ページも一緒に」を選ぶと、下の階層までまとめて消えます。

`NextFormManual` 以下を削除しても、**組み込みのマニュアルはそのまま読めます**。
消えるのは storage に残っていた古い写しだけです。

削除したページは「削除されたページ」の一覧に残ります (元に戻せる状態です)。
完全に消すには、同じ `?option=delete` の画面から完全削除を行います。

> アップグレードツールは、残っているページがある場合だけこの案内を出します。

### ディレクトリ一覧を止める ★0.3.1★

`.htaccess` には利用者が独自に手を入れていることがあるため、**アップグレードでは
書き換えません**。0.3.1 で配布物に 1 行足したので、**既存サイトでは手で足してください。**

`.htaccess` の先頭に次の 1 行を加えます。

```apache
Options -Indexes
```

無いと `storage/` や `storage/page/` のディレクトリ一覧が外から見えます。
個別のファイルは拒否されるので中身は読めませんが、**どんなページが存在するかは
分かってしまいます**。追加後に確認してください。

```bash
curl -o /dev/null -w '%{http_code}\n' https://example.com/wiki/storage/
# 403 になれば止まっています (以前は 200 で一覧が出ていました)
```

> **追加したら 500 になる場合**、サーバの `AllowOverride` が `Options` を
> 許していません。その行を消して、`httpd.conf` 側の該当 `<Directory>` に
> `Options -Indexes` を設定してください。

### 外から操作しているスクリプトを直す ★0.4.0★

0.4.0 から、**状態を変える操作は POST でしか受け付けません。**さらにその POST が
同じサイトから来たことを `Origin` (無ければ `Referer`) で確かめます。

**ブラウザからの操作は今までどおりです。**画面のフォームは元から POST なので、
編集・削除・添付・管理画面のどれも操作は変わりません。手を入れる必要があるのは、
**wiki を外部のスクリプトから叩いている場合だけ**です。

0.3 まではこう書けました。

```bash
# 0.4.0 からは 403 になります
curl 'https://example.com/wiki/?ページ名&action=write&contents=本文'
```

0.4.0 では POST にして `Origin` を付けます。

```bash
curl -X POST -H 'Origin: https://example.com' \
     -d 'action=write' --data-urlencode 'contents=本文' \
     'https://example.com/wiki/?ページ名'
```

思い当たるものが無ければ、何もしなくて構いません。確かめるなら、
アップグレード後に一度サイトを使ってみて、403 の画面
(「このサイトから送られた要求ではありません．」) が出ないことを見てください。

> **どうしても直せないスクリプトがある場合**、`index.php` に
> `define('CSRF_PROTECTION', 'false');` を書けば元の動作に戻せます。
> ただし**罠サイトからページを消せる状態に戻ります。**
> 先に、呼び出し側に `Origin` ヘッダを足せないかを検討してください。

## 6. 元に戻す

**既定のバックアップ (`storage/` を含まない) から戻す場合**は、
書き換えた場所を消してから戻します。消してから戻すのは、新しい版で増えた
ファイルが残らないようにするためです。

```bash
B=/var/www/html/mywiki.backup-20260803-212243
sudo rm -rf /var/www/html/mywiki/app /var/www/html/mywiki/resource /var/www/html/mywiki/theme
sudo cp -a "$B"/app "$B"/resource "$B"/theme "$B"/license.txt /var/www/html/mywiki/
```

`storage/` は触っていないので、そのままです。
実行後の画面に、この 2 行がそのまま貼れる形で表示されます。

**`--full-backup` で控えた場合**は、入れ替えるだけです。

```bash
sudo rm -rf /var/www/html/mywiki
sudo mv /var/www/html/mywiki.backup-20260803-212243 /var/www/html/mywiki
```

問題がなければ、バックアップは消して構いません。

```bash
sudo rm -rf /var/www/html/mywiki.backup-20260803-212243
```

## 7. うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| `まだインストールが済んでいません` | 対象の `index.php` が `app/install.inc` を読み込んでいます。まだ一度もインストールされていないサイトです。先にブラウザで開いてインストールを済ませてください |
| `ToraToraWiki 1.3.10 の fork ですが、対象は … です` | 上流 1.3.10 以外からのアップグレードです。検証していません。承知のうえなら `--force` |
| `書き込めません` | `sudo` を付けて実行してください |
| `バックアップ先の空き容量が足りません` | `--backup-dir` で別の場所を指定するか、別に控えたうえで `--no-backup`。`--full-backup` を付けている場合は外すと数 MB で済みます |
| `コピーできません: …` / `リンクが読めません: …` | 表示されたパスを確認してください。壊れたシンボリックリンクや、通常ファイルでないものが混ざっていることがあります |
| `bad user. file owner id:…` | 手順 5(a) の `update_wiki` です。先に手順 4 (所有者) を済ませてください |
| サイドバーが本文の下に回り込む | 手順 5 (テーマ再生成) が済んでいないか、ブラウザのキャッシュです |
| 500 エラーになる | 手順 4 (所有者) を確認してください。web サーバが `app/` を読めていない可能性があります |
| 画面が真っ白 | `display_errors` が `Off` だと画面に何も出ません。サーバのエラーログを見てください |

## 8. 上流 (ToraToraWiki) との関係

NextForm のコードの変更は **`app/` の中だけ**に閉じています。
`index.php`、`.htaccess`、`resource/` は上流と同一で、
ページの保存形式も変えていません。だからこのアップグレードは
「コードを差し替えてテーマを作り直す」だけで済みます。

`license.txt` は、fork したことと NextForm の著作権表示を書き加えてあります
(GPLv3 が改変版に求めているものです)。ライセンス条文そのものは上流と同一の
**GPLv3** で、上流 ToraToraWiki の著作権表示もそのまま残しています。
